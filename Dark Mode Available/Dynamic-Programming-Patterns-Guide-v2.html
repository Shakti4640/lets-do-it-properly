Universal 5-Step Framework

Read Me First Mental Model

Five questions you ask of every DP problem. Once you can answer all five, the recurrence is already half-written.

Every DP recurrence in this guide was discovered by walking the same five steps. Internalize them and the equations stop feeling magical.

THINK — pose the right question AHA — the insight that unlocks the recurrence RECURRENCE — the equation PITFALL — common mistake
  1. Define the state. Ask: "What are the smallest pieces of information I need to remember to make a decision right now?" The answer is your state — the arguments to dp(...).
  2. Identify the choice. At the current state, what are the discrete options? Each option becomes a branch in the recurrence (a $\min$, $\max$, sum, or boolean OR over branches).
  3. Express the transition. For each choice, what state am I left with after taking it? Express $dp(\text{state})$ in terms of $dp(\text{smaller state})$.
  4. Pin down base cases. What is the simplest state where the answer is obvious? (Empty array, length 0, no items, sum 0, single character, etc.)
  5. Decide direction & storage. Top-down memo (recursion + cache) or bottom-up table. Reduce dimensions if only the last 1–2 layers are needed.
Universal opener: "Suppose I'm at position $i$ with state $X$. What can I do, and what does the problem look like after I do it?" Almost every recurrence in this document is an answer to that one sentence.
Solution.java
// Pseudocode skeleton — every DP in this guide instantiates this template
Type solve(State s) {
    if (isBase(s)) return baseValue;
    if (memo.containsKey(s)) return memo.get(s);
    Type best = identity;            // 0, ∞, -∞, false …
    for (Choice c : choicesAt(s)) {
        State next = apply(c, s);
        best = combine(best, valueOf(c) + solve(next));
    }
    memo.put(s, best);
    return best;
}
Time: O(states · choices) · Space: O(states)

Foundation · 03

DP Vocabulary & Tricks

Toolkit

Eight reusable tricks. Each one shows up in dozens of problems below — internalize them and recurrences write themselves.

  • Take vs. Skip. Two-branch idea behind almost every subset DP: $dp[i] = \max\bigl(\text{skip} = dp[i-1],\; \text{take} = v_i + dp[i-\text{prev}]\bigr)$.
  • Last decision principle. Don't think "what's the first thing I'll do" — think "what's the last thing I did to land here?". Transitions then write themselves.
  • Subset reuse. If items can repeat, the take branch points to the same $i$ (e.g. unbounded knapsack: $dp[i][W-w_i]$). If not, it points to $i-1$.
  • Interval expansion. For range problems: either split at some $k \in [i,j)$, or shrink the ends $(i+1,j-1)$.
  • Suffix vs. prefix. When the choice depends on what comes after, compute right-to-left.
  • Two pointers as state. For two sequences, default to $(i,j)$; only add dimensions if a constraint demands it.
  • Boolean → count. Replace $\lor$ with $+$ to convert "is it possible" into "how many ways".
  • Min ↔ Max ↔ Count. Same recurrence shape, different aggregator.
  • Rolling array. If $dp[i]$ only uses $dp[i-1]$ (and maybe $dp[i-2]$), drop the array to two variables for $O(1)$ space.
Solution.java
// Take vs. Skip — the universal subset frame
dp[i] = Math.max(dp[i-1],                       // skip
                 value[i] + dp[i - prevIndex]); // take

// Min ↔ Max ↔ Count — same shape, different aggregator
// dp[i] = Math.min(...);   ← optimization
// dp[i] = dp[a] + dp[b];   ← counting
// dp[i] = dp[a] || dp[b];  ← feasibility

// Rolling array — drop dimensions when only the last layer is needed
long prev2 = 0, prev1 = 1;
for (int i = 2; i <= n; i++) {
    long cur = prev1 + prev2;
    prev2 = prev1;
    prev1 = cur;
}
Foundation · 04

Generic Code Template

Skeleton

The same nine-line skeleton applies to every recurrence in this guide. Memoize, branch, combine, return.

function solve(state):
    if state is base case:        return base value
    if memo[state] is computed:   return memo[state]

    best = identity for the aggregator (0, ∞, -∞, false …)
    for each choice c available at state:
        sub = state after applying c
        best = combine(best, value(c) + solve(sub))

    memo[state] = best
    return best

Substitute combine with $\max$, $\min$, $+$, or $\lor$ depending on whether the problem asks for the optimum, the count, or feasibility. That's the entire skeleton — every problem below is a fill-in-the-blanks of this template.

Solution.java
<T> T solve(State s, Map<State, T> memo) {
    if (isBase(s))                    return baseValue();
    if (memo.containsKey(s))          return memo.get(s);

    T best = identityForAggregator();
    for (Choice c : choicesAt(s))
        best = combine(best, valueOf(c) + solve(applyChoice(c, s), memo));

    memo.put(s, best);
    return best;
}
Time: O(states · choices)

Fibonacci Numbers

Linear Counting O(n)

Compute the nth Fibonacci number, where F(0)=0, F(1)=1 and every later term equals the sum of the two before it. The poster-child for 1D DP — easiest place to see the recurrence-to-code translation.

THINK: What is $F(n)$? "The previous value plus the one before that." That phrase is already a recurrence.
AHA: The state is just $n$. Both predecessors are required by definition, so there is no real branching.
RECURRENCE:
$$F(n)=\begin{cases}0 & n=0\\1 & n=1\\F(n-1)+F(n-2) & n\gt 1\end{cases}$$
JAVA: 
dp[i] = dp[i-1] + dp[i-2];
PITFALL: Don't recurse without memoization — exponential blowup. Either cache or roll two variables.
Solution.java
int fib(int n) {
    if (n < 2) return n;
    int prev2 = 0, prev1 = 1;
    for (int i = 2; i <= n; i++) {
        int cur = prev1 + prev2;
        prev2 = prev1;
        prev1 = cur;
    }
    return prev1;
}
Time: O(n) · Space: O(1)

Climbing Stairs (1 or 2 steps)

LeetCode 70 Counting O(n)

A staircase has n stairs. From any stair you can jump 1 or 2 steps. Count the distinct ways to reach the top. The answer is Fibonacci shifted by one.

THINK: To reach stair $n$, where could my last step have come from? Either stair $n-1$ (1 step) or $n-2$ (2 steps).
AHA: Total ways = ways to reach $n-1$ + ways to reach $n-2$. That is Fibonacci shifted.
RECURRENCE:
$$S(n)=\begin{cases}1 & n=0\\1 & n=1\\S(n-1)+S(n-2) & n\gt 1\end{cases}$$
JAVA: 
dp[i] = dp[i-1] + dp[i-2];   // ways to reach stair i
Solution.java
int climbStairs(int n) {
    if (n <= 2) return n;
    int prev2 = 1, prev1 = 2;
    for (int i = 3; i <= n; i++) {
        int cur = prev1 + prev2;
        prev2 = prev1;
        prev1 = cur;
    }
    return prev1;
}
Time: O(n) · Space: O(1)

Tribonacci

LeetCode 1137 Linear

Tribonacci sums the previous three terms instead of two: T(0)=0, T(1)=T(2)=1, T(n) = T(n-1)+T(n-2)+T(n-3). Same DP shape as Fibonacci with a deeper window.

THINK: Same idea as Fibonacci but the definition stretches to three previous terms.
RECURRENCE:
$$T(n)=\begin{cases}0 & n=0\\1 & n=1\text{ or }n=2\\T(n-1)+T(n-2)+T(n-3) & n\gt 2\end{cases}$$
JAVA: 
dp[i] = dp[i-1] + dp[i-2] + dp[i-3];
Solution.java
int tribonacci(int n) {
    if (n == 0) return 0;
    if (n <= 2) return 1;
    int a = 0, b = 1, c = 1;
    for (int i = 3; i <= n; i++) {
        int d = a + b + c;
        a = b; b = c; c = d;
    }
    return c;
}
Time: O(n) · Space: O(1)

Climbing Stairs (1, 2, or 3 steps)

Counting Linear

Same staircase but you may now jump 1, 2, or 3 steps. The count is the sum of the three preceding ways.

THINK: Three possible "last moves" instead of two — sum of three predecessors.
RECURRENCE:
$$S(n)=\begin{cases}1 & n=0\\1 & n=1\\2 & n=2\\S(n-1)+S(n-2)+S(n-3) & n\gt 2\end{cases}$$
JAVA: 
dp[i] = dp[i-1] + dp[i-2] + dp[i-3];
AHA: Climbing-stairs problems form a family. With allowed step set $\{a,b,c,\dots\}$ the recurrence is $\sum S(n-a)$.
Solution.java
int climbStairs3(int n) {
    if (n == 0) return 1;
    if (n == 1) return 1;
    if (n == 2) return 2;
    int a = 1, b = 1, c = 2;
    for (int i = 3; i <= n; i++) {
        int d = a + b + c;
        a = b; b = c; c = d;
    }
    return c;
}
Time: O(n) · Space: O(1)

Cat. 1 · 06

Weighted Climbing Stairs (k arbitrary moves)

Counting Generalized

Generalized stairs: with allowed step sizes 1..k, count distinct paths to stair n. Sum the previous k entries.

THINK: Generalize from $\{1,2\}$ or $\{1,2,3\}$ to any allowed step set. The "last move" still came from $n-i$ for some allowed $i$.
RECURRENCE:
$$S(n)=\begin{cases}1 & n=0\\\displaystyle\sum_{i=1}^{\min(k,n)} S(n-i) & n\gt 0\end{cases}$$
JAVA: 
for (int j = 1; j <= Math.min(k, i); j++)
    dp[i] += dp[i - j];
Solution.java
long climbK(int n, int k) {
    long[] dp = new long[n + 1];
    dp[0] = 1;
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= Math.min(k, i); j++)
            dp[i] += dp[i - j];
    return dp[n];
}
Time: O(n · k) · Space: O(n)
Cat. 1 · 07

Minimum Cost Climbing Stairs

LeetCode 746 Optimization

Each stair has a cost. You may start from stair 0 or 1 and at every step move 1 or 2 stairs. Find the minimum total cost to reach the top (one past the last stair).

THINK: "Number of ways" → "min cost" is a swap of aggregator. Replace $+$ with $\min$ and add the cost of the step you took.
RECURRENCE:
$$M(n)=\begin{cases}0 & n\le 1\\\min\bigl(M(n-1)+C[n-1],\ M(n-2)+C[n-2]\bigr) & n\gt 1\end{cases}$$
JAVA: 
dp[i] = Math.min(dp[i-1] + cost[i-1],
                dp[i-2] + cost[i-2]);
AHA: The shape is identical to Climbing Stairs — only the operator differs. Recognizing this is the single most useful DP skill.
Solution.java
int minCostClimbingStairs(int[] cost) {
    int n = cost.length;
    int prev2 = 0, prev1 = 0;
    for (int i = 2; i <= n; i++) {
        int cur = Math.min(prev1 + cost[i - 1], prev2 + cost[i - 2]);
        prev2 = prev1;
        prev1 = cur;
    }
    return prev1;
}
Time: O(n) · Space: O(1)
Cat. 1 · 08

Binomial Coefficients / Pascal's Triangle

Combinatorial 2D

Compute C(n, k) — the number of ways to choose k items from n. Pascal's triangle: every entry equals the sum of the two above it.

THINK: Picking $k$ from $n$ items: focus on item $n$ — include it (now pick $k-1$ from $n-1$) or skip (pick $k$ from $n-1$).
RECURRENCE:
$$C(n,k)=\begin{cases}1 & k=0\text{ or }k=n\\C(n-1,k-1)+C(n-1,k) & 0\lt k\lt n\end{cases}$$
JAVA: 
C[i][j] = C[i-1][j-1] + C[i-1][j];
AHA: "Take vs. skip" is the universal subset trick. It returns over and over.
Solution.java
long binom(int n, int k) {
    long[][] C = new long[n + 1][k + 1];
    for (int i = 0; i <= n; i++) {
        C[i][0] = 1;
        for (int j = 1; j <= Math.min(i, k); j++)
            C[i][j] = (i == j) ? 1 : C[i-1][j-1] + C[i-1][j];
    }
    return C[n][k];
}
Time: O(n · k) · Space: O(n · k)

Number of Ways to Reach a Given Score

Counting Coin-Change shape

Count the number of ways to reach a target score using moves of fixed sizes (e.g. {3, 5, 10}). A coin-change variant where order doesn't matter.

THINK: Same as climbing stairs, except the moves are scoring values (e.g. $\{3,5,10\}$).
RECURRENCE:
$$W(S)=\begin{cases}1 & S=0\\\displaystyle\sum_{m_i\le S} W(S-m_i) & S\gt 0\end{cases}$$
JAVA: 
for (int m : moves)
    if (m <= s) dp[s] += dp[s - m];
Solution.java
long countWays(int target, int[] moves) {
    long[] dp = new long[target + 1];
    dp[0] = 1;
    for (int m : moves)
        for (int s = m; s <= target; s++)
            dp[s] += dp[s - m];
    return dp[target];
}
Time: O(target · |moves|) · Space: O(target)

Minimum Number of Perfect Squares

LeetCode 279 Min-coin shape

Find the smallest number of perfect squares (1, 4, 9, 16…) that sum to n. Same skeleton as min-coins with coins = perfect squares.

THINK: Of all squares $\le n$, which one did I "subtract last"? Try each, take the cheapest.
RECURRENCE:
$$M(n)=\begin{cases}0 & n=0\\\displaystyle\min_{1\le i\le \lfloor\sqrt{n}\rfloor}\bigl(M(n-i^2)+1\bigr) & n\gt 0\end{cases}$$
JAVA: 
for (int j = 1; j*j <= i; j++)
    dp[i] = Math.min(dp[i], dp[i - j*j] + 1);
AHA: Identical structure to Coin Change with coins = perfect squares.
Solution.java
int numSquares(int n) {
    int[] dp = new int[n + 1];
    Arrays.fill(dp, Integer.MAX_VALUE);
    dp[0] = 0;
    for (int i = 1; i <= n; i++)
        for (int j = 1; j * j <= i; j++)
            dp[i] = Math.min(dp[i], dp[i - j*j] + 1);
    return dp[n];
}
Time: O(n · √n) · Space: O(n)

Decode Ways

LeetCode 91 Counting

Given a numeric string ('1'→A, '2'→B, … '26'→Z), count the distinct ways to decode it. Watch out for leading zeros.

THINK: At index $i$, the last decoded chunk was either 1 character ($i-1..i$) or 2 characters ($i-2..i$) — provided each is a valid code.
RECURRENCE:
$$D(i)=\begin{cases}1 & i=0\text{ and valid}\\0 & i=0\text{ and invalid}\\D(i-1)+D(i-2) & \text{both 1- and 2-digit decodes valid}\end{cases}$$
JAVA: 
if (s.charAt(i-1) != '0')          dp[i] += dp[i-1];
int two = Integer.parseInt(s.substring(i-2, i));
if (two >= 10 && two <= 26)        dp[i] += dp[i-2];
PITFALL: '0' alone is invalid; "06" is invalid. Validity checks are the trickiest part.
Solution.java
int numDecodings(String s) {
    int n = s.length();
    int[] dp = new int[n + 1];
    dp[0] = 1;
    dp[1] = s.charAt(0) == '0' ? 0 : 1;
    for (int i = 2; i <= n; i++) {
        if (s.charAt(i - 1) != '0')          dp[i] += dp[i - 1];
        int two = Integer.parseInt(s.substring(i - 2, i));
        if (two >= 10 && two <= 26)          dp[i] += dp[i - 2];
    }
    return dp[n];
}
Time: O(n) · Space: O(n)

Maximum Segments (lengths $a$, $b$, $c$)

Optimization Cut-style

Given a length-n rod and three allowed segment sizes a, b, c, cut the rod into the largest number of pieces possible using only those sizes.

THINK: Cut a length-$n$ rod into max number of pieces of allowed sizes. The "last cut" was size $a$, $b$, or $c$ → recurse on remainder.
RECURRENCE:
$$M(n)=\begin{cases}-\infty & n\lt 0\\0 & n=0\\1+\max\bigl(M(n-a),M(n-b),M(n-c)\bigr) & n\gt 0\end{cases}$$
JAVA: 
int best = -1;
if (n >= a && dp[n-a] != -1) best = Math.max(best, dp[n-a]);
if (n >= b && dp[n-b] != -1) best = Math.max(best, dp[n-b]);
if (n >= c && dp[n-c] != -1) best = Math.max(best, dp[n-c]);
dp[n] = (best == -1) ? -1 : best + 1;
Solution.java
int maxSegments(int n, int a, int b, int c) {
    int[] dp = new int[n + 1];
    Arrays.fill(dp, -1);
    dp[0] = 0;
    for (int i = 1; i <= n; i++) {
        if (i - a >= 0 && dp[i - a] != -1) dp[i] = Math.max(dp[i], dp[i - a] + 1);
        if (i - b >= 0 && dp[i - b] != -1) dp[i] = Math.max(dp[i], dp[i - b] + 1);
        if (i - c >= 0 && dp[i - c] != -1) dp[i] = Math.max(dp[i], dp[i - c] + 1);
    }
    return Math.max(dp[n], 0);
}
Time: O(n) · Space: O(n)

Kadane's Algorithm (Max Subarray Sum)

LeetCode 53 Optimization O(n)

Find the contiguous subarray (containing at least one number) with the largest sum. The textbook 1D-DP: at each position decide to extend the current run or start fresh.

THINK: Define $dp[i]$ = best subarray sum ending at $i$. At each step ask: "Does extending help, or is starting fresh at $A[i]$ better?"
RECURRENCE:
$$dp(i)=\begin{cases}A[1] & i=1\\\max\bigl(A[i],\ dp(i-1)+A[i]\bigr) & i\gt 1\end{cases}$$
JAVA: 
dp[i] = Math.max(A[i], dp[i-1] + A[i]);
ans   = Math.max(ans, dp[i]);
AHA: Defining state as "ending at $i$" rather than "first $i$ elements" is the whole trick. Answer is $\max_i dp(i)$.
Solution.java
int maxSubArray(int[] nums) {
    int best = nums[0], cur = nums[0];
    for (int i = 1; i < nums.length; i++) {
        cur  = Math.max(nums[i], cur + nums[i]);
        best = Math.max(best, cur);
    }
    return best;
}
Time: O(n) · Space: O(1)

Minimum Jumps / Jump Game

LeetCode 45 Min-cost

Each cell A[i] tells you the maximum jump length from that cell. Find the minimum number of jumps required to reach the last index from index 0.

THINK: From $i$, I can jump to any $i+1\dots i+A[i]$. Cost = 1 jump + whatever it takes from there.
RECURRENCE:
$$J(i)=\begin{cases}0 & i=n-1\\\displaystyle 1+\min_{1\le k\le \min(A[i],\,n-1-i)} J(i+k) & i\lt n-1\end{cases}$$
JAVA: 
for (int k = 1; k <= A[i] && i + k < n; k++)
    dp[i] = Math.min(dp[i], dp[i + k] + 1);
Solution.java
int jump(int[] A) {
    int n = A.length;
    int[] dp = new int[n];
    Arrays.fill(dp, Integer.MAX_VALUE);
    dp[0] = 0;
    for (int i = 0; i < n; i++)
        if (dp[i] != Integer.MAX_VALUE)
            for (int k = 1; k <= A[i] && i + k < n; k++)
                dp[i + k] = Math.min(dp[i + k], dp[i] + 1);
    return dp[n - 1];
}
Time: O(n²) worst case · Space: O(n)

Sum of Digits Problem (Digit DP)

Digit DP Counting

Count numbers in [0, N] whose digit sum equals a target s. Build the number digit-by-digit while remembering whether you're still bounded by N's prefix (the 'tight' flag).

THINK: Build a number digit-by-digit, left to right. State = (position, remaining sum, still bounded by $N$'s digits?).
RECURRENCE:
$$dp(\text{pos},s,\text{tight})=\begin{cases}1 & \text{pos}=\text{len},\ s=0\\\displaystyle\sum_{d=0}^{\text{up}} dp(\text{pos}+1,\ s-d,\ \text{newTight}) & \text{otherwise}\end{cases}$$
JAVA: 
int up = (tight == 1) ? digits[pos] : 9;
for (int d = 0; d <= up && d <= s; d++)
    res += dp(pos + 1, s - d, tight & (d == up ? 1 : 0));
AHA: The tight flag is the standard digit-DP idiom — tells you whether the next digit is free (0–9) or capped at $N$'s digit.
Solution.java
int[] digits;
Integer[][][] memo;
int countWithDigitSum(int N, int targetSum) {
    String s = Integer.toString(N);
    digits = new int[s.length()];
    for (int i = 0; i < digits.length; i++) digits[i] = s.charAt(i) - '0';
    memo = new Integer[digits.length][targetSum + 1][2];
    return solve(0, targetSum, 1);
}
int solve(int pos, int sumLeft, int tight) {
    if (sumLeft < 0) return 0;
    if (pos == digits.length) return sumLeft == 0 ? 1 : 0;
    if (memo[pos][sumLeft][tight] != null) return memo[pos][sumLeft][tight];
    int up  = (tight == 1) ? digits[pos] : 9;
    int res = 0;
    for (int d = 0; d <= up; d++)
        res += solve(pos + 1, sumLeft - d, tight & (d == up ? 1 : 0));
    return memo[pos][sumLeft][tight] = res;
}
Time: O(len · sum · 2 · 10) · Space: O(len · sum)

Non-Decreasing Digits Problem

Digit DP Counting

Count n-digit numbers whose digits never decrease left-to-right. The state needs the previous digit so the next one can be ≥ it.

THINK: "Last digit so far" is part of the state because the next digit must be $\ge$ it.
RECURRENCE:
$$dp(n,d)=\begin{cases}1 & n=1\\\displaystyle\sum_{\text{prev}=1}^{d} dp(n-1,\text{prev}) & n\gt 1\end{cases}$$
JAVA: 
for (int prev = 1; prev <= d; prev++)
    dp[n][d] += dp[n-1][prev];
Solution.java
long countNonDecreasing(int n) {
    long[][] dp = new long[n + 1][10];
    for (int d = 0; d < 10; d++) dp[1][d] = 1;
    for (int i = 2; i <= n; i++)
        for (int d = 0; d < 10; d++)
            for (int prev = 0; prev <= d; prev++)
                dp[i][d] += dp[i - 1][prev];

                if (op == '&') {
                    T[i][j] += lT * rT;
                    F[i][j] += lT * rF + lF * rT + lF * rF;
                } else if (op == '|') {
                    T[i][j] += lT * rT + lT * rF + lF * rT;
                    F[i][j] += lF * rF;
                } else {
                    T[i][j] += lT * rF + lF * rT;
                    F[i][j] += lT * rT + lF * rF;
                }
            }
        }
    return T[0][n - 1];
}
Time: O(n³) · Space: O(n²)

Optimal Game Strategy (extended)

Game Theory Range DP

Same setup as Optimal Strategy but the recurrence reasons over both players' future moves explicitly. The current player maximizes; the opponent minimizes.

THINK: Same min-of-max framework as the simpler version, applied over both players' future moves.
RECURRENCE:
$$G(i,j)=\begin{cases}A_i & i=j\\\max\!\bigl(A_i+\min(G(i+2,j),G(i+1,j-1)),\ A_j+\min(G(i+1,j-1),G(i,j-2))\bigr) & \text{else}\end{cases}$$
JAVA: 
dp[i][j] = Math.max(
    A[i] + Math.min(dp[i+2][j],   dp[i+1][j-1]),
    A[j] + Math.min(dp[i+1][j-1], dp[i][j-2]));
Solution.java
int optimalGameStrategy(int[] A) {
    int n = A.length;
    int[][] dp = new int[n][n];
    for (int i = 0; i < n; i++) dp[i][i] = A[i];
    for (int len = 2; len <= n; len++)
        for (int i = 0; i + len - 1 < n; i++) {
            int j = i + len - 1;
            int pickI = A[i] + Math.min(
                (i + 2 <= j) ? dp[i + 2][j] : 0,
                (i + 1 <= j - 1) ? dp[i + 1][j - 1] : 0);
            int pickJ = A[j] + Math.min(
                (i + 1 <= j - 1) ? dp[i + 1][j - 1] : 0,
                (i <= j - 2) ? dp[i][j - 2] : 0);
            dp[i][j] = Math.max(pickI, pickJ);
        }
    return dp[0][n - 1];
}

Bellman–Ford

Graph Min-cost

Compute shortest paths from a source vertex to all others, including graphs with negative edges. Relax every edge V−1 times.

THINK: "Distance to $v$ after at most $k$ edges" admits one transition: relax over every edge entering $v$.
RECURRENCE:
$$d(v,k)=\begin{cases}\infty & \text{initial non-source}\\\min\!\bigl(d(v,k-1),\ \displaystyle\min_{u}\,d(u,k-1)+w(u,v)\bigr) & \text{else}\end{cases}$$
JAVA: 
for (int k = 1; k < V; k++)
    for (int[] e : edges)        // {u, v, w}
        if (d[e[0]] + e[2] < d[e[1]])
            d[e[1]] = d[e[0]] + e[2];
Solution.java
int[] bellmanFord(int V, int[][] edges, int src) {
    int[] dist = new int[V];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[src] = 0;
    for (int k = 0; k < V - 1; k++)
        for (int[] e : edges) {
            int u = e[0], v = e[1], w = e[2];
            if (dist[u] != Integer.MAX_VALUE && dist[u] + w < dist[v])
                dist[v] = dist[u] + w;
        }
    return dist;
}

Floyd–Warshall

Compute shortest paths between every pair of vertices in a weighted graph. Allow each vertex k in turn to be a transit point.

$$D(i,j,k)=\begin{cases}w(i,j) & k=0\\\min\!\bigl(D(i,j,k-1),\ D(i,k,k-1)+D(k,j,k-1)\bigr) & \text{else}\end{cases}$$

Solution.java
void floydWarshall(int[][] D) {
    int V = D.length;

Re-rooting (any node as root)

Tree Two-Pass

Compute, for every node, the answer obtained when that node is treated as the root of the tree. A two-pass DFS does it in O(N).

THINK: Two-pass DP. Pass 1: root at node 0, compute downward best. Pass 2: propagate "best from above" using parent's full answer minus this child's contribution.
RECURRENCE:
$$H(u)=\begin{cases}0 & u\text{ is leaf in some rooting}\\\max\bigl(H(v)+1\ :\ v\in\text{neighbors}(u)\bigr) & \text{else}\end{cases}$$
JAVA: 
// pass 1: down[u]  via DFS rooted at 0
// pass 2: up[v] derived from parent: up[v] = best subtree excluding v
H[u] = Math.max(down[u], up[u]);
Solution.java
int n;
List<List<Integer>> adj;
int[] down, up;
void dfs1(int u, int parent) {
    down[u] = 0;
    for (int v : adj.get(u))
        if (v != parent) {
            dfs1(v, u);
            down[u] = Math.max(down[u], down[v] + 1);
        }
}
void dfs2(int u, int parent) {
    int best1 = -1, best2 = -1;
    for (int v : adj.get(u))
        if (v != parent) {
            int h = down[v] + 1;
            if (h > best1) { best2 = best1; best1 = h; }
            else if (h > best2) { best2 = h; }
        }
    for (int v : adj.get(u))
        if (v != parent) {
            int siblingBest = (down[v] + 1 == best1) ? best2 : best1;
            up[v] = Math.max(up[u] + 1,
                              siblingBest == -1 ? 1 : siblingBest + 1);
            dfs2(v, u);
        }
}

Classic LIS-style

Given n boxes with three rotations each, stack them so each box's base strictly fits inside the box below. Maximize the total stack height.

THINK: Each box rotation = a separate item. Sort by base, run LIS where the relation is "fits on top of".
RECURRENCE:
$$H(i)=\begin{cases}h_i & i=0\\\displaystyle\max_{0\le j\lt i,\ \text{fits}}\bigl(H(j)+h_i\bigr) & \text{else}\end{cases}$$
JAVA: 
// each box rotation is its own item; sort by base, then LIS by 'fits on top'
Arrays.sort(boxes, (x, y) -> y.base() - x.base());
dp[i] = boxes[i].h;
for (int j = 0; j < i; j++)
    if (fits(boxes[i], boxes[j]))
        dp[i] = Math.max(dp[i], dp[j] + boxes[i].h);
Solution.java
int boxStacking(int[][] boxes) {
    List<int[]> rotations = new ArrayList<>();
    for (int[] b : boxes) {
        int[] s = b.clone();
        Arrays.sort(s);
        rotations.add(new int[]{s[0], s[1], s[2]});
        rotations.add(new int[]{s[0], s[2], s[1]});
        rotations.add(new int[]{s[1], s[2], s[0]});
    }
    rotations.sort((a, b) -> (b[0] * b[1]) - (a[0] * a[1]));
    int n = rotations.size(), best = 0;
    int[] dp = new int[n];
    for (int i = 0; i < n; i++) {
        dp[i] = rotations.get(i)[2];
        for (int j = 0; j < i; j++)
            if (rotations.get(j)[0] > rotations.get(i)[0]
                    && rotations.get(j)[1] > rotations.get(i)[1])
                dp[i] = Math.max(dp[i], dp[j] + rotations.get(i)[2]);
        best = Math.max(best, dp[i]);
    }
    return best;
}

Classic Min-cost

THINK: Decide where the first line ends. Cost of that line + optimal cost for the rest.
RECURRENCE:

int wordWrap(int[] len, int width) {
    int n = len.length;
    int[] dp = new int[n + 1];
    Arrays.fill(dp, Integer.MAX_VALUE);
    dp[n] = 0;
    for (int i = n - 1; i >= 0; i--) {
        int line = -1;
        for (int j = i; j < n; j++) {
            line += len[j] + 1;
            if (line > width) break;
            int slack = width - line;
            int cost  = (j == n - 1) ? 0 : slack * slack * slack;
            if (dp[j + 1] != Integer.MAX_VALUE)
                dp[i] = Math.min(dp[i], cost + dp[j + 1]);
        }
    }
    return dp[0];
}

Build a stack of total height n using m kinds of tiles, with at most k tiles of each kind. Count the distinct stacks.

THINK: For total height $n$, decide how many tiles of the current type to stack ($0$ to $k$), then move to the next type.
RECURRENCE:

long tileStacking(int n, int m, int k) {
    long[][] dp = new long[n + 1][m + 1];

        for (int h = 0; h <= n; h++) {

Set Partitions (Bell Numbers)

Count the number of ways to partition a set of n distinct elements (the Bell number B(n)). Use the recurrence B(n) = Σ C(n−1, k) · B(k).

THINK: Pick a subset of size $k$ that contains element 1. Partition the remaining $n-1-k$ elements freely.
RECURRENCE:

Solution.java
long bell(int n) {
    long[] B = new long[n + 1];
    long[][] C = new long[n + 1][n + 1];
    for (int i = 0; i <= n; i++) {
        C[i][0] = 1;
        for (int j = 1; j <= i; j++)
            C[i][j] = (i == j) ? 1 : C[i - 1][j - 1] + C[i - 1][j];
    }
    B[0] = 1;
    for (int i = 1; i <= n; i++)
        for (int k = 0; k < i; k++)
            B[i] += C[i - 1][k] * B[k];
    return B[n];
}

Solution.java
int minAssignment(int[][] cost) {
    int n = cost.length;
    int[] dp = new int[1 << n];
    Arrays.fill(dp, Integer.MAX_VALUE);
    dp[0] = 0;
    for (int mask = 0; mask < (1 << n); mask++) {
        if (dp[mask] == Integer.MAX_VALUE) continue;
        int p = Integer.bitCount(mask);
        if (p == n) continue;
        for (int j = 0; j < n; j++)
            if ((mask & (1 << j)) == 0)
                dp[mask | (1 << j)] = Math.min(
                    dp[mask | (1 << j)],
                    dp[mask] + cost[p][j]);
    }
    return dp[(1 << n) - 1];
}

Double Helix Problem

Classic LCS-style

Two integer sequences cross at common values. Walk one of them, switching tracks at any common element. Maximize the sum of values walked.

THINK: Two arrays with crossover points. State $(i,j)$ = best when prefix $i$ of $A$ and prefix $j$ of $B$ consumed; on equal values you may switch arrays.
RECURRENCE:
$$dp(i,j)=\begin{cases}0 & i=0\text{ or }j=0\\dp(i-1,j-1)+A_i & A_i=B_j\\\max\bigl(dp(i-1,j),\ dp(i,j-1)\bigr) & \text{else}\end{cases}$$
JAVA: 
dp[i][j] = (A[i-1] == B[j-1])
    ? dp[i-1][j-1] + A[i-1]
    : Math.max(dp[i-1][j], dp[i][j-1]);
Solution.java
int doubleHelix(int[] A, int[] B) {
    int m = A.length, n = B.length;
    int i = 0, j = 0, sumA = 0, sumB = 0, total = 0;
    while (i < m && j < n) {
        if (A[i] < B[j]) sumA += A[i++];
        else if (B[j] < A[i]) sumB += B[j++];
        else {
            total += Math.max(sumA, sumB) + A[i];
            sumA = sumB = 0;
            i++; j++;
        }
    }
    while (i < m) sumA += A[i++];
    while (j < n) sumB += B[j++];
    total += Math.max(sumA, sumB);
    return total;
}
Time: O(m + n) · Space: O(1)

Final Workflow Checklist

Cheat Sheet Read Last

A 10-step ritual to apply to every new DP problem. Working through it methodically beats memorizing recurrences.

When a new problem lands, run through this list before writing a single line of code. The recurrence will fall out almost mechanically.

  1. Restate in your own words. Strip the story. What is being optimized / counted / decided?
  2. Brute force first. Write the recursive solution that tries every choice. The recurrence is hidden in there — DP just adds memoization.
  3. Spot the parameters. What changes between recursive calls? Those are your DP state dimensions.
  4. Last move principle. Reason backward: "What was the last move that brought me to this state?" Each possible last move is a branch.
  5. Pick the aggregator. $\min$, $\max$, sum, OR — derived from "are we optimizing, counting, or checking feasibility?"
  6. Find base cases. Smallest possible state. Be ruthless about edge cases.
  7. Bound the state space. Multiply state-dimension sizes; that's a rough lower bound on time complexity.
  8. Pick the direction. Top-down memo is easier to write; bottom-up tables are easier to optimize for space.
  9. Reduce dimensions. If only the previous 1–2 layers are needed, switch to rolling arrays.
  10. Sanity test. Hand-trace $n=0,1,2,3$. If the recurrence agrees with the obvious answer there, you're almost certainly correct.
One sentence summary: Every DP problem in this guide is the same shape — define the state, enumerate the last decision, write a transition over predecessors, set base cases, choose an aggregator. The 70+ recurrences above are concrete instances of that one mental model.
