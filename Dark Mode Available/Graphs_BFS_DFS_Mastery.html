① What is a Graph?

A graph is just dots connected by lines. The dots are nodes (or vertices), the lines are edges. That's it. Cities connected by roads, people connected by friendships, web pages connected by links — all graphs.

A ─── B │ ╱ │ │ ╱ │ C ─── D ─── E

Compare to trees: a tree is a special graph with no cycles and exactly one path between any two nodes. A general graph can have cycles (a path that loops back), multiple paths between two nodes, and even disconnected pieces. That's why graph code always needs a visited set — without it you'd loop forever.

Vocabulary

Vertex / NodeA single dot. We'll usually label them with numbers 0..n-1. EdgeA connection between two vertices. DirectedEdges have a direction (one-way street). A → B doesn't mean B → A. UndirectedEdges go both ways (a road). If A — B, you can walk both directions. WeightedEdges carry a number (cost, distance, time). CycleA path that ends where it started. Trees have none; graphs often do. ConnectedAn undirected graph where you can reach any node from any other. ComponentA maximal connected piece. The graph above is 1 component; if D-E was missing, it'd be 2. DegreeHow many edges touch a node. DAGDirected Acyclic Graph — directed and no cycles. Think course prerequisites.
The one rule that separates trees from graphs: graphs can revisit. So every traversal needs a visited[] array or a Set<Integer>. Forget this and you get an infinite loop.

② How to store a graph in code

There are 3 common ways. You'll use #1 for 95% of problems.

① Adjacency List (the workhorse)

For each node, store a list of its neighbors. Imagine a phone book: name → list of friends.

// n = number of nodes, edges = int[][] like {{0,1},{1,2},{0,2}}
List<List<Integer>> adj = new ArrayList<>();
for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
for (int[] e : edges){
    adj.get(e[0]).add(e[1]);
    adj.get(e[1]).add(e[0]);   // drop this line if directed
}
SpaceO(V + E) — tiny for sparse graphs (most real ones). Lookup neighborsO(degree) — fast. Edge exists?O(degree) — fine.

② Adjacency Matrix

An n × n grid of booleans/ints. m[i][j] = 1 means edge from i to j.

int[][] m = new int[n][n];
for (int[] e : edges){
    m[e[0]][e[1]] = 1;
    m[e[1]][e[0]] = 1;
}

Good when the graph is dense (most pairs connected) or when "is there an edge from i to j?" is asked a lot. Bad for huge sparse graphs — wastes memory.

③ Edge List

Just an array of pairs {u, v}. Mostly useful for algorithms that scan all edges (Kruskal, Bellman-Ford). For BFS/DFS, convert it to an adjacency list first.

FormatSpaceBest for
Adjacency listO(V+E)BFS, DFS, sparse graphs (default pick)
Adjacency matrixO(V²)Dense graphs, fast edge lookup, Floyd-Warshall
Edge listO(E)Kruskal, Bellman-Ford, simple iteration

③ Grids ARE graphs (this unlocks half of LeetCode)

A 2D grid like char[][] grid is secretly a graph. Each cell is a node. Each cell connects to its 4 neighbors (up, down, left, right) — sometimes 8 if diagonals count.

0 0 1 0 0 1 1 0 ← 1's are land, 0's are water 0 0 0 0 "Find islands" = "Find connected components"

The magic phrase: "directions array." Memorize this:

int[][] dirs = {{-1,0},{1,0},{0,-1},{0,1}};   // up, down, left, right

for (int[] d : dirs){
    int nr = r + d[0];
    int nc = c + d[1];
    if (nr < 0 || nr >= rows || nc < 0 || nc >= cols) continue;
    // nr,nc is a valid neighbor
}
Trick: instead of a separate visited[][], you can often mark the grid itself — flip a '1' to '0' after visiting. Saves memory. The downside: you mutate the input. Most interviewers are fine with it; mention the trade-off.

④ The two templates you'll write 100 times

BFS template

void bfs(int start, List<List<Integer>> adj){
    int n = adj.size();
    boolean[] visited = new boolean[n];
    Queue<Integer> q = new LinkedList<>();
    q.add(start);
    visited[start] = true;        // 🔑 mark when ENQUEUED, not when polled
    while (!q.isEmpty()){
        int cur = q.poll();
        // do work with cur
        for (int nb : adj.get(cur)){
            if (!visited[nb]){
                visited[nb] = true;
                q.add(nb);
            }
        }
    }
}
The #1 BFS bug: marking visited when you poll instead of when you enqueue. If the same node gets queued by 5 neighbors before being polled, you process it 5 times. Always mark on enqueue.

DFS templates (recursive AND iterative)

// Recursive — clean and short
void dfs(int u, List<List<Integer>> adj, boolean[] visited){
    if (visited[u]) return;
    visited[u] = true;
    // do work with u
    for (int v : adj.get(u)) dfs(v, adj, visited);
}

// Iterative — needed when the graph is HUGE (avoid stack overflow)
void dfsIter(int start, List<List<Integer>> adj){
    boolean[] visited = new boolean[adj.size()];
    Deque<Integer> stack = new ArrayDeque<>();
    stack.push(start);
    while (!stack.isEmpty()){
        int u = stack.pop();
        if (visited[u]) continue;
        visited[u] = true;
        // do work
        for (int v : adj.get(u)) if (!visited[v]) stack.push(v);
    }
}
BFS vs DFS at a glance:
BFS uses a queue and explores in layers. Best for shortest path in unweighted graphs.
DFS uses a stack (or recursion) and goes deep first. Best for connectivity, cycles, components, topological sort.

⑤ BFS Track 🚂 — Very Easy → Hard

BFS gives you shortest distance in unweighted graphs for free. The number of "ripple layers" you go out from the source = the distance.

VERY EASY BG1. Find if Path Exists in Graph (LC 1971)

Problem: Given an undirected graph and two nodes source, destination, return true if a path exists.

Intuition

Start BFS from source. If you ever pop destination, return true. If the queue empties without reaching it, return false.

public boolean validPath(int n, int[][] edges, int src, int dst){
    List<List<Integer>> adj = new ArrayList<>();
    for (int i=0; i<n; i++) adj.add(new ArrayList<>());
    for (int[] e : edges){
        adj.get(e[0]).add(e[1]);
        adj.get(e[1]).add(e[0]);
    }
    boolean[] visited = new boolean[n];
    Queue<Integer> q = new LinkedList<>();
    q.add(src); visited[src] = true;
    while (!q.isEmpty()){
        int u = q.poll();
        if (u == dst) return true;
        for (int v : adj.get(u)){
            if (!visited[v]){
                visited[v] = true;
                q.add(v);
            }
        }
    }
    return false;
}

VERY EASY BG2. Flood Fill (LC 733)

Problem: Given an image (2D int grid), a starting pixel (sr, sc), and a new color, repaint the connected region of the same color starting at that pixel — like the paint bucket in MS Paint.

public int[][] floodFill(int[][] image, int sr, int sc, int color){
    int oldColor = image[sr][sc];
    if (oldColor == color) return image;   // avoid infinite loop
    int R = image.length, C = image[0].length;
    int[][] dirs = {{-1,0},{1,0},{0,-1},{0,1}};
    Queue<int[]> q = new LinkedList<>();
    q.add(new int[]{sr, sc});
    image[sr][sc] = color;            // mark visited by repainting
    while (!q.isEmpty()){
        int[] cur = q.poll();
        for (int[] d : dirs){
            int nr = cur[0] + d[0], nc = cur[1] + d[1];
            if (nr<0||nr>=R||nc<0||nc>=C) continue;
            if (image[nr][nc] != oldColor) continue;
            image[nr][nc] = color;
            q.add(new int[]{nr, nc});
        }
    }
    return image;
}
The "color already matches" trap: If oldColor == color, you'll keep reading neighbors as "still old color" and loop forever. Always early-return.

EASY BG3. Number of Islands (LC 200)

Problem: A grid of '1' (land) and '0' (water). Count connected groups of land (4-directional).

Intuition

Walk through every cell. When you hit unvisited land, increment the counter and BFS to drown that whole island (mark as '0'). Cells you've already drowned will be skipped automatically.

public int numIslands(char[][] g){
    int R = g.length, C = g[0].length, count = 0;
    int[][] dirs = {{-1,0},{1,0},{0,-1},{0,1}};
    for (int r=0; r<R; r++) for (int c=0; c<C; c++){
        if (g[r][c] != '1') continue;
        count++;
        Queue<int[]> q = new LinkedList<>();
        q.add(new int[]{r,c});
        g[r][c] = '0';
        while(!q.isEmpty()){
            int[] cur = q.poll();
            for (int[] d : dirs){
                int nr=cur[0]+d[0], nc=cur[1]+d[1];
                if (nr<0||nr>=R||nc<0||nc>=C||g[nr][nc] != '1') continue;
                g[nr][nc] = '0';
                q.add(new int[]{nr,nc});
            }
        }
    }
    return count;
}
TimeO(R·C) — every cell entered once. SpaceO(min(R,C)) — BFS queue holds at most one frontier.

MEDIUM BG4. Rotting Oranges (LC 994)

Problem: 0 = empty, 1 = fresh, 2 = rotten. Every minute, rotten oranges rot their 4 neighbors. Return the minutes until all are rotten, or -1 if impossible.

Intuition (multi-source BFS — the upgrade)

Don't BFS from one source. BFS from every rotten orange at the same time. Push all rotten oranges into the queue at the start. Each BFS layer = one minute.

public int orangesRotting(int[][] g){
    int R = g.length, C = g[0].length, fresh = 0, minutes = 0;
    Queue<int[]> q = new LinkedList<>();
    for (int r=0; r<R; r++) for (int c=0; c<C; c++){
        if (g[r][c] == 2) q.add(new int[]{r,c});
        else if (g[r][c] == 1) fresh++;
    }
    int[][] dirs = {{-1,0},{1,0},{0,-1},{0,1}};
    while (!q.isEmpty() && fresh > 0){
        int size = q.size();          // process one minute at a time
        for (int i=0; i<size; i++){
            int[] cur = q.poll();
            for (int[] d : dirs){
                int nr=cur[0]+d[0], nc=cur[1]+d[1];
                if (nr<0||nr>=R||nc<0||nc>=C||g[nr][nc] != 1) continue;
                g[nr][nc] = 2;
                fresh--;
                q.add(new int[]{nr,nc});
            }
        }
        minutes++;
    }
    return fresh == 0 ? minutes : -1;
}
Multi-source BFS is one of the most powerful tricks in graphs. Whenever a problem says "from any of these starting points, find the minimum…" — toss them all in the queue at once and BFS in parallel.

MEDIUM BG5. 01 Matrix (LC 542)

Problem: For each cell in a 0/1 grid, return the distance to the nearest 0.

Intuition (multi-source BFS, again)

Naive: from every 1, BFS to find nearest 0. Too slow. Flip it: start BFS from every 0 simultaneously, expanding outward. The layer at which a 1 is reached IS its distance.

public int[][] updateMatrix(int[][] mat){
    int R = mat.length, C = mat[0].length;
    int[][] dist = new int[R][C];
    Queue<int[]> q = new LinkedList<>();
    for (int r=0; r<R; r++) for (int c=0; c<C; c++){
        if (mat[r][c] == 0) q.add(new int[]{r,c});
        else dist[r][c] = -1;       // "not visited yet"
    }
    int[][] dirs = {{-1,0},{1,0},{0,-1},{0,1}};
    while(!q.isEmpty()){
        int[] cur = q.poll();
        for (int[] d : dirs){
            int nr=cur[0]+d[0], nc=cur[1]+d[1];
            if (nr<0||nr>=R||nc<0||nc>=C||dist[nr][nc] != -1) continue;
            dist[nr][nc] = dist[cur[0]][cur[1]] + 1;
            q.add(new int[]{nr,nc});
        }
    }
    return dist;
}

MEDIUM BG6. Word Ladder (LC 127)

Problem: Given beginWord, endWord, and a wordList, transform begin → end one letter at a time, every intermediate word must be in the list. Return the length of the shortest sequence (words count), or 0 if impossible.

Intuition

The graph is "hidden": nodes = words, edges = "differ by exactly one letter." BFS from beginWord, generate neighbors by trying every letter at every position. First time we reach endWord, that's the shortest distance.

public int ladderLength(String beginWord, String endWord, List<String> wordList){
    Set<String> dict = new HashSet<>(wordList);
    if (!dict.contains(endWord)) return 0;
    Queue<String> q = new LinkedList<>();
    q.add(beginWord);
    dict.remove(beginWord);
    int steps = 1;
    while (!q.isEmpty()){
        int size = q.size();
        for (int i=0; i<size; i++){
            String w = q.poll();
            if (w.equals(endWord)) return steps;
            char[] arr = w.toCharArray();
            for (int p=0; p<arr.length; p++){
                char orig = arr[p];
                for (char ch='a'; ch<='z'; ch++){
                    if (ch == orig) continue;
                    arr[p] = ch;
                    String nxt = new String(arr);
                    if (dict.remove(nxt)) q.add(nxt);   // remove == "mark visited"
                }
                arr[p] = orig;
            }
        }
        steps++;
    }
    return 0;
}
"Implicit graph" trick: You don't need to build the graph if you can compute neighbors on the fly. Saves tons of memory.

HARD BG7. Shortest Bridge (LC 934)

Problem: A grid has exactly two islands of 1s. Flip the minimum number of 0s to 1s to connect them.

Intuition (DFS + multi-source BFS combo)

  1. Find the first island with DFS. Mark all its cells as 2 AND push them all into a queue.
  2. BFS outward from that whole island in parallel. Every BFS layer = one flip. The instant you touch a 1 (the second island), return the layer count.
int[][] dirs = {{-1,0},{1,0},{0,-1},{0,1}};

public int shortestBridge(int[][] g){
    int R = g.length, C = g[0].length;
    Queue<int[]> q = new LinkedList<>();
    boolean found = false;
    for (int r=0; r<R && !found; r++)
        for (int c=0; c<C && !found; c++)
            if (g[r][c] == 1){ paint(g, r, c, q); found = true; }

    int flips = 0;
    while(!q.isEmpty()){
        int size = q.size();
        for (int i=0; i<size; i++){
            int[] cur = q.poll();
            for (int[] d : dirs){
                int nr=cur[0]+d[0], nc=cur[1]+d[1];
                if (nr<0||nr>=R||nc<0||nc>=C||g[nr][nc] == 2) continue;
                if (g[nr][nc] == 1) return flips;     // touched island #2
                g[nr][nc] = 2;                          // mark water as visited
                q.add(new int[]{nr,nc});
            }
        }
        flips++;
    }
    return -1;   // unreachable per problem guarantees
}
private void paint(int[][] g, int r, int c, Queue<int[]> q){
    if (r<0||r>=g.length||c<0||c>=g[0].length||g[r][c] != 1) return;
    g[r][c] = 2;
    q.add(new int[]{r,c});
    for (int[] d : dirs) paint(g, r+d[0], c+d[1], q);
}

HARD BG8. Bus Routes (LC 815)

Problem: routes[i] = list of stops bus i visits in a loop. Start at source, want to reach target. Return the minimum number of buses you must take, or -1.

Intuition

Trick: BFS over buses, not stops. Build stop → list of buses serving it. Start by enqueuing every bus that passes source. Each BFS layer = +1 bus ridden.

public int numBusesToDestination(int[][] routes, int src, int tgt){
    if (src == tgt) return 0;
    Map<Integer, List<Integer>> stopToBuses = new HashMap<>();
    for (int b=0; b<routes.length; b++)
        for (int stop : routes[b])
            stopToBuses.computeIfAbsent(stop, k -> new ArrayList<>()).add(b);

    Queue<Integer> q = new LinkedList<>();
    Set<Integer> visitedStops = new HashSet<>();
    Set<Integer> visitedBuses = new HashSet<>();
    q.add(src); visitedStops.add(src);
    int buses = 0;
    while (!q.isEmpty()){
        int size = q.size();
        buses++;
        for (int i=0; i<size; i++){
            int stop = q.poll();
            for (int b : stopToBuses.getOrDefault(stop, List.of())){
                if (!visitedBuses.add(b)) continue;     // already rode this bus
                for (int nxtStop : routes[b]){
                    if (nxtStop == tgt) return buses;
                    if (visitedStops.add(nxtStop)) q.add(nxtStop);
                }
            }
        }
    }
    return -1;
}
Lesson: "What's a node?" is the most important graph question. Sometimes nodes are buses. Sometimes states. Sometimes (word, position) tuples. Pick the right node and the algorithm writes itself.

⑥ DFS Track 🪂 — Very Easy → Hard

DFS is your go-to when the question is about structure: connectivity, cycles, components, ordering, "is X reachable from Y," "are there any back edges." Use BFS instead when the question is about shortest distance.

VERY EASY DG1. Number of Islands (DFS) (LC 200)

Same problem as BG3, written with recursive DFS. This is the version you'll see most often in interviews — shorter and easier to whiteboard.

public int numIslands(char[][] g){
    int count = 0;
    for (int r=0; r<g.length; r++)
        for (int c=0; c<g[0].length; c++)
            if (g[r][c] == '1'){ sink(g, r, c); count++; }
    return count;
}
private void sink(char[][] g, int r, int c){
    if (r<0||r>=g.length||c<0||c>=g[0].length||g[r][c] != '1') return;
    g[r][c] = '0';
    sink(g, r-1, c); sink(g, r+1, c);
    sink(g, r, c-1); sink(g, r, c+1);
}

VERY EASY DG2. Number of Provinces (LC 547)

Problem: An n × n matrix isConnected where isConnected[i][j] = 1 means city i and j are connected. Count provinces (connected components of cities).

Intuition

Standard "count connected components." Walk every city; if not visited, DFS to mark all in its province; bump the counter.

public int findCircleNum(int[][] m){
    int n = m.length, count = 0;
    boolean[] visited = new boolean[n];
    for (int i=0; i<n; i++){
        if (!visited[i]){ dfs(m, visited, i); count++; }
    }
    return count;
}
private void dfs(int[][] m, boolean[] vis, int u){
    vis[u] = true;
    for (int v=0; v<m.length; v++)
        if (m[u][v] == 1 && !vis[v]) dfs(m, vis, v);
}

EASY DG3. Max Area of Island (LC 695)

Problem: Same as Number of Islands, but return the area of the largest one.

Intuition

DFS that returns the area of the island it explored. 1 + dfs(up) + dfs(down) + dfs(left) + dfs(right). Track the global max.

public int maxAreaOfIsland(int[][] g){
    int best = 0;
    for (int r=0; r<g.length; r++)
        for (int c=0; c<g[0].length; c++)
            if (g[r][c] == 1) best = Math.max(best, area(g, r, c));
    return best;
}
private int area(int[][] g, int r, int c){
    if (r<0||r>=g.length||c<0||c>=g[0].length||g[r][c] != 1) return 0;
    g[r][c] = 0;          // mark visited
    return 1 + area(g,r-1,c) + area(g,r+1,c) + area(g,r,c-1) + area(g,r,c+1);
}

MEDIUM DG4. Clone Graph (LC 133)

Problem: Make a deep copy of an undirected connected graph. Each node has a value and a list of neighbors.

Intuition

Every original node maps to exactly one clone. Use a HashMap<Node, Node> as your "visited" — if you've cloned this node before, return the existing clone (this also breaks cycles).

Map<Node, Node> map = new HashMap<>();

public Node cloneGraph(Node node){
    if (node == null) return null;
    if (map.containsKey(node)) return map.get(node);
    Node copy = new Node(node.val);
    map.put(node, copy);                                  // 🔑 BEFORE recursing
    for (Node nb : node.neighbors)
        copy.neighbors.add(cloneGraph(nb));
    return copy;
}
Order matters! Put the clone in the map before recursing on neighbors. Otherwise, a cycle (A → B → A) recurses infinitely because the second visit to A doesn't see itself yet.

MEDIUM DG5. Course Schedule (Cycle Detection) (LC 207)

Problem: numCourses courses with prerequisites. Each prereq [a,b] means "to take a, you must take b first." Return true if all courses can be finished — i.e., the directed graph has no cycle.

Intuition (3-color DFS)

Each node has 3 states:

  • 0 (white) — never visited.
  • 1 (gray) — currently in the recursion stack (we're exploring it right now).
  • 2 (black) — fully finished, no cycle through here.

If during DFS you reach a gray node, that's a back edge → cycle exists.

public boolean canFinish(int n, int[][] prereq){
    List<List<Integer>> adj = new ArrayList<>();
    for (int i=0; i<n; i++) adj.add(new ArrayList<>());
    for (int[] p : prereq) adj.get(p[1]).add(p[0]);   // b -> a
    int[] state = new int[n];
    for (int i=0; i<n; i++)
        if (state[i] == 0 && hasCycle(i, adj, state)) return false;
    return true;
}
private boolean hasCycle(int u, List<List<Integer>> adj, int[] state){
    state[u] = 1;                       // gray — visiting
    for (int v : adj.get(u)){
        if (state[v] == 1) return true;             // hit gray = cycle
        if (state[v] == 0 && hasCycle(v, adj, state)) return true;
    }
    state[u] = 2;                       // black — done
    return false;
}
Why 3 colors and not 2? A 2-color visited[] tells you "have I seen this before?" but not "am I in the middle of seeing it?" Only the latter detects cycles in directed graphs. Two-color visited works fine for cycle detection in undirected graphs (with a parent check), but for directed you need the 3-color trick.

MEDIUM DG6. Pacific Atlantic Water Flow (LC 417)

Problem: A grid of heights. Water flows from a cell to a neighbor with equal or lower height. Pacific is at top/left edges, Atlantic at bottom/right. Return all cells from which water can reach both oceans.

Intuition (reverse the flow)

Going forward (every cell asking "can I reach an ocean?") is wasteful. Instead, run two DFS from the oceans backward: which cells can the Pacific reach by going uphill? Which can the Atlantic reach? The answer = intersection.

int[][] dirs = {{-1,0},{1,0},{0,-1},{0,1}};

public List<List<Integer>> pacificAtlantic(int[][] h){
    int R = h.length, C = h[0].length;
    boolean[][] pac = new boolean[R][C], atl = new boolean[R][C];
    for (int r=0; r<R; r++){
        dfs(h, r, 0,   pac);            // left edge — Pacific
        dfs(h, r, C-1, atl);            // right edge — Atlantic
    }
    for (int c=0; c<C; c++){
        dfs(h, 0,   c, pac);            // top — Pacific
        dfs(h, R-1, c, atl);            // bottom — Atlantic
    }
    List<List<Integer>> ans = new ArrayList<>();
    for (int r=0; r<R; r++) for (int c=0; c<C; c++)
        if (pac[r][c] && atl[r][c]) ans.add(List.of(r,c));
    return ans;
}
private void dfs(int[][] h, int r, int c, boolean[][] seen){
    seen[r][c] = true;
    for (int[] d : dirs){
        int nr=r+d[0], nc=c+d[1];
        if (nr<0||nr>=h.length||nc<0||nc>=h[0].length) continue;
        if (seen[nr][nc] || h[nr][nc] < h[r][c]) continue;   // uphill only
        dfs(h, nr, nc, seen);
    }
}

MEDIUM DG7. Surrounded Regions (LC 130)

Problem: Capture all 'O's that are completely surrounded by 'X's. Any 'O' connected to the border survives.

Intuition (border-out trick)

Hard: "find every O that's NOT connected to a border." Easy: "find every O that IS connected to a border, mark it safe, then flip everything else."

public void solve(char[][] b){
    int R = b.length, C = b[0].length;
    for (int r=0; r<R; r++){ mark(b, r, 0); mark(b, r, C-1); }
    for (int c=0; c<C; c++){ mark(b, 0, c); mark(b, R-1, c); }
    for (int r=0; r<R; r++) for (int c=0; c<C; c++){
        if (b[r][c] == 'O') b[r][c] = 'X';       // captured
        if (b[r][c] == '#') b[r][c] = 'O';       // safe
    }
}
private void mark(char[][] b, int r, int c){
    if (r<0||r>=b.length||c<0||c>=b[0].length||b[r][c] != 'O') return;
    b[r][c] = '#';
    mark(b, r-1, c); mark(b, r+1, c);
    mark(b, r, c-1); mark(b, r, c+1);
}

HARD DG8. Course Schedule II — Topological Sort (LC 210)

Problem: Same as Course Schedule, but return a valid order to take the courses. Empty array if impossible.

Intuition (postorder DFS = topological order)

Run DFS. When a node is fully finished (post-order, after all its children), prepend it to the result. Result is a valid topological order. If any cycle is detected, return empty.

public int[] findOrder(int n, int[][] prereq){
    List<List<Integer>> adj = new ArrayList<>();
    for (int i=0; i<n; i++) adj.add(new ArrayList<>());
    for (int[] p : prereq) adj.get(p[1]).add(p[0]);
    int[] state = new int[n];
    Deque<Integer> stack = new ArrayDeque<>();
    for (int i=0; i<n; i++)
        if (state[i] == 0 && !dfs(i, adj, state, stack)) return new int[0];
    int[] order = new int[n];
    for (int i=0; i<n; i++) order[i] = stack.pop();
    return order;
}
private boolean dfs(int u, List<List<Integer>> adj, int[] state, Deque<Integer> stack){
    state[u] = 1;
    for (int v : adj.get(u)){
        if (state[v] == 1) return false;       // cycle
        if (state[v] == 0 && !dfs(v, adj, state, stack)) return false;
    }
    state[u] = 2;
    stack.push(u);                            // 🔑 add when DONE — postorder
    return true;
}
Why postorder works: When you finish a node, every node that depends on it has either already been pushed or will be pushed later — meaning it'll appear above this one in the popped output. So pushing on finish + popping at the end gives a perfect topological order.
🧠 Alternative: Kahn's algorithm (BFS-based topo sort) 
// Compute indegrees, push all 0-indegree nodes, BFS, decrement indegrees.
public int[] findOrderKahn(int n, int[][] prereq){
    List<List<Integer>> adj = new ArrayList<>();
    for (int i=0; i<n; i++) adj.add(new ArrayList<>());
    int[] indeg = new int[n];
    for (int[] p : prereq){ adj.get(p[1]).add(p[0]); indeg[p[0]]++; }
    Queue<Integer> q = new LinkedList<>();
    for (int i=0; i<n; i++) if (indeg[i] == 0) q.add(i);
    int[] order = new int[n]; int i = 0;
    while(!q.isEmpty()){
        int u = q.poll();
        order[i++] = u;
        for (int v : adj.get(u)) if (--indeg[v] == 0) q.add(v);
    }
    return i == n ? order : new int[0];
}

HARD DG9. Word Search (LC 79)

Problem: Given a grid of letters and a target word, return true if the word can be spelled by walking through adjacent cells, never reusing a cell.

Intuition (DFS + backtracking)

From every cell that matches word[0], try DFS. Mark the cell visited (overwrite with a sentinel like '#'), recurse to find word[i+1], then unmark on the way back so other paths can reuse it.

public boolean exist(char[][] b, String word){
    for (int r=0; r<b.length; r++)
        for (int c=0; c<b[0].length; c++)
            if (go(b, r, c, word, 0)) return true;
    return false;
}
private boolean go(char[][] b, int r, int c, String w, int i){
    if (i == w.length()) return true;
    if (r<0||r>=b.length||c<0||c>=b[0].length||b[r][c] != w.charAt(i)) return false;
    char save = b[r][c];
    b[r][c] = '#';             // mark visited
    boolean ok = go(b,r-1,c,w,i+1) || go(b,r+1,c,w,i+1)
              || go(b,r,c-1,w,i+1) || go(b,r,c+1,w,i+1);
    b[r][c] = save;             // 🔑 backtrack
    return ok;
}
Why backtracking, not just visited? Different starting cells, or even different sub-paths, may need to reuse the same cell. The mark+unmark pattern keeps the visited state local to this exploration only.

HARD DG10. Critical Connections (Bridges) (LC 1192)

Problem: An undirected network. Find all "critical" edges — edges whose removal would disconnect the graph. (These are called bridges.)

Intuition (Tarjan's algorithm — fancy DFS)

During DFS, give each node two numbers:

  • disc[u] = the order in which we discovered u.
  • low[u] = the smallest disc reachable from u using its subtree + at most one back edge.

An edge u → v (where v is u's child in DFS) is a bridge iff low[v] > disc[u]. Translation: there's no way to get back from v's subtree to u or above without using that edge.

int timer = 0;
int[] disc, low;
List<List<Integer>> adj;
List<List<Integer>> bridges = new ArrayList<>();

public List<List<Integer>> criticalConnections(int n, List<List<Integer>> conn){
    adj = new ArrayList<>();
    for (int i=0; i<n; i++) adj.add(new ArrayList<>());
    for (List<Integer> e : conn){
        adj.get(e.get(0)).add(e.get(1));
        adj.get(e.get(1)).add(e.get(0));
    }
    disc = new int[n]; low = new int[n];
    Arrays.fill(disc, -1);
    dfs(0, -1);
    return bridges;
}
private void dfs(int u, int parent){
    disc[u] = low[u] = timer++;
    for (int v : adj.get(u)){
        if (v == parent) continue;        // don't go straight back
        if (disc[v] == -1){              // unvisited
            dfs(v, u);
            low[u] = Math.min(low[u], low[v]);
            if (low[v] > disc[u])         // no back edge over u→v ⇒ bridge
                bridges.add(List.of(u, v));
        } else {
            low[u] = Math.min(low[u], disc[v]);
        }
    }
}
Why this is the boss fight: Tarjan's bridge-finding shows up in cloud network reliability, distributed systems, and circuit design. If you can implement disc/low from scratch, you're ahead of most candidates.

The 4 patterns that solve 80% of graph problems

① Standard BFS (shortest path / level by level)

boolean[] visited = new boolean[n];
q.add(start); visited[start] = true;
int dist = 0;
while(!q.isEmpty()){
    int size = q.size();

        int u = q.poll();

    }

}
② Multi-source BFS (push all sources at start) 
Queue<int[]> q = new LinkedList<>();
for (every source s) { q.add(s); visited[s] = true; }

③ Recursive DFS for components / area / sinking 
void dfs(int u){
    if (visited[u]) return;
    visited[u] = true;
    // per-node work
    for (int v : adj.get(u)) dfs(v);
}
④ DFS with 3-color (cycle detection / topo) 
int[] state = new int[n];   // 0 white, 1 gray, 2 black
boolean dfs(int u){
    state[u] = 1;
    for (int v : adj.get(u)){
        if (state[v] == 1) return true;     // cycle
        if (state[v] == 0 && dfs(v)) return true;
    }
    state[u] = 2;
    return false;
}

Final mindset checklist

  1. What's a node? Sometimes it's not obvious (states, words, buses).
  2. What's an edge? When does node A connect to node B?
  3. Is the graph directed or undirected? Affects how you build adj and detect cycles.
  4. Is it weighted? If yes, BFS may be wrong — consider Dijkstra.
  5. Do I need shortest path, count, structure, or order? That picks BFS vs DFS vs topo.
  6. Test on disconnected graphs. Don't forget the outer for loop that starts a new traversal for every unvisited node.
  7. Where do I mark visited? On enqueue (BFS) or on entry (DFS). Never later.
