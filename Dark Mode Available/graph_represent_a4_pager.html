Reading the row. Left builds the grid, right takes it apart, and the two cards in a row are the same graph type. Only two things ever change: the value you store (1 or e[2]) and whether you touch two cells or one. Unweighted undirected? Use the mirror code with 1 in both cells, or switch to boolean[][] for less memory. ↑ top
All three types in one method. Once the pattern is clear you can fold the three cards on the left into a single method with two flags, which is what most library code does: m[e[0]][e[1]] = weighted ? e[2] : 1; then if (!directed) m[e[1]][e[0]] = weighted ? e[2] : 1; The reverse direction folds the same way: int start = directed ? 0 : u; as the inner loop's first value. Learn the three separately first, then join them, or a flag bug will look like a graph bug.

Q1. Edge → matrix reads only E edges, so why is the cost written O(V² + E)?
Reveal hint

Because new int[V][V] is not free. Java builds and zeroes V² cells before your loop starts. Here that is 25 cells of setup for 6 writes.

Q2. The undirected build writes m[u][v] and m[v][u]. What about a self loop, where u == v?
Reveal hint

Both lines hit the same cell, so the second write does no harm. The care is needed coming back: report a self loop once, so keep v = u in the scan but never mirror it.

static List<int[]> toEdges(List<List<int[]>> adj) {
    List<int[]> out = new ArrayList<>();
    for (int u = 0; u < adj.size(); u++)
        for (int[] nb : adj.get(u)) {
            if (nb[0] < u) continue;  // mirror copy

}

Why one empty list per node beats a map. A Map<Integer, List<Integer>> looks tidier, but every lookup hashes and boxes an Integer, and a node with no edges is simply missing from the map, so for (int u = 0; u < V; u++) then breaks on a null. A list indexed by node number has none of those problems, and node ids are already 0 .. V-1. Use a map only when node ids are strings or are far apart, like {7, 4000, 91234}.
Q3. An undirected graph has 6 edges and your adjacency list holds 12 entries. Is that a bug?
Reveal hint

No, that is correct: entries = 2E, because each link is stored on both nodes. The real bug would be an edge list with 12 rows — that means the nb[0] < u skip is missing.

Q4. Why is the adjacency list the default form for BFS, DFS and Dijkstra?
Reveal hint

Because for (int[] nb : adj.get(u)) touches only the real neighbours of u. A matrix has to test all V cells of row u, most of them 0. On a sparse graph that is O(V + E) against O(V²).

    int V = adj.size();
    int[][] m = new int[V][V];
    for (int u = 0; u < V; u++)
        for (int[] nb : adj.get(u))
            m[u][nb[0]] = nb[1];
    return m;
}

Round trip self check. To test any pair of these methods, convert one way, convert back, sort both edge lists, then compare: edges.sort((a, b) -> a[0] != b[0] ? a[0] - b[0] : a[1] - b[1]); Sorting matters because neighbour order changes with the form you came from. If the lists differ, the cause is almost always one of three things: a missing mirror, a mirror you forgot to skip, or a weight of 0 the matrix swallowed.
Q5. Which of the six conversions need no directed/undirected branch at all?
Reveal hint

The two on this sheet: matrix → list and list → matrix. Both forms already store the mirror. Only conversions that touch an edge list need a branch, because an edge list holds each link once: going out of one you add the mirror, coming into one you skip it.

Q6. Matrix → edge list on an undirected graph returns 12 rows. What is broken?
Reveal hint

The inner loop starts at v = 0 instead of v = u, so every edge is picked up from both of its cells. Start at v = u — keeping v = u so self loops still count once.

One line to remember. An edge list holds each link once; a matrix and an adjacency list hold an undirected link twice. So going out of an edge list you add the mirror, and coming into an edge list you skip it. Weighted against unweighted only changes what value you store: e[2] or 1.
