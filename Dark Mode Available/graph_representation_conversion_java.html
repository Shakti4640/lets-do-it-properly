How It Works

  
There are three ways to store the same graph. This tool shows how to turn any one of them into any other — six conversions in all. Pick a conversion, then press Play or step through with Next and Prev.


  
The three forms

  

    
FormWhat it holds

    
Edge ListA plain list of links: (u, v, w).

    
Adjacency ListOne list per node, holding that node's neighbors.

    
Adjacency MatrixA V×V grid. Cell m[u][v] holds the edge.

What the colors mean

  
    
    
  • The blue item on the left (a row, cell, or chip) is the source piece being read now.
    • 
    
  • The matching graph edge lights up blue too.
    • 
    
  • On the right, the output cell/chip/row pops when it gets written.
    • 
    
  • The highlighted code line is the exact line doing that step.
    • 
  


  
The three modes change the result: unweighted makes every weight 1, weighted keeps the real weight, and undirected stores each link both ways. When going back to an edge list from an undirected graph, the mirror copy is skipped so each link shows once.






  
Notes & Tips


  
Speed at a glance

  

    
StorageSpaceCheck edge (u,v)List neighbors

    
Edge ListO(E)O(E)O(E)

    
Adjacency ListO(V + E)O(degree of u)O(degree of u)

    
Adjacency MatrixO(V²)O(1)O(V)

  


  
Which to pick

  
    
    
  • Few edges (sparse) → adjacency list. The safe default.
    • 
    
  • Many edges (dense) or lots of "is u linked to v?" checks → adjacency matrix.
    • 
    
  • You only loop over all edges (like Kruskal's) → keep the edge list.
    • 
  


  
Matrix trap: if a real weight can be 0, do not use 0 to mean "no edge". Use a marker like Integer.MAX_VALUE instead.


  
The graph used

  
5 nodes (0–4) and 6 edges: (0,1,4), (0,2,2), (1,3,7), (2,3,1), (3,4,3), (4,2,5).
