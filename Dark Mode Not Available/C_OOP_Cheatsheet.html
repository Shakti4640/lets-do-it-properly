0. Primitive Types & Conversions

C has no universal base type, no autoboxing, and no type erasure. Integer types come in many widths; portability relies on <stdint.h>.

Core types (C11)

Remember: C has no built-in string type. A "string" is a char* you promise is NUL-terminated. Everything about strings (length, copy, compare) uses <string.h>.

Type promotion rules

  • Integer promotion: char, short, bool → int (or unsigned int) in every expression.
  • Usual arithmetic conversions: mixed types promote to the wider/higher-rank type. Mixed signed/unsigned of same rank → unsigned.
  • No automatic int → pointer: except 0 → NULL (a null-pointer constant).
  • Array → pointer decay: int a[10]; f(a); passes int*, not an array.

Q1. char c = 200; on a platform where char is signed — what's stored?
Reveal hint
Implementation-defined. Likely wraps to -56. Always use uint8_t when you need the value 0..255.
Q2. Why does if (-1 < 0u) print false?
Reveal hint
Mixed signed/unsigned → -1 is converted to unsigned (huge positive). Never compare signed & unsigned without a cast.
Q3. printf("%d\n", sizeof(int)); — safe?
Reveal hint
No. sizeof yields size_t, which doesn't match %d. Use %zu.

2. struct — the "Class with No Methods"

/* point.h */
#ifndef POINT_H
#define POINT_H

typedef struct Point {
    double x;
    double y;
} Point;

void point_init(Point* p, double x, double y);
double point_distance(const Point* a, const Point* b);

#endif
/* point.c */
#include "point.h"
#include <math.h>

void point_init(Point* p, double x, double y) {
    p->x = x;
    p->y = y;
}

double point_distance(const Point* a, const Point* b) {
    double dx = a->x - b->x, dy = a->y - b->y;
    return sqrt(dx*dx + dy*dy);
}
TopicWrongRight
Struct tag vs typedefMixing struct Point and Point inconsistently.Typedef once: typedef struct Point { ... } Point;.
Header guardIncluding a header twice without guard — redefinition errors.#ifndef/#define/#endif or #pragma once.
Zero-initRelying on garbage on the stack.Point p = {0}; or C99 designated init: Point p = {.x = 1.0};.
Passing structsPassing huge structs by value everywhere.Prefer const T*; pass by value only for small value types.
Padding/alignmentAssuming sizeof(T) == sum of member sizes.Compiler inserts padding. Use offsetof, not hand math.
Q. Does Point p; inside a function zero the fields?
Reveal hint
No — automatic storage is uninitialized. Use Point p = {0}; to zero all members.

3. "Constructors" & "Destructors"

C has no constructors. The idiom is a *_create / *_destroy pair, or *_init / *_dispose if the caller provides the storage.

/* Heap-owned object */
Cart* cart_create(int discount);
void  cart_destroy(Cart* c);

/* Caller-owned storage */
void  cart_init(Cart* c, int discount);
void  cart_dispose(Cart* c);
TopicWrongRight
Half-initialized on failurecreate partially builds, returns non-NULL.Clean up and return NULL on any failure mid-build.
Missing destroyCalling free(c) only, skipping cart_destroy.Destroy handles nested resources first, then free.
Ownership unclear"Who frees this?" lost in the API.Document in the header; name functions like *_take, *_borrow, *_clone.
Re-init without disposeCalling init on a live object → leaks inner allocations.Require dispose first, or make init safe on zero-initialized structs only.
double freeFreeing through two owners.After free, set the pointer to NULL; one owner only.
Q. Why set p = NULL; right after free(p);?
Reveal hint
Guarding against accidental reuse or double-free. free(NULL) is a no-op, but free on a freed pointer is UB.

4. "Access Control" via Translation Units

C has no public/private/protected. You control visibility with:

ToolEffect
Header (.h) declaresEverything that's public API.
static in a .c file"Private" — internal linkage, invisible outside the TU.
Opaque struct forward declarationCallers can hold a struct Cart* but can't access any fields.
Naming convention (_foo)Convention only — nothing stops the caller.
 
/* cart.h — public */
typedef struct Cart Cart;        // opaque!
Cart* cart_create(void);
void  cart_add(Cart* c, const char* item);
void  cart_destroy(Cart* c);

/* cart.c — private */
#include "cart.h"
struct Cart { char** items; size_t len; size_t cap; };  // hidden
static void grow(Cart* c) { /* internal helper */ }
Tip — anonymous helpers: any helper in a .c file that isn't in the header should be marked static. That's C's equivalent of private.
Q. What does static on a file-scope function mean?
Reveal hint
Internal linkage — the name is visible only in this translation unit. Unrelated to static inside a function (= persist across calls).

5. Encapsulation — Opaque Pointer Pattern

The strongest encapsulation C offers. Callers see only a forward-declared type; they cannot read or write fields.

/* account.h */
typedef struct Account Account;
Account*  account_create(double initial);
double    account_balance(const Account* a);
int       account_deposit(Account* a, double amount);   // 0 on success
void      account_destroy(Account* a);

/* account.c */
struct Account { double balance; };

Account* account_create(double initial) {
    if (initial < 0) return NULL;
    Account* a = malloc(sizeof *a);
    if (!a) return NULL;
    a->balance = initial;
    return a;
}
double account_balance(const Account* a) { return a->balance; }
int account_deposit(Account* a, double amount) {
    if (amount < 0) return -1;
    a->balance += amount; return 0;
}
void account_destroy(Account* a) { free(a); }
Benefits: layout is private, you can change it without breaking callers; invariants checked in accessors; compiler prevents field access from outside.
Q. An opaque Account* — can the caller sizeof(*a)?
Reveal hint
No. The type is incomplete in callers' TUs. That's the point — only account.c knows the size.

6. "Inheritance" via Struct Embedding

Put the "base" struct as the first member of the "derived" struct. Then a Derived* is safely convertible to a Base*.

typedef struct Animal { const char* name; int legs; } Animal;

typedef struct Dog {
    Animal base;               // must be first
    const char* breed;
} Dog;

void animal_print(const Animal* a) { printf("%s (%d legs)\n", a->name, a->legs); }

int main(void) {
    Dog d = { .base = { .name = "Rex", .legs = 4 }, .breed = "Lab" };
    animal_print(&d.base);                 // explicit upcast
    animal_print((Animal*)&d);              // same thing, first-member guarantee
    return 0;
}
TopicWrongRight
Base not firstEmbedding Animal as a non-first field — pointer cast is UB.Always place the "base" as the first member.
Downcast(Dog*)animal without checking.Tag the base with a discriminator and verify before cast — C has no RTTI.
Copy slicingAnimal a = *(Animal*)&dog; — drops derived fields.Pass pointers; copy only when you mean to copy the full derived struct.
Name collisionsTwo embedded bases with same-named fields.Access via explicit chain: d.base1.foo vs d.base2.foo.
Q. Why must the base struct be the first member?
Reveal hint
C guarantees a pointer to a struct points to its first member (no leading padding). That's the only guarantee that makes upcasting via a plain pointer cast legal.

7. Polymorphism — Function Pointers & Hand-Rolled vtable

The canonical C OOP pattern. A base struct carries a pointer to a vtable; each derived type fills in a vtable with its own implementations.

/* shape.h */
typedef struct Shape Shape;
typedef struct ShapeVTable {
    double (*area)(const Shape*);
    void   (*destroy)(Shape*);       // virtual destructor
} ShapeVTable;

struct Shape { const ShapeVTable* vt; };

static inline double shape_area(const Shape* s)   { return s->vt->area(s); }
static inline void   shape_destroy(Shape* s)     { s->vt->destroy(s); }

/* circle.c */
typedef struct Circle { Shape base; double r; } Circle;

static double circle_area(const Shape* s) {
    const Circle* c = (const Circle*)s;
    return 3.14159265 * c->r * c->r;
}
static void circle_destroy(Shape* s) { free(s); }

static const ShapeVTable CIRCLE_VT = { .area = circle_area, .destroy = circle_destroy };

Shape* circle_new(double r) {
    Circle* c = malloc(sizeof *c);
    if (!c) return NULL;
    c->base.vt = &CIRCLE_VT;
    c->r = r;
    return &c->base;
}
TopicWrongRight
NULL vtableForgot to wire vt → segfault at first call.Initialize vt in the factory, never in client code.
Per-instance vtableStoring a copy of the vtable in each object.Share one static const vtable per type — same idea as a C++ class vtable.
Signature driftTwo implementations accept different param types.Pin signatures in the header typedef.
Missing virtual destroyfree(shape) skips derived cleanup.Call shape_destroy(s) which dispatches to the derived destroy.
Thread safetyMutating shared vtables at runtime.Keep vtables const static.
Q. Each type has one vtable shared across all instances — why?
Reveal hint
Memory + cache efficiency. Per-instance copies waste space and invite bugs when one gets patched.

8. Abstraction — "Interfaces" via a vtable

An "interface" in C is just a struct of function pointers. Any implementation that fills it in qualifies.

typedef struct Writer {
    void (*write)(struct Writer* w, const char* s);
    void (*flush)(struct Writer* w);
    void (*close)(struct Writer* w);
} Writer;

/* File-backed implementation */
typedef struct FileWriter { Writer iface; FILE* fp; } FileWriter;
static void fw_write(Writer* w, const char* s) {
    fputs(s, ((FileWriter*)w)->fp);
}
Tip: keep "interfaces" small (2-3 functions). Bigger ones become a pain to implement — Interface Segregation matters in C too.

9. Pure-Interface vs Partial Base

AspectPure interface (all function pointers)Partial base (data + pointers)
StateNone in the base.Base may carry shared fields.
Multiple "inheritance"Easy — a struct may expose several interfaces via embedded anchors.Harder — only one base can be first.
Use whenPure capability contract.Shared behavior + virtual hooks (Template Method).
Q. You want one struct to implement two interfaces A and B. How?
Reveal hint
Embed both anchors as fields: struct X { A a_iface; B b_iface; /* data */ }; Provide adapter functions like x_as_a(X*) and x_as_b(X*).

10. Overloading — not supported

AspectCWorkarounds
By signatureNot allowed — one definition per name.Distinct names: vec_add_int, vec_add_float.
Generic dispatchNone built-in.C11 _Generic selects at compile time based on argument type (see section 22).
VariadicYes via <stdarg.h>Lose type safety. printf-style only; keep narrow.
Default argumentsNone.Wrapper function or macro that supplies a default.
 
#define MAX(a, b) _Generic((a), int: max_i, double: max_d)(a, b)
int    max_i(int    a, int    b) { return a > b ? a : b; }
double max_d(double a, double b) { return a > b ? a : b; }
Q. Can _Generic dispatch at runtime?
Reveal hint
No. It's a compile-time selection on the static type of the controlling expression. No vtable lookup.

11. static — three very different meanings

ContextMeaningAnalogy
static at file scope (function or global)Internal linkage — invisible outside this TU.Java private for a file.
static inside a functionStorage persists across calls; initialized once.A single "hidden" cache.
static in an array parameter: void f(int a[static 10])Promise that a has ≥ 10 elements.Array-size hint to the compiler.
 
int next_id(void) {
    static int id = 0;     // initialized once, persists between calls
    return ++id;
}
Q. What's the difference between static int counter = 0; inside a function vs at file scope?
Reveal hint
Inside a function: local name, persists across calls. At file scope: file-global name, but invisible from other TUs. Both use static storage.

12. const — what it actually locks

DeclarationWhat's const
const int* ppointed-to value (read right-to-left: pointer to const int).
int* const pthe pointer itself; the int can change.
const int* const pboth — fully read-only view.
int const * psame as const int* p — east-const style.
const int x = 42;Can't reassign. Still has an address.
Trick: read from right to left. const int* p → "p is a pointer to int that is const."
Q. Is char* p = "abc"; p[0] = 'A'; legal?
Reveal hint
No — undefined behavior. String literals are in read-only memory. Use char buf[] = "abc"; buf[0] = 'A'; or const char* p = "abc";.

13. "Self" reference & base-call

No this keyword — you pass the object explicitly, by convention first:

int cart_total(const Cart* self) { /* ... */ }

No super. To delegate to a base, call the base function directly on the embedded base pointer:

static void dog_print(const Animal* a) {
    animal_print_base(a);                      // "super" call
    const Dog* d = (const Dog*)a;
    printf("  breed: %s\n", d->breed);
}

14. Nested structs & callbacks

typedef struct Timer {
    struct {                     // nested, no name
        long sec;
        long nsec;
    } fired_at;
    void (*on_fire)(void* user);   // callback
    void* user;                  // opaque user data (C's "this" for closures)
} Timer;
Tip — "closures" in C: always pair a function pointer with a void* user context slot. Without it, callbacks can't carry state.

15. Equivalent of Object's equals/hashCode/toString

JavaC idiom
equalsint foo_equals(const Foo* a, const Foo* b); — returns 0/1.
compareToint foo_cmp(const void* a, const void* b); — qsort-compatible, returns <0, 0, >0.
hashCodeuint64_t foo_hash(const Foo* a); — e.g., FNV-1a or siphash.

Q. What should your compare function return when equal?
Reveal hint
Exactly 0. Non-zero signals "ordering known" to qsort/bsearch. Return a - b only when no overflow is possible.

16b. Is-a vs Has-a — Deep Dive (C examples)

In C, the distinction maps to:
• is-a → struct embedding + first-member rule + shared vtable.
• has-a → struct with a field (by value, by pointer, or an opaque owner).

Same-domain contrasts

ScenarioWrong ("is-a" abuse)Right ("has-a")
Stack of intsEmbedding a struct DynArray and leaking its whole API.struct IntStack { DynArray a; }; — only expose push/pop/peek.
Logged mapMaking struct LogMap embed HashMap and forwarding nothing.Wrap the map as an opaque field; provide the instrumented API only.
Square / RectangleEmbed Rectangle in Square, override setter via vtable — breaks invariants.Both implement a Shape interface; no inheritance between them.
Car / EngineEmbed Engine in Car "so Car inherits start()".struct Car { Engine engine; Wheel wheels[4]; };.
User / LoggerEmbed Logger in User to call user_log().struct User { Logger* log; }; (non-owning).
Order / list of itemsEmbed a LinkedList and expose everything.Opaque list as a member; expose order_add, order_total, etc.
Manager / EmployeeEmbed Employee in Manager — rigid as roles change.Person carries a set of role tags / role-structs.

Snippets — right way

/* Car HAS-A engine and wheels */
typedef struct Car {
    Engine  engine;              // composition
    Wheel   wheels[4];           // aggregation (fixed size)
    Logger* log;                 // non-owning pointer
} Car;
/* Dog IS-A Animal — first-member embedding */
typedef struct Dog {
    Animal base;                 // must be first
    const char* breed;
} Dog;

void handle(Animal* a);          // accepts a Dog via first-member guarantee
/* Decorator — IS-A Writer AND HAS-A Writer (legitimately both) */
typedef struct BufferedWriter {
    Writer  iface;               // is-a
    Writer* inner;               // has-a
    char    buf[4096];
    size_t  len;
} BufferedWriter;

Red flags you confused is-a with has-a

  • You embedded a struct just to reach a helper function — extract it as a free function instead.
  • Your "derived" struct overrides a virtual to do nothing or report an error — LSP broken; use composition.
  • You have a field that can be "detached" and make sense alone — it's has-a.
  • You copied a "derived" by value and got garbled fields — you sliced. Pass by pointer.
Q. Why can't you pass a Dog by value where an Animal is expected?
Reveal hint
C copies only sizeof(Animal) bytes — derived fields are lost. Pass Animal* (pointing at the first member of the Dog) instead.

17. Casting — no RTTI in C

CastUseRisk
(T)xExplicit numeric or pointer conversion.Silent data loss, UB on pointer type mismatch.
void* conversionsImplicit both ways in standard C (unlike C++).Don't overuse — type safety loss.
Downcast via first-member rule(Dog*)animal_ptr when you know it's a Dog.UB if it isn't. Add a type tag for safety.
Bit-punning*(float*)&iUB (strict aliasing). Use memcpy instead.
 
/* Safe type-tag for downcasts */
enum ShapeKind { K_CIRCLE, K_SQUARE };
struct Shape { enum ShapeKind kind; const ShapeVTable* vt; };
const Circle* as_circle(const Shape* s) {
    return s->kind == K_CIRCLE ? (const Circle*)s : NULL;
}
Q. Why use memcpy for bit-punning instead of a pointer cast?
Reveal hint
Strict aliasing. Accessing an object through a pointer of an incompatible type is UB (except char*). memcpy is the safe, optimized way.

19. Error handling — no exceptions

TopicWrongRight
Return codesReturning "-1 on error" for functions that legitimately return negatives.Separate return-code and out-parameter: int foo(Input, Output* out);.
errnoReading errno without setting it first.Set errno = 0; before call; check after if the function documents errno.
CleanupDuplicating cleanup at every error path.goto cleanup pattern, or RAII-like defer macros, or per-resource helper functions.
Swallowing errorsIgnoring return codes of malloc, fopen, fread.Check every allocation and I/O; propagate failure.

int load_config(const char* path, Config** out) {
    int rc = 0;
    FILE* fp = NULL;
    Config* cfg = NULL;

    fp = fopen(path, "rb");     if (!fp)  { rc = -1; goto done; }
    cfg = malloc(sizeof *cfg); if (!cfg) { rc = -2; goto done; }
    /* ... fill cfg ... */

    *out = cfg; cfg = NULL;         // transfer ownership
done:
    if (fp)  fclose(fp);
    if (cfg) free(cfg);
    return rc;
}
Q. Why is goto cleanup considered good C style?
Reveal hint
It's the closest C gets to RAII — one exit path, one cleanup block, no code duplication. Linus's kernel style recommends it.

20. SOLID in C

LetterC expression
S Single ResponsibilityOne TU per concern; one struct per concept; narrow public API per header.
O Open/ClosedExtend by providing a new implementation of an interface vtable. Avoid editing existing modules to add a case.
L Liskov SubstitutionEvery Shape* implementation must honor the contract of every method in the ShapeVTable.
I Interface SegregationPrefer small vtables (Writer, Reader) over one fat base with many hooks.
D Dependency InversionModules depend on vtable types, not concrete types. Pass a Writer*, not a FileWriter*.
Pro tip: the plain struct + vtable pattern is C's answer to DI and mocking. Tests can supply their own implementation without touching the production code.

21. Memory & RAII substitute

C has no destructors. Resource management is pattern + discipline.

Patterns

PatternUse
Single-owner functions*_create pairs with *_destroy. Ownership transferred by return value.
Arena / region allocatorAllocate many objects in a pool; free the whole pool at once.
Ref countAdd refcount to a struct; *_ref/*_unref. Destroy at 0.
Cleanup macro (GCC/Clang)__attribute__((cleanup(fn))) auto-calls fn when the variable goes out of scope. Closest thing to RAII.
goto cleanupSingle exit point, consolidated free/close.
 
/* GCC/Clang: scoped auto-cleanup */
static inline void fclose_p(FILE** fp) { if (*fp) fclose(*fp); }
#define AUTO_FILE __attribute__((cleanup(fclose_p)))

int read_header(const char* path) {
    AUTO_FILE FILE* fp = fopen(path, "rb");
    if (!fp) return -1;
    /* ...work... — fp is auto-closed on return */
    return 0;
}
TopicWrongRight
Mismatched alloc/freemalloc + delete (C++ mix).Pair malloc/free, calloc/free, realloc/free.
Use-after-freeKeeping a pointer after free.Set to NULL; never re-dereference.
Stack vs heap lifetimeReturning a pointer to a local array.Return via malloc or let the caller pass a buffer.
Overflow in mallocmalloc(n * sizeof(T)) when n is attacker-controlled.Overflow-check: if (n > SIZE_MAX / sizeof(T)) ….
Leaks in error pathsEvery branch frees a different subset.Single cleanup: label; free everything unconditionally at the end.
Q. How can C code approximate C++'s RAII?
Reveal hint
GCC/Clang __attribute__((cleanup(fn))) calls a cleanup function when the variable leaves scope. Portable fallback: goto cleanup.

#define SWAP(a, b) \
    do { typeof(a) _t = (a); (a) = (b); (b) = _t; } while (0)   // GCC/Clang

Q. Why is #define MAX(a,b) a > b ? a : b buggy?
Reveal hint
Operator precedence and double evaluation: MAX(i++, j) increments i twice. Wrap arguments in parens and use a statement expression or __typeof__.
