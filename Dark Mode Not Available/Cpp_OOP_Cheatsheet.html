Type promotion rules (integral)

  • bool, char, short → promoted to int in arithmetic (integral promotion).
  • Mixed signed/unsigned of the same rank → converted to unsigned (classic source of bugs).
  • Integer + float → integer converted to the float type.
  • Narrowing (e.g., double→int) requires an explicit cast in brace-init; is silent in parens/copy-init.
Q1. char a = -1; unsigned char b = 255; a == b — what's the result?
Reveal hint
Both get promoted to int. a becomes -1, b becomes 255. -1 == 255 → false. Integral promotion doesn't mask different signedness.
Q2. std::vector<int> v(10, 5); vs std::vector<int> v{10, 5};.
Reveal hint
Parentheses call the (count, value) constructor → 10 elements all 5. Braces call the initializer_list constructor → 2 elements: 10 and 5.
Q3. Why is 0u - 1 > 0?
Reveal hint
Unsigned arithmetic wraps: 0u - 1 is UINT_MAX, which is positive. Mixing signed and unsigned is a common bug.

1. The Four OOP Pillars — Overview

PillarOne-line ideaKey C++ hookSmell if misused

C++ twist: polymorphism is opt-in. Without virtual, calls bind statically. The compiler won't warn when slicing occurs — you have to use pointers or references to get dynamic dispatch.
Q. You wrote Base b = getDerived(); — what happened?
Reveal hint
Object slicing: the Derived-specific bytes were discarded. Only the Base part was copied. Use Base& or Base* / std::unique_ptr<Base> to preserve the real type.

3. Constructors & Destructors

RuleWrongRight
Single-arg ctorWidget w = 42; silently converts.Mark it explicit unless implicit conversion is a feature.
Base dtorNon-virtual destructor in a polymorphic base.virtual ~Base() = default; — otherwise delete base is UB.
Delegating ctorCalling another ctor from the body.Use the initializer-list form: Foo(int x): Foo{x, 0} {}.

class File {
    std::FILE* fp_{nullptr};
public:
    explicit File(const std::string& path) : fp_{std::fopen(path.c_str(), "rb")} {
        if (!fp_) throw std::runtime_error{"cannot open"};
    }
    ~File() { if (fp_) std::fclose(fp_); }        // RAII
    File(const File&) = delete;                     // non-copyable
    File& operator=(const File&) = delete;
    File(File&& o) noexcept : fp_{o.fp_} { o.fp_ = nullptr; }  // movable
    File& operator=(File&& o) noexcept { std::swap(fp_, o.fp_); return *this; }
};
Q. Why is a virtual destructor required when you delete through a Base pointer?
Reveal hint
Without virtual, only ~Base() runs; derived members leak and are UB. A single virtual ~Base() = default; fixes it.

Q. Base* p = new Derived; in another translation unit — can it call a protected method of Base?
Reveal hint
No. Cross-package-style rule applies even within C++: protected access requires the reference type to be the own derived type (or a subtype), not the Base type.

7. Polymorphism & virtual

TopicWrongRight
Virtual dispatchCalling through a value: Base b = d; b.foo();Call through reference or pointer: Base& r = d; r.foo();
Override intentAdding a new method that you thought overrode.Use the override specifier — the compiler checks you.
Default argumentsDifferent defaults in base & derived virtual.Defaults are chosen by static type; runtime dispatch still uses the derived body. Confusing — avoid changing defaults.

struct Animal {
    virtual ~Animal() = default;
    virtual std::string speak() const = 0;        // pure virtual
};
struct Dog : Animal {
    std::string speak() const override { return "woof"; }
};
void call(const Animal& a) { std::cout << a.speak(); }
Q. What does final on a virtual method do?
Reveal hint
Prevents further overriding. Also lets the compiler devirtualize calls through the exact class, sometimes yielding a speedup.

TopicWrongRight

struct Shape {
    virtual ~Shape() = default;
    virtual double area() const = 0;
    virtual std::string name() const = 0;
};
struct Circle : Shape {
    double r_;
    explicit Circle(double r) : r_{r} {}
    double area() const override { return 3.14159265 * r_ * r_; }
    std::string name() const override { return "circle"; }
};

9. Abstract Class vs "Interface"

C++ has no dedicated interface keyword. An "interface" is just an abstract class with only pure virtuals, no data, and a virtual destructor.

AspectAbstract class (with state)Pure interface
State/data membersAllowed.None.
Multiple inheritanceOne is typical; avoid the diamond of state.Combine many freely — they carry no state.
Virtual dtorRequired.Required.
Use whenShared partial implementation ("Template Method").Pure contract ("can-do").
Tip — diamond of state: if two paths bring the same base, use virtual inheritance so there's a single shared sub-object. Otherwise you have two copies — a common crash source.

Q. You removed virtual from a method but kept override. What happens?
Reveal hint
Compile error. override requires the method to actually override a virtual. That's exactly why you mark it — it catches typos and signature mismatches.

15. Rule of 0 / 3 / 5 & Special Members

The compiler can synthesize six special members: default ctor, dtor, copy ctor, copy assign, move ctor, move assign. Choose one discipline:

RuleWhenWhat
Rule of 0You manage no raw resources.Write none. Compiler defaults are correct.
Rule of 3You manage a resource manually.Define dtor, copy ctor, copy assign consistently.
Rule of 5You manage a resource + want move.Define all five (plus dtor).
Delete instead of defineNon-copyable / non-movable types.= delete the ones you want gone.
Copy-and-swap idiom: write a strong-exception-safe copy assignment in one line using swap:
T& operator=(T rhs) { swap(*this, rhs); return *this; }

Self-check for deep copy

TopicWrongRight
Raw pointer memberDefault copy gives you two owners of the same memory → double free.Custom copy or (better) switch to std::unique_ptr/std::shared_ptr.
Move semanticsThrowing from move ctor/assign.Mark them noexcept; containers use them more efficiently.
Copy assign self-checkSkipping if (this == &other) return *this; when it matters.Use copy-and-swap or ensure safe on self-assignment.
Q. You add a std::unique_ptr member to an otherwise default class. What do you need to write?
Reveal hint
Nothing — Rule of 0. unique_ptr is non-copyable and move-only, and the compiler propagates that. Just don't write incompatible copy members.

16b. Is-a vs Has-a — Deep Dive (C++ examples)

Same test: if every X is a Y in every context, it's is-a. Otherwise it's has-a. In C++, failure to distinguish them is a major source of slicing, dangling references, and vtable confusion.

Same-domain contrasts

Red flags you confused is-a with has-a

  • Subclass's override is "do nothing" or throws std::logic_error.
  • You subclass std::vector / std::string — both have non-virtual destructors.
  • Base has 15+ public functions, but your derived only uses two.
  • Your design needs you to "undo" an inherited public method for derived classes.
  • You pass derived by value and are surprised by slicing.
Q1. Why is class MyVec : public std::vector<int> a bad idea?
Reveal hint
Non-virtual destructor in std::vector: delete through a base pointer is UB. Also, MyVec inherits the entire 40-method API which is now its contract.
Q2. Penguin is a Bird but doesn't fly. Where does fly() go?
Reveal hint
Not on Bird. Declare a separate abstract interface Flyable; let Sparrow implement both Bird and Flyable; Penguin only implements Bird (and perhaps Swimmable).
Q3. Composition vs aggregation for Order::items?
Reveal hint
Composition — items die with the order. Aggregation is when the part outlives the whole (shared references, weak_ptr).

17. Casting & RTTI

Q. Can dynamic_cast work on a class with no virtual methods?
Reveal hint
No. Runtime polymorphism needs a vtable, which requires at least one virtual method (typically the destructor).

18. Immutability & constexpr

RequirementHow

class Point {

    constexpr Point(double x, double y) noexcept : x_{x}, y_{y} {}

Q. Does const imply constexpr?
Reveal hint
No. const means "not modifiable after init"; constexpr means "the value can be used at compile time". A const initialized from a non-constant is a runtime constant only.

19. Exceptions (OOP angle)

TopicWrongRight
Throwing from dtorLetting an exception escape ~T().Destructors are implicitly noexcept. Wrap/log and swallow; never propagate.
Catch-allcatch (...) that swallows silently.Catch narrowest first; rethrow with throw; if not handled.
Catch by valuecatch (std::exception e) — slices.catch (const std::exception& e).
Exception hierarchyDeriving from std::string.Derive from std::exception or its subclasses (runtime_error, logic_error).
Resource leaksManual new/delete with potential throws in between.RAII + smart pointers (Section 21).

Exception safety levels

  1. No-throw: the operation cannot throw (noexcept).
  2. Strong: either succeeds, or leaves the program as if untouched.
  3. Basic: invariants hold, no leaks, but state may change.
  4. None: all bets are off (avoid).
Q. Why must a move constructor be marked noexcept when possible?
Reveal hint
Containers like std::vector use moves during reallocation only if they're noexcept; otherwise they fall back to copies for strong exception safety. Missing noexcept = silent performance regression.

21. Smart Pointers & RAII

TypeOwnershipWhen
std::unique_ptr<T>Single owner; move-only.Default for dynamically-allocated objects.
std::shared_ptr<T>Shared (ref-counted).When lifetime truly spans multiple owners.
std::weak_ptr<T>Non-owning observer of shared.Breaks reference cycles in shared ownership graphs.
Raw T* / T&Non-owning.Use as parameters when ownership isn't transferred.

RAII rules

  • Every resource (memory, file, socket, lock, GPU buffer) has exactly one owner object.
  • Acquisition happens in the ctor; release in the dtor.
  • Never call raw new/delete. Use std::make_unique<T> / std::make_shared<T>.
  • For locks, use std::lock_guard / std::scoped_lock / std::unique_lock.
auto p = std::make_unique<File>("x.bin");  // one owner
std::shared_ptr<Node> parent = std::make_shared<Node>();
std::weak_ptr<Node> child_to_parent = parent;       // break cycle
Q. Two shared_ptrs pointing at each other — leak or not?
Reveal hint
Leak. Ref counts never reach zero. One side must be a weak_ptr to break the cycle.

22. Templates & Concepts — the OOP angle

Templates are C++'s "generic programming" mechanism. Paired with C++20 concepts, they let you express contracts that act like interfaces but resolve at compile time.

template<class T>
concept Printable = requires(const T& t) { { std::cout << t } -> std::same_as<std::ostream&>; };

template<Printable T>
void print_all(const std::vector<T>& v) {
    for (const auto& x : v) std::cout << x << '\n';
}

Static polymorphism via CRTP

template<class Derived>
struct Printable {
    void print() const { static_cast<const Derived*>(this)->do_print(); }
};
struct Widget : Printable<Widget> {
    void do_print() const { std::cout << "widget"; }
};
Tip: pick virtual when you need open-ended extensibility at runtime, templates/concepts when the set of types is known at compile time and you want zero overhead.
Q. CRTP gives you polymorphism without virtual calls. What's the trade-off?
Reveal hint
All uses must know the exact derived type at compile time; you can't put different CRTP instantiations in a single container without erasing to a common base.
