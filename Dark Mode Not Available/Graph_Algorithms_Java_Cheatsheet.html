Foundations 1. Terminology & Types of Graphs

OBJECTIVE Build the vocabulary needed to describe every algorithm that follows, and recognize which graph family a problem belongs to.
WHY Half the difficulty of graph problems is translating a story ("courses with prerequisites", "cities with flights") into the right abstract graph. The wrong abstraction forces the wrong algorithm and the wrong complexity.
HOW For any input, answer four questions first: directed? weighted? cyclic? connected? These four bits pick the algorithm family before you write a line of code.
THEORY
  • Graph G = (V, E): V is a finite set of vertices, E ⊆ V×V a set of edges.
  • Handshake lemma (undirected): Σ deg(v) = 2|E| ⇒ the number of odd-degree vertices is always even.
  • Tree ⇔ connected and |E| = |V| − 1 ⇔ connected and acyclic ⇔ unique simple path between any two vertices.
  • DAG: directed graph with no directed cycle. A DAG always admits a topological order.
  • Bipartite: V splits into two sets with every edge crossing ⇔ no odd cycle ⇔ 2-colorable.
  • Sparse: E ≈ V; Dense: E ≈ V². Drives representation and algorithm choice.

Graph types you'll meet

Trick: if the problem says reach, path, cycle, depend, order, match, level, distance, flow, or component — model it as a graph before writing any loop.
Tip: "connected" means different things for directed vs undirected. Directed has strong (both ways) and weak (ignoring direction) connectivity.
Hint: handshake lemma gives you the parity argument you'll need for every Eulerian / bipartite problem.
Watch out: self-loops add 2 to a vertex's undirected degree, not 1.
Q. Maximum number of edges in a simple undirected graph on n vertices?
Reveal hint
C(n,2) = n(n−1)/2. This is why adjacency matrices are Θ(V²) worst case.
Q. Can a graph have an odd number of odd-degree vertices?
Reveal hint
No — handshake lemma forces it to be even.

Representation 2. Graph Representations in Java

OBJECTIVE Store a graph in memory so the algorithm you'll run later is efficient in both space and time.
WHY The wrong representation can silently turn O(V+E) into O(V²) — or blow up memory on sparse graphs. The choice is almost always dictated by density (E vs V²) and which queries you run most.
HOW
  • Adjacency list (default): List<List<Integer>> or List<List<Edge>>. Θ(V + E) space.
  • Adjacency matrix: int[V][V]. Θ(V²) space. Great for dense graphs or when you need O(1) "is edge present?".
  • Edge list: List<int[]> of {u, v, w}. Perfect for Kruskal and Bellman-Ford.
THEORY
AspectMatrixListEdge list
SpaceΘ(V²)Θ(V + E)Θ(E)
Is (u,v) an edge?O(1)O(deg(u))O(E)
Iterate neighbors of uO(V)O(deg(u))O(E)
Remove edgeO(1)O(deg(u))O(E)
Best algorithmsFloyd-Warshall, dense Prim.DFS, BFS, Dijkstra.Kruskal, Bellman-Ford.

Adjacency list — unweighted

int n = 6;
List<List<Integer>> adj = new ArrayList<>();
for (int i = 0; i < n; i++) adj.add(new ArrayList<>());

void addEdge(int u, int v) {
    adj.get(u).add(v);
    adj.get(v).add(u);   // drop this line for directed graphs
}

Adjacency list — weighted

record Edge(int to, int w) {}

List<List<Edge>> g = new ArrayList<>();
for (int i = 0; i < n; i++) g.add(new ArrayList<>());

void addW(int u, int v, int w) {
    g.get(u).add(new Edge(v, w));
}

Adjacency matrix

int[][] m = new int[n][n];    // 0 = no edge, or use INF for weighted

void addEdge(int u, int v, int w) {
    m[u][v] = w;
    m[v][u] = w;                // undirected only
}
Tip — rule of thumb: if E ≤ V log V, use adjacency list. If E ≈ V², matrix can actually be faster in practice due to cache locality.
Trick — 0-indexed vertices: always. Use −1 as the "no parent" sentinel to avoid off-by-ones.
Watch out: for undirected graphs, forgetting to add the reverse edge is the #1 bug in BFS/DFS assignments.
Hint: V=10⁵, E=10⁶ → matrix would need ~40 GB; list needs ~10⁶ entries. Pick list.

Traversal 3. Depth-First Search (DFS)

OBJECTIVE Visit every reachable vertex from a source by diving as deep as possible before backtracking.
WHY DFS exposes structural properties of the graph almost for free: connected components, cycles (back edges), topological order (post-order), articulation points, bridges, SCCs — all fall out of a single traversal with the right bookkeeping.
HOW
  • Maintain a visited[] array.
  • Recursive (implicit stack) or iterative (explicit Deque) — iterative version avoids stack-overflow on huge graphs.
  • For undirected graphs pass the parent to skip trivial 2-cycles; for directed graphs use a 3-color scheme to find back edges.
THEORY
  • DFS tree: the edges actually traversed. Non-tree edges fall into back, forward, or cross categories.
  • Back edge (u → ancestor) ⇔ cycle in the graph.
  • Post-order: the order in which DFS finishes vertices. Reversed post-order = topological order on a DAG.
  • 3-color method: WHITE unvisited, GRAY on current stack, BLACK finished. A GRAY→GRAY edge is a back edge.
COMPLEXITY Time O(V + E) on adjacency list, O(V²) on matrix. Space O(V) for visited plus recursion stack (up to O(V)).

Recursive DFS

boolean[] visited = new boolean[n];

void dfs(int u) {
    visited[u] = true;
    // pre-order work here
    for (int v : adj.get(u))
        if (!visited[v]) dfs(v);
    // post-order work here
}

for (int i = 0; i < n; i++)
    if (!visited[i]) dfs(i);    // covers every connected component

Iterative DFS (safe for huge graphs)

Deque<Integer> stack = new ArrayDeque<>();
stack.push(start);
visited[start] = true;

while (!stack.isEmpty()) {
    int u = stack.pop();
    for (int v : adj.get(u))
        if (!visited[v]) {
            visited[v] = true;
            stack.push(v);
        }
}

Cycle detection in a directed graph (3-color)

int[] color = new int[n];           // 0=WHITE, 1=GRAY, 2=BLACK
boolean hasCycle = false;

void dfs(int u) {
    color[u] = 1;
    for (int v : adj.get(u)) {
        if (color[v] == 1) { hasCycle = true; return; }
        if (color[v] == 0) { dfs(v); if (hasCycle) return; }
    }
    color[u] = 2;
}
Tip — undirected cycle detection: pass the parent: dfs(v, u) and skip v == parent. A visited non-parent neighbor means cycle.
Trick — free topological order: append u to a list in post-order, then reverse. No separate Kahn pass needed.
Hint — stack safety: Java's default stack is ~512KB. For V > ~10⁵ prefer iterative DFS, or launch it on a new Thread(null, task, "dfs", 16*1024*1024).
Watch out: on undirected graphs, forgetting the parent check makes every edge look like a cycle.
Q. Which DFS traversal order do you push to the topological-sort stack?
Reveal hint
Post-order (push when the DFS of the vertex finishes). Reversed post-order is a valid topological ordering of a DAG.

Traversal 4. Breadth-First Search (BFS)

OBJECTIVE Explore the graph layer by layer from a source, giving you the minimum number of edges to every reachable vertex.
WHY In an unweighted graph, BFS is the shortest-path algorithm. It's also the natural choice for bipartite checks (alternate layer colors), level-order processing, and "distance to nearest X" via multi-source BFS.
HOW
  • FIFO ArrayDeque.
  • Mark as visited on enqueue, not on dequeue.
  • For paths, keep a parent[].
THEORY
  • BFS visits vertices in non-decreasing distance order from the source.
  • The first time a vertex is dequeued, its distance is minimal.
  • BFS tree: edges that first reached each vertex — gives one valid shortest-path tree.
COMPLEXITY Time O(V + E), space O(V).

Template

int[] dist = new int[n];
Arrays.fill(dist, -1);
Deque<Integer> q = new ArrayDeque<>();
q.offer(src);
dist[src] = 0;

while (!q.isEmpty()) {
    int u = q.poll();
    for (int v : adj.get(u))
        if (dist[v] == -1) {
            dist[v] = dist[u] + 1;
            q.offer(v);
        }
}

Bipartite check

int[] color = new int[n];
Arrays.fill(color, -1);

for (int s = 0; s < n; s++) if (color[s] == -1) {
    Deque<Integer> q = new ArrayDeque<>();
    q.offer(s); color[s] = 0;
    while (!q.isEmpty()) {
        int u = q.poll();
        for (int v : adj.get(u)) {
            if (color[v] == -1) { color[v] = 1 - color[u]; q.offer(v); }
            else if (color[v] == color[u]) return false;   // odd cycle
        }
    }
}
return true;
Trick — Multi-source BFS: seed the queue with every source at distance 0. One pass answers "distance to the nearest source" for every cell. Classic for "rotting oranges", "nearest fire", "walls and gates".
Trick — 0/1 BFS: if weights are only 0 or 1, use ArrayDeque: push-front for 0-weight edges, push-back for 1-weight edges. Still O(V + E) and beats Dijkstra for this case.
Tip: mark on enqueue, not dequeue — otherwise the same vertex gets pushed many times and correctness breaks.
Watch out: BFS gives shortest paths only when all edge weights are equal. Use Dijkstra otherwise.
Hint — path reconstruction: keep parent[v] and walk backwards from t, then reverse.
Q. Why is BFS wrong on a weighted graph with positive weights?
Reveal hint
BFS assumes every edge costs 1. A path with more hops but small weights can be cheaper than a direct heavy-weight edge — Dijkstra needed.

Traversal 5. DFS/BFS on Implicit Graphs (Grids)

OBJECTIVE Run graph algorithms on inputs that aren't stored as a graph — grids, state spaces, puzzles.
WHY Building an explicit adjacency list from an m×n grid would waste memory and time. Neighbors are computed on the fly from row/column deltas.
HOW
  • Four delta arrays DR/DC for up/down/left/right; eight deltas for king moves.
  • Bounds-check first, then content-check (walls, visited).
  • Encode (r,c) as r*cols + c when you need HashMap keys or a flat visited array.
THEORY Every cell is a vertex; each valid move is an edge. BFS still gives shortest paths (min moves), DFS still finds components (islands, regions).
COMPLEXITY Time O(m · n), space O(m · n).

Grid BFS template

static final int[] DR = { -1, 1, 0, 0 };
static final int[] DC = { 0, 0, -1, 1 };

void bfs(int[][] grid, int sr, int sc) {
    int rows = grid.length, cols = grid[0].length;
    boolean[][] seen = new boolean[rows][cols];

    Deque<int[]> q = new ArrayDeque<>();
    q.offer(new int[] { sr, sc });
    seen[sr][sc] = true;

    while (!q.isEmpty()) {
        int[] p = q.poll();
        for (int d = 0; d < 4; d++) {
            int nr = p[0] + DR[d];
            int nc = p[1] + DC[d];
            if (nr < 0 || nr >= rows || nc < 0 || nc >= cols) continue;
            if (seen[nr][nc] || grid[nr][nc] == WALL) continue;
            seen[nr][nc] = true;
            q.offer(new int[] { nr, nc });
        }
    }
}
Trick: encode (r,c) as r*cols + c. Makes it easy to use with HashSet<Integer> or int[]-backed visited.
Tip: bounds-check before content-check — the opposite order throws ArrayIndexOutOfBoundsException.
Hint: 8-directional moves? Use deltas {-1,-1,-1,0,0,1,1,1} and {-1,0,1,-1,1,-1,0,1}. Knight moves? Two delta arrays of length 8 with ±1/±2 pairs.
Watch out: recursive flood fill on a 10⁴×10⁴ grid blows the stack. Use BFS or union-find.
Q. You need the minimum steps for a knight to reach (r,c). Which traversal?
Reveal hint
BFS (edges are unit weight). Use 8 knight deltas; you get the answer on first dequeue of the target.

Topological Sort 6. Topological Sort — DFS based

OBJECTIVE Produce a linear ordering of a DAG's vertices such that every edge u→v has u before v.
WHY It's the model for dependencies: course prerequisites, build orders, recipe steps, task schedules. Many DAG algorithms (shortest/longest path, DP) need the vertices visited in topological order to work in linear time.
HOW Run DFS; when a vertex finishes (post-order), push it on a stack. Reverse the stack — that's a topological order. Use 3-color coloring simultaneously to detect a cycle (no topo order exists on a cyclic graph).
THEORY
  • A topological order exists ⇔ graph is a DAG.
  • In general it's not unique — independent chains have any relative order.
  • Reverse post-order of a DFS on a DAG is always a valid topological order.
COMPLEXITY Time O(V + E), space O(V).
List<Integer> order = new ArrayList<>();
int[] color = new int[n];
boolean hasCycle = false;

void dfs(int u) {
    color[u] = 1;
    for (int v : adj.get(u)) {
        if (color[v] == 1) { hasCycle = true; return; }
        if (color[v] == 0) { dfs(v); if (hasCycle) return; }
    }
    color[u] = 2;
    order.add(u);                       // post-order
}

for (int i = 0; i < n; i++)
    if (color[i] == 0) dfs(i);

Collections.reverse(order);              // topological order
Trick: cycle detection comes free — a gray neighbor during DFS is a back edge = cycle = no topo order.
Watch out: for V > ~10⁵ the DFS may overflow — switch to Kahn's iterative version below.

Topological Sort 7. Topological Sort — Kahn's (BFS based)

OBJECTIVE Same output as section 6 but using an iterative queue-driven approach.
WHY No recursion, so no stack-overflow risk. Naturally gives you cycle detection if the output doesn't cover all V vertices. Easy to tweak into lex-smallest topo order by swapping the queue for a heap.
HOW
  1. Compute in-degrees.
  2. Enqueue all 0-in-degree vertices.
  3. Pop one, append to output, decrement in-degrees of its out-neighbors; enqueue any that hit 0.
  4. Cycle iff order.size() < n.
THEORY The algorithm repeatedly removes a "source" (a vertex with no incoming edges) from the DAG. A DAG always has at least one source; running out of sources before exhausting V means the remaining subgraph has a cycle.
COMPLEXITY Time O(V + E), space O(V).
int[] in = new int[n];
for (int u = 0; u < n; u++)
    for (int v : adj.get(u)) in[v]++;

Deque<Integer> q = new ArrayDeque<>();
for (int i = 0; i < n; i++) if (in[i] == 0) q.offer(i);

List<Integer> order = new ArrayList<>();
while (!q.isEmpty()) {
    int u = q.poll();
    order.add(u);
    for (int v : adj.get(u))
        if (--in[v] == 0) q.offer(v);
}
boolean hasCycle = (order.size() != n);
Trick — lexicographically smallest topo order: replace ArrayDeque with PriorityQueue<Integer>. Each pop picks the smallest available vertex.
Hint — "Find all possible recipes": recipes depend on ingredients. Model ingredients/recipes as a DAG; run Kahn starting from pantry items. Any recipe you dequeue is cookable.
Tip: Kahn scales to V = 10⁶ easily, while recursive DFS won't without stack tuning.
Watch out: always rebuild in[] from the full adjacency list before starting.
Q. Cycle detection in a directed graph with V = 10⁶ — Kahn or DFS?
Reveal hint
Kahn. It's iterative, O(V + E), and flags a cycle when the output misses any vertex.

Shortest Path 8. Shortest Path — Overview

OBJECTIVE Given a graph and a source, find the minimum-cost path to one or all destinations.
WHY This is the single most common graph problem in practice — routing, networking, game AI, logistics. Getting the right algorithm is half the work.
HOW Pick by graph properties:
VariantBest algorithmTimeHandles negatives?
Unweighted, one sourceBFSO(V + E)n/a
Weighted DAG, one sourceTopo sort + relaxO(V + E)Yes
Non-negative weights, one sourceDijkstraO((V + E) log V)No
Any weights, one sourceBellman-FordO(V · E)Yes, detects neg cycles
All pairs, denseFloyd-WarshallO(V³)Yes (no neg cycles)
All pairs, sparseJohnsonO(V · E + V² log V)Yes
Heuristic-guidedA*VariesNo (usually)
THEORY — Relaxation Every shortest-path algorithm is built on one primitive: 
if (dist[u] + w(u, v) < dist[v]) {
    dist[v] = dist[u] + w(u, v);
    parent[v] = u;
}
The algorithms differ only in the order in which edges are relaxed.
Tip — decision tree: unweighted → BFS. DAG → Topo + relax. Non-negative → Dijkstra. Negative edges → Bellman-Ford. All-pairs dense → Floyd. All-pairs sparse → Johnson.

Shortest Path 9. BFS Shortest Path (Unweighted Graphs)

OBJECTIVE Compute shortest-path distances (and paths) in an unweighted graph from a single source.
WHY BFS is faster and simpler than Dijkstra when all edges cost the same — no heap needed.
HOW Run BFS (Section 4) while maintaining parent[]; reconstruct the path by walking parents back from the target.
THEORY Since BFS dequeues in non-decreasing distance order, the first time a vertex is reached, that distance is minimal.
COMPLEXITY O(V + E) time, O(V) memory.
List<Integer> reconstructPath(int s, int t, int[] parent) {
    if (parent[t] == -1 && s != t) return List.of();
    List<Integer> p = new ArrayList<>();
    for (int v = t; v != -1; v = parent[v]) p.add(v);
    Collections.reverse(p);
    return p;
}
Hint: if all edges have the same positive weight w, multiply the BFS layer index by w for the real distance.

Shortest Path 10. DAG Shortest Path (Topo + Relax)

OBJECTIVE Compute shortest-path distances from a source in a weighted DAG, including with negative edges.
WHY A DAG guarantees no cycles, so each vertex is relaxed exactly once if we process in topological order. Result: linear time, beating Dijkstra, and handling negative weights.
HOW Topological sort, then relax all outgoing edges of each vertex in that order.
THEORY In topological order, every predecessor of u has already had its final distance fixed, so dist[u] is final when we relax u's out-edges.
COMPLEXITY O(V + E).
long[] dist = new long[n];
Arrays.fill(dist, Long.MAX_VALUE);
dist[src] = 0;

for (int u : topoOrder) {
    if (dist[u] == Long.MAX_VALUE) continue;        // unreachable, don't relax
    for (Edge e : g.get(u)) {
        if (dist[u] + e.w() < dist[e.to()])
            dist[e.to()] = dist[u] + e.w();
    }
}
Trick — longest path in a DAG: same algorithm with max instead of min (or negate weights and run shortest path). Longest path is NP-hard in general but polynomial on DAGs.
Watch out: guard dist[u] == INF before adding a weight — otherwise INF + w overflows.

Shortest Path 11. Dijkstra's Algorithm

OBJECTIVE Single-source shortest paths in a graph with non-negative weights.
WHY It's the practical answer for road networks, network routing, game maps — anywhere you have positive costs and need fast single-source distances.
HOW Greedy: always extract the next vertex with the smallest tentative distance from a priority queue; relax its out-edges; push improved neighbors back in.
THEORY
  • Invariant: when a vertex is extracted from the PQ, dist[u] is final.
  • Proof rests on non-negativity: any later path cannot undercut dist[u].
  • Fails on negative edges because a later relaxation could beat a "settled" distance.
COMPLEXITY
Priority queueTimeWhen it wins
Array / linear scanO(V² + E)Dense graphs.
Binary heap (Java PQ)O((V + E) log V)Default for sparse graphs.
Fibonacci heapO(E + V log V)Theoretical; rarely worth it in practice.
 
long[] dist = new long[n];
int[] parent = new int[n];
Arrays.fill(dist, Long.MAX_VALUE);
Arrays.fill(parent, -1);
dist[src] = 0;

PriorityQueue<long[]> pq = new PriorityQueue<>(
    Comparator.comparingLong(a -> a[0]));
pq.offer(new long[] { 0, src });

while (!pq.isEmpty()) {
    long[] cur = pq.poll();
    long d = cur[0];
    int u = (int) cur[1];
    if (d > dist[u]) continue;                    // stale entry
    for (Edge e : g.get(u)) {
        long nd = d + e.w();
        if (nd < dist[e.to()]) {
            dist[e.to()] = nd;
            parent[e.to()] = u;
            pq.offer(new long[] { nd, e.to() });
        }
    }
}
Trick — lazy deletion: Java's PriorityQueue has no decrease-key. Just push a new (dist, v) entry; skip outdated ones with if (d > dist[u]) continue;.
Trick — early exit: if you only need dist[t], return as soon as t is popped.
Tip: use a long[] in the PQ instead of a class — fewer allocations, faster in tight loops.
Watch out: Dijkstra is silently wrong on negative edges, even without negative cycles.
Hint: to reconstruct the path, walk parent[v] back from t, then reverse.
Q. Can you run Dijkstra on a graph where some edges have weight 0 and others weight 5?
Reveal hint
Yes, weights just need to be non-negative. Zero is fine.

Shortest Path 12. Bellman-Ford Algorithm

OBJECTIVE Single-source shortest paths in a graph that may contain negative edges, with negative-cycle detection.
WHY When Dijkstra can't help (negative weights), Bellman-Ford is the workhorse. It also detects negative cycles — critical for arbitrage detection, currency conversion, and cost models that allow rebates.
HOW Relax every edge V−1 times. After that, the distances are final for any graph without a negative cycle. One more pass: if anything still relaxes, there's a negative cycle.
THEORY — DP formulation
  • Let dist[i][v] = shortest path from source to v using at most i edges.
  • Recurrence: dist[i][v] = min(dist[i-1][v], min over (u,v) of dist[i-1][u] + w(u,v)).
  • Any simple path uses at most V−1 edges, so V−1 passes suffice.
COMPLEXITY O(V · E) time, O(V) space (1D rolling array).
long[] dist = new long[n];
Arrays.fill(dist, Long.MAX_VALUE);
dist[src] = 0;

for (int i = 0; i < n - 1; i++) {
    boolean changed = false;
    for (int[] e : edges) {                          // {u, v, w}
        if (dist[e[0]] == Long.MAX_VALUE) continue;
        long nd = dist[e[0]] + e[2];
        if (nd < dist[e[1]]) { dist[e[1]] = nd; changed = true; }
    }
    if (!changed) break;                            // early stop trick
}

boolean hasNegativeCycle = false;
for (int[] e : edges) {
    if (dist[e[0]] != Long.MAX_VALUE
        && dist[e[0]] + e[2] < dist[e[1]])
        hasNegativeCycle = true;
}
Trick — early stop: if a whole pass relaxes nothing, no later pass will. Saves a lot of time on sparse updates.
Trick — which vertices are on a neg cycle? Run V more passes after the initial V−1. Any vertex relaxed is either on, or reachable from, a negative cycle.
Watch out: overflow. INF + w wraps around int. Use long, and always gate with dist[u] != INF.
Hint — LeetCode "Cheapest flights within K stops": Bellman-Ford is a natural fit — bound the number of passes by K+1 to enforce the hop limit.

Shortest Path 13. Floyd-Warshall — All-Pairs Shortest Paths

OBJECTIVE Compute shortest distances between every pair of vertices.
WHY When the graph is small (V ≤ ~500) and you need many pairwise queries, one Floyd-Warshall run answers them all in O(V³) — simpler and often faster in practice than V Dijkstras. Also handles negative edges.
HOW Triple loop over k, i, j: try to improve d[i][j] via intermediate k.
THEORY — DP over "allowed intermediates"
  • d[k][i][j] = shortest i→j path using only vertices 0..k−1 as intermediates.
  • Recurrence: d[k][i][j] = min(d[k-1][i][j], d[k-1][i][k-1] + d[k-1][k-1][j]).
  • Rolling the k dimension reduces space to O(V²).
  • Negative cycle iff d[i][i] < 0 for some i after the loop.
COMPLEXITY O(V³) time, O(V²) space.
long[][] d = new long[n][n];
for (long[] row : d) Arrays.fill(row, Long.MAX_VALUE / 4);
for (int v = 0; v < n; v++) d[v][v] = 0;
for (int[] e : edges) d[e[0]][e[1]] = Math.min(d[e[0]][e[1]], e[2]);

for (int k = 0; k < n; k++)
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            if (d[i][k] + d[k][j] < d[i][j])
                d[i][j] = d[i][k] + d[k][j];

// Negative cycle iff any d[i][i] < 0
Trick — transitive closure: swap min/+ for OR/AND on a boolean matrix. Same triple loop computes reachability between every pair.
Tip — INF: use Long.MAX_VALUE / 4 so that INF + INF doesn't overflow.
Hint — path reconstruction: keep next[i][j] (the first hop on the best i→j path); update whenever you relax.

Shortest Path 14. Johnson's Algorithm (All-Pairs, Sparse)

OBJECTIVE All-pairs shortest paths on sparse graphs, possibly with negative edges.
WHY Floyd's O(V³) is wasteful when E ≪ V². Johnson runs one Bellman-Ford plus V Dijkstras for O(V·E + V² log V) — big win when the graph is sparse.
HOW
  1. Add an auxiliary vertex q with 0-weight edges to every other vertex.
  2. Run Bellman-Ford from q to compute potentials h[v]. Abort on negative cycle.
  3. Reweight every edge: w'(u,v) = w(u,v) + h[u] − h[v]. Guaranteed non-negative.
  4. Run Dijkstra from every vertex on the reweighted graph.
  5. Translate back: d(u,v) = d'(u,v) − h[u] + h[v].
THEORY — Why reweighting preserves shortest paths For any path p = v₀ → v₁ → … → vₖ, Σ w' = Σ w + h[v₀] − h[vₖ]. The h-telescope depends only on the endpoints, so all paths from v₀ to vₖ shift by the same constant — the relative ordering is preserved.
COMPLEXITY O(V · E + V² log V) with a binary heap.
Hint — when to pick what: Johnson wins when E is small and V is big. Floyd wins when V is small and the graph is dense.

Shortest Path 15. A* Algorithm

OBJECTIVE Single-pair shortest path with directional "hints" — a goal-biased search.
WHY In many real problems (game maps, navigation) you know the geometry and can estimate how close any vertex is to the goal. A* uses that estimate to explore far fewer vertices than Dijkstra.
HOW Dijkstra with priority f(v) = g(v) + h(v), where g(v) is the best known distance from the start and h(v) estimates the remaining cost to the goal.
THEORY — Heuristic properties
PropertyMeaningConsequence
Admissibleh(v) ≤ true cost(v, goal)Optimal path guaranteed.
Consistent (monotone)h(u) ≤ w(u,v) + h(v) on every edgeNever re-opens closed nodes.
h ≡ 0No guidance at allA* degrades gracefully to Dijkstra.
 
PriorityQueue<long[]> pq = new PriorityQueue<>(
    Comparator.comparingLong(a -> a[0]));
long[] g = new long[n];
Arrays.fill(g, Long.MAX_VALUE);
g[src] = 0;
pq.offer(new long[] { h(src), src });

while (!pq.isEmpty()) {
    long[] cur = pq.poll();
    int u = (int) cur[1];
    if (u == goal) return g[u];
    for (Edge e : graph.get(u)) {
        long ng = g[u] + e.w();
        if (ng < g[e.to()]) {
            g[e.to()] = ng;

        }
    }
}
Trick — grid heuristics: 4-directional → Manhattan; 8-directional → Chebyshev; free Euclidean space → Euclidean. All are admissible and consistent for unit-cost moves.
Watch out: an overestimating heuristic breaks optimality. If unsure, use h ≡ 0 (Dijkstra) — slower but correct.

Trees 16. Trees & Out-Trees (Rooted)

OBJECTIVE Identify, root, and process trees — a key special case that unlocks linear-time algorithms for many hard problems.
WHY Trees are everywhere: file systems, DOMs, hierarchies, parse trees. Because a tree has V−1 edges and no cycles, both DFS and BFS are O(V), and any tree problem decomposes recursively into child subproblems.
HOW
  • Detect a tree: check connected AND |E| = |V| − 1 AND acyclic (any two imply the third).
  • Root it: pick any vertex, DFS from it, record parent/children.
  • Solve tree problems via post-order DP: compute f(u) from children, then combine.
THEORY — Tree facts
  • Connected AND acyclic AND |E| = |V| − 1 are equivalent (any two imply the third).
  • Exactly one simple path between any two vertices.
  • Removing any edge disconnects the tree (every edge is a bridge).
COMPLEXITY DFS/BFS O(V); tree DP O(V).
int[] parent = new int[n];
Arrays.fill(parent, -1);
List<List<Integer>> children = new ArrayList<>();
for (int i = 0; i < n; i++) children.add(new ArrayList<>());

void root(int u, int p) {
    parent[u] = p;
    for (int v : adj.get(u))
        if (v != p) {
            children.get(u).add(v);
            root(v, u);
        }
}
root(chosenRoot, -1);
Trick — tree diameter in two BFSes: BFS from any vertex x to find farthest y; BFS from y to find farthest z. Distance y↔z = diameter. Total O(V).
Tip — "all nodes at distance k": root at the start node, then BFS down k steps. For arbitrary start, use parent pointers and BFS in the undirected tree.
Hint — tree DP pattern: post-order DFS; combine children results into f(u) using max/sum/etc.
Q. V = 10, E = 10 — can it be a tree?
Reveal hint
No. A tree needs exactly V−1 = 9 edges. One extra edge forces a cycle.

MST 17. Minimum Spanning Tree — Prim

OBJECTIVE Find a spanning subtree of minimum total weight in a connected weighted undirected graph.
WHY MSTs are the backbone of network design (cheapest way to connect all routers / cities / sensors). Prim is the natural choice when the graph is dense or already stored as an adjacency list/matrix.
HOW Grow the MST from a start vertex: always add the lightest edge that extends the current tree by one new vertex. Use a PriorityQueue keyed on edge weight.
THEORY — Cut property For any cut (partition of V into S and V∖S), the lightest crossing edge is in some MST. Prim keeps S = "tree so far" and always adds the lightest edge leaving S.
COMPLEXITY O(E log V) with binary heap; O(V²) with a plain array — the latter wins on dense graphs.
boolean[] inMST = new boolean[n];
PriorityQueue<int[]> pq = new PriorityQueue<>(
    Comparator.comparingInt(a -> a[0]));    // {w, to}
pq.offer(new int[] { 0, 0 });

long total = 0;
int taken = 0;

while (!pq.isEmpty() && taken < n) {
    int[] cur = pq.poll();
    int w = cur[0], u = cur[1];
    if (inMST[u]) continue;
    inMST[u] = true;
    total += w;
    taken++;
    for (Edge e : g.get(u))
        if (!inMST[e.to()])
            pq.offer(new int[] { e.w(), e.to() });
}
Trick: Prim is Dijkstra with a twist — the PQ is keyed on edge weight, not cumulative distance.
Tip: on dense graphs (E ≈ V²), the simple O(V²) array-based Prim beats the heap version in practice.

MST 18. Minimum Spanning Tree — Kruskal & Union-Find

OBJECTIVE Same as Prim but edge-centric: process all edges by weight and add the ones that don't form a cycle.
WHY On sparse graphs or when edges come pre-sorted (or via Manhattan distances), Kruskal is usually cleaner and faster. It also doubles as a dynamic-connectivity tool via union-find.
HOW
  1. Sort all edges by weight ascending.
  2. For each edge (u, v, w), if find(u) ≠ find(v), union them and take the edge.
  3. Stop after V − 1 edges.
THEORY — Cycle property Among all edges forming a cycle, the heaviest is never in any MST. Kruskal adds only edges that don't close a cycle — guaranteed minimum.
COMPLEXITY O(E log E) dominated by sorting. Union-find ops are near-constant (α(n)) amortized.

Union-Find (path compression + union by rank)

int[] par, rnk;

void init(int n) {
    par = new int[n];
    rnk = new int[n];
    for (int i = 0; i < n; i++) par[i] = i;
}

int find(int x) {
    while (par[x] != x) {
        par[x] = par[par[x]];           // path halving
        x = par[x];
    }
    return x;
}

boolean union(int a, int b) {
    int ra = find(a), rb = find(b);
    if (ra == rb) return false;
    if (rnk[ra] < rnk[rb]) { int t = ra; ra = rb; rb = t; }
    par[rb] = ra;
    if (rnk[ra] == rnk[rb]) rnk[ra]++;
    return true;
}

Kruskal main loop

edges.sort(Comparator.comparingInt(e -> e[2]));
init(n);
long total = 0;
int taken = 0;
for (int[] e : edges) {
    if (union(e[0], e[1])) {
        total += e[2];
        if (++taken == n - 1) break;
    }
}
Trick — Prim vs Kruskal: Kruskal wins on sparse graphs (edge list + sort). Prim wins on dense graphs (no sort, array-based).
Hint — "Min cost to connect all points": compute all pairwise Manhattan distances as edges; run Kruskal. With n = 1000 that's ~5×10⁵ edges.
Tip — dynamic connectivity: union-find is also the right tool for "Edge length limited paths", "Number of islands II", "Accounts merge".
Watch out: MST isn't unique when multiple edges share the same weight — different valid MSTs can share the same total.

Eulerian 19. Eulerian Paths / Cycles & Hierholzer

OBJECTIVE Find a walk that uses every edge exactly once (Eulerian path / cycle), if one exists.
WHY Appears in route inspection, DNA sequence assembly (de Bruijn graphs), and classic puzzles ("draw this shape without lifting your pen"). Existence is decidable in O(V + E); construction in O(V + E) via Hierholzer.
HOW
  1. Check existence with degree conditions (below).
  2. Run Hierholzer from the correct start vertex — it greedily walks until stuck, then splices in side-trips when backtracking.
THEORY — Existence conditions
Graph classEulerian cycleEulerian path
Undirected (connected)All vertices have even degree.Exactly 0 or 2 odd-degree vertices. Start at an odd one.
Directed (connected when ignoring direction)For every v: in-deg = out-deg; all edge-bearing vertices in one SCC.Exactly one vertex with out−in = 1 (start), one with in−out = 1 (end); others balanced.
COMPLEXITY O(V + E).
Deque<Integer> stack = new ArrayDeque<>();
List<Integer> circuit = new ArrayList<>();
stack.push(start);

while (!stack.isEmpty()) {
    int u = stack.peek();
    if (!adj.get(u).isEmpty()) {
        int v = adj.get(u).remove(adj.get(u).size() - 1);   // O(1) tail pop
        stack.push(v);
    } else {
        circuit.add(stack.pop());
    }
}
Collections.reverse(circuit);
Trick — lexicographic Euler path ("Reconstruct Itinerary"): store each vertex's outgoing list in a PriorityQueue<String>; Hierholzer's removal of the smallest produces the smallest lexicographic itinerary.
Tip — start vertex: Euler cycle → any vertex. Euler path → start at one of the two "unbalanced" vertices.
Watch out: isolated vertices with no edges don't matter for existence but must not break your connectivity check.

Hamiltonian 20. Hamiltonian Paths & Cycles

OBJECTIVE Find a path that visits every vertex exactly once (Hamiltonian path / cycle).
WHY Models TSP-like problems: "visit every city exactly once", "assemble a DNA sequence using every fragment", "schedule every task once".
HOW
  • General graphs: NP-complete. Use backtracking for small n.
  • n ≤ ~20: bitmask DP (Held-Karp) is O(2ⁿ·n²).
  • Heuristics: Ore's theorem provides a sufficient existence check.
THEORY
  • Ore: if every pair of non-adjacent vertices u, v satisfies deg(u) + deg(v) ≥ n, the graph is Hamiltonian.
  • Dirac (special case): if every vertex has degree ≥ n/2, Hamiltonian cycle exists.
  • No known polynomial existence test for general graphs.
COMPLEXITY Backtracking O(n!) worst case; bitmask DP O(2ⁿ·n²).
boolean[] visited = new boolean[n];
int[] path = new int[n];

boolean solve(int pos) {
    if (pos == n)
        return adj.get(path[pos - 1]).contains(path[0]); // cycle check
    for (int v = 0; v < n; v++) {
        if (!visited[v] && adj.get(path[pos - 1]).contains(v)) {
            visited[v] = true;
            path[pos] = v;
            if (solve(pos + 1)) return true;
            visited[v] = false;
        }
    }
    return false;
}
Trick: don't confuse Euler (edges, linear time) with Hamilton (vertices, exponential). Mnemonic: Euler = Edge.
Hint — Ore's theorem as preflight: check Ore first; if it passes, existence is guaranteed. If not, fall back to backtracking.

Connectivity 21. Strongly Connected Components — Tarjan

OBJECTIVE Partition a directed graph's vertices into maximal strongly connected components (SCCs) in a single DFS pass.
WHY SCCs reveal functional groups in directed networks (websites linking to each other, recursive dependencies, 2-SAT components). The contracted SCC graph is always a DAG — so contract and solve the easier problem.
HOW Classic Tarjan bookkeeping:
  • disc[u]: discovery time of u.
  • low[u]: smallest disc reachable from u's subtree via at most one back edge.
  • Keep a stack of "currently open" vertices.
  • When low[u] == disc[u], pop everything down to u — that's one SCC.
THEORY — Why low-link works A vertex u roots an SCC iff no ancestor of u in the DFS tree is reachable from u's subtree via back edges. Equivalently, low[u] == disc[u].
COMPLEXITY O(V + E), one DFS, no graph reversal.
int timer = 0, compId = 0;
int[] disc, low, comp;
boolean[] onStack;
Deque<Integer> st = new ArrayDeque<>();

void dfs(int u) {
    disc[u] = low[u] = timer++;
    st.push(u); onStack[u] = true;

    for (int v : adj.get(u)) {
        if (disc[v] == -1) {
            dfs(v);
            low[u] = Math.min(low[u], low[v]);
        } else if (onStack[v]) {
            low[u] = Math.min(low[u], disc[v]);
        }
    }

    if (low[u] == disc[u]) {              // u is an SCC root
        while (true) {
            int v = st.pop();
            onStack[v] = false;
            comp[v] = compId;
            if (v == u) break;
        }
        compId++;
    }
}
Trick — condensation DAG: contract each SCC to a super-vertex. The result is always a DAG. Many hard-looking directed-graph problems reduce to "topo sort + DP" on the condensation.
Tip — interpretation of low[u]: the smallest discovery time reachable from u without leaving its DFS subtree.

Connectivity 22. SCC — Kosaraju

OBJECTIVE Same SCC output as Tarjan but via two simple DFS passes, easier to explain.
WHY Great for interviews and teaching: the algorithm reads naturally from "DFS finish order + transposed graph". Tarjan is faster in practice; Kosaraju is easier to write correctly the first time.
HOW
  1. DFS on G; push each vertex on a stack in post-order.
  2. Build transpose Gᵀ (reverse every edge).
  3. Pop vertices from the stack; each fresh DFS on Gᵀ explores exactly one SCC.
THEORY — Post-order intuition The last vertex to finish in the first DFS belongs to a sink SCC of the condensation. Reversing edges flips sinks into sources, so a DFS from there explores exactly that SCC without leaking.
COMPLEXITY O(V + E), two linear passes.
Trick — which one to pick: Tarjan (one DFS, no reversal) for speed; Kosaraju for clarity on unfamiliar graphs.

Connectivity 23. Articulation Points & Bridges

OBJECTIVE Find "critical" vertices and edges whose removal disconnects the undirected graph.
WHY Network resilience: which single server/link, if it fails, would break connectivity? In a grid: which cell, if removed, disconnects an island?
HOW One DFS with disc[] / low[] bookkeeping (same spirit as Tarjan). Use the edge conditions below.
THEORY
Vertex uIs articulation?
DFS rootYes iff it has ≥ 2 DFS children.
Non-rootYes iff there exists a child v with low[v] ≥ disc[u].

Edge (u, v) is a bridge iff low[v] > disc[u] (strict).

COMPLEXITY O(V + E).
void dfs(int u, int parent) {
    disc[u] = low[u] = timer++;
    int children = 0;
    for (int v : adj.get(u)) {
        if (v == parent) continue;
        if (disc[v] == -1) {
            children++;
            dfs(v, u);
            low[u] = Math.min(low[u], low[v]);
            if (parent != -1 && low[v] >= disc[u]) isArt[u] = true;
            if (low[v] > disc[u]) bridges.add(new int[] { u, v });
        } else {
            low[u] = Math.min(low[u], disc[v]);
        }
    }
    if (parent == -1 && children > 1) isArt[u] = true;
}
Trick — "Minimum days to disconnect island": count islands; if it's already ≠ 1 → answer is 0. Else find any articulation point → 1. Else → 2 (always possible on a grid, remove two corner cells).
Watch out: articulation uses low[v] ≥ disc[u]; bridge uses strict >. The DFS root is a special case.

Coloring 24. Graph Coloring

OBJECTIVE Assign colors to vertices so no two adjacent vertices share a color, using as few colors as possible.
WHY Models scheduling (exam slots, register allocation), frequency assignment, puzzles (Sudoku), and conflict resolution. Optimal coloring is NP-hard, but special cases and heuristics are widely usable.
HOW
  • Bipartite (2-color) check: BFS/DFS, alternate colors, fail on a same-color neighbor.
  • k-colorability: backtracking (exponential worst case).
  • Greedy: walk vertices in some order, assign smallest unused color.
  • Welsh-Powell: sort by degree descending; color independent sets one color at a time.
  • DSatur: always pick the vertex with the most already-colored neighbors (saturation); break ties by degree.
THEORY — Bounds
BoundMeaning
χ(G) ≥ ω(G)χ is at least the size of the largest clique.
χ(G) ≤ Δ(G) + 1Greedy bound (Δ = max degree).
Brooksχ ≤ Δ unless G is a complete graph or an odd cycle.
Four-Color theoremEvery planar graph is 4-colorable.
Bipartite ⇔ 2-colorable ⇔ no odd cycle.Checkable in linear time.
COMPLEXITY Bipartite check O(V + E). Backtracking k-color O(kV) worst case. Greedy / Welsh-Powell / DSatur polynomial, approximate.

Bipartite check (2-color)

int[] color = new int[n];
Arrays.fill(color, -1);

for (int s = 0; s < n; s++) if (color[s] == -1) {
    Deque<Integer> q = new ArrayDeque<>();
    q.offer(s);
    color[s] = 0;
    while (!q.isEmpty()) {
        int u = q.poll();
        for (int v : adj.get(u)) {
            if (color[v] == -1) { color[v] = 1 - color[u]; q.offer(v); }
            else if (color[v] == color[u]) return false;
        }
    }
}
return true;

k-colorability via backtracking

boolean solve(int u, int k, int[] col) {
    if (u == n) return true;
    for (int c = 0; c < k; c++) {
        if (safe(u, c, col)) {
            col[u] = c;
            if (solve(u + 1, k, col)) return true;
            col[u] = -1;
        }
    }
    return false;
}

boolean safe(int u, int c, int[] col) {
    for (int v : adj.get(u))
        if (col[v] == c) return false;
    return true;
}
Trick — Sudoku as graph coloring: 81 cells = vertices, edges between cells sharing row/column/3×3 box, 9 colors, pre-filled = fixed colors. Run backtracking with k = 9.
Tip — odd-cycle fast check: BFS 2-coloring fails precisely when an odd cycle exists.
Watch out: greedy coloring can be as bad as n colors with a pathological order. Welsh-Powell and DSatur reduce (but don't eliminate) the risk.

TSP 25. Traveling Salesman Problem

OBJECTIVE Find a minimum-cost tour that visits every vertex exactly once and returns to the start.
WHY The canonical NP-hard optimization problem. Real instances are solved with smart heuristics (routing, logistics, circuit design). Bitmask DP handles n ≤ 20 optimally; approximations handle everything else.
HOW
  • Brute force: O(n!). Only n ≤ 10.
  • Bitmask DP (Held-Karp): O(2ⁿ·n²). Feasible up to ~20.
  • Nearest Neighbor: O(n²), quick but can be arbitrarily bad.
  • Christofides: polynomial, guaranteed ≤ 1.5× optimal for metric TSP.
THEORY — Held-Karp DP
  • dp[mask][u] = min cost to start at 0, visit the set mask of vertices (including u), and end at u.
  • Transition: dp[mask | 1<<v][v] = min(..., dp[mask][u] + d(u,v)).
  • Answer: min over u of dp[full][u] + d(u, 0).
COMPLEXITY Held-Karp O(2ⁿ·n²) time, O(2ⁿ·n) space.
int[][] dp = new int[1 << n][n];
for (int[] r : dp) Arrays.fill(r, Integer.MAX_VALUE / 2);
dp[1][0] = 0;                                   // start at vertex 0

for (int mask = 1; mask < (1 << n); mask++) {
    for (int u = 0; u < n; u++) if ((mask & (1 << u)) != 0) {
        for (int v = 0; v < n; v++) if ((mask & (1 << v)) == 0) {
            int nm = mask | (1 << v);
            dp[nm][v] = Math.min(dp[nm][v], dp[mask][u] + d[u][v]);
        }
    }
}

int ans = Integer.MAX_VALUE;
int full = (1 << n) - 1;
for (int u = 1; u < n; u++)
    ans = Math.min(ans, dp[full][u] + d[u][0]);
Trick — Christofides in one sentence: MST → perfect matching on odd-degree vertices → Eulerian circuit on (MST + matching) → shortcut repeats. Triangle inequality keeps shortcuts short.
Hint — LeetCode #943 "Shortest Superstring": model strings as nodes, edge (i→j) weight = length to append j after i accounting for overlap. Minimum-cost Hamiltonian path = shortest superstring. Bitmask DP solves it.

Max Flow 26. Maximum Flow

OBJECTIVE Given a directed capacity graph with source s and sink t, find the maximum amount of "flow" you can push from s to t.
WHY The master problem of combinatorial optimization: bipartite matching, min-cut, project selection, image segmentation, scheduling — all reduce to max flow.
HOW Repeatedly find an augmenting path in the residual graph (edges with capacity remaining) and push as much flow as possible along it. Different path-finding strategies give different algorithms.
THEORY
  • Residual graph: for edge (u,v) with capacity c and flow f, add forward residual c−f and reverse residual f.
  • Augmenting path: s→t path in residual graph with positive capacity.
  • Max-flow min-cut theorem: max flow(s→t) equals the minimum capacity over all s-t cuts.
COMPLEXITY
AlgorithmPath finderTimeNotes
Ford-FulkersonAny (DFS)O(E · max_flow)Only polynomial for integer capacities.
Edmonds-KarpBFS (shortest augmenting path)O(V · E²)First strongly polynomial version.
DinicBFS level graph + blocking flowsO(V² · E)O(E·√V) on unit-capacity / bipartite matching.

Edmonds-Karp skeleton

int[][] cap;                                    // cap[u][v] current residual capacity
int[] parent = new int[n];

int bfs(int s, int t) {
    Arrays.fill(parent, -1);
    parent[s] = s;
    int[] inc = new int[n];
    inc[s] = Integer.MAX_VALUE;
    Deque<Integer> q = new ArrayDeque<>();
    q.offer(s);
    while (!q.isEmpty()) {
        int u = q.poll();
        for (int v = 0; v < n; v++)
            if (parent[v] == -1 && cap[u][v] > 0) {
                parent[v] = u;
                inc[v] = Math.min(inc[u], cap[u][v]);
                if (v == t) return inc[t];
                q.offer(v);
            }
    }
    return 0;
}

int maxFlow(int s, int t) {
    int flow = 0, add;
    while ((add = bfs(s, t)) > 0) {
        flow += add;
        for (int v = t; v != s; v = parent[v]) {
            cap[parent[v]][v] -= add;
            cap[v][parent[v]] += add;                // reverse edge!
        }
    }
    return flow;
}
Trick — min cut from max flow: after computing max flow, BFS from s on the residual graph. Reachable vertices form the S side; unreachable form the T side. Original edges from S to T form the min cut.
Tip — modeling constraints: vertex capacities → split each vertex into in-node and out-node with an edge of capacity c. Multi-source/sink → add super-source and super-sink with ∞ edges.
Watch out: reverse residual edges are non-negotiable. Without them the algorithm can get stuck at a non-optimum because it can't "undo" a bad earlier decision.
Hint — LeetCode #1349 "Maximum students": bipartite matching on chessboard-colored seats based on cheating neighbors. Solve via Dinic or Hopcroft-Karp.

Matching 27. Bipartite Matching — Hopcroft-Karp

OBJECTIVE Find a maximum matching in a bipartite graph (V = L ⊎ R) — pair up the most left-vertices with right-vertices without reusing anyone.
WHY The canonical algorithm for assignment problems: workers to tasks, students to seats, requests to servers. Hopcroft-Karp hits O(E·√V), far better than naïve augmenting-path O(V·E).
HOW
  1. BFS from every unmatched left vertex to compute a layered graph.
  2. Find vertex-disjoint augmenting paths in that layered graph via DFS.
  3. Augment all of them at once; repeat until no more augmenting paths exist.
THEORY — König's theorem In a bipartite graph, maximum matching equals minimum vertex cover. So if you need min vertex cover on a bipartite graph, solve max matching first.
COMPLEXITY O(E · √V).
Trick — bipartite matching in disguise: "assign jobs to workers", "students to seats", "tasks to machines", "domino tiling on a chessboard". If the underlying graph is bipartite, Hopcroft-Karp (or Dinic on unit capacities) is the right tool.

Master buckets — tips, tricks, hints, pitfalls

Tips
  • Ask four questions before coding: directed? weighted? cyclic? connected?
  • Default to adjacency list. Matrix only when V ≤ 500 and density is high.
  • Always add both (u,v) and (v,u) for undirected graphs.
  • Use long for sums in shortest-path algorithms and guard INF + w.
  • Mark visited on enqueue in BFS, not on dequeue.
  • In Dijkstra, push a new entry instead of decrease-key; skip stale ones.
Tricks
  • 0/1 BFS: weights ∈ {0,1} → ArrayDeque, push-front for 0-weight, push-back for 1-weight.
  • Multi-source BFS: seed every source at distance 0 for "nearest X" problems.
  • Tree diameter: two BFSes — from any x find farthest y; from y find farthest z. |y-z| is the diameter.
  • Topo + DAG DP: shortest, longest, count of paths — all linear on DAGs.
  • Graph coloring models: scheduling, register allocation, Sudoku, map coloring.
  • Max flow models: matching, segmentation, min-cost assignment, edge connectivity.
Hints / theorems
  • Handshake: Σ deg(v) = 2|E|. Odd-degree vertices come in pairs.
  • Tree ⇔ connected ∧ acyclic ∧ |E| = |V|−1 (any two ⇒ third).
  • Bipartite ⇔ no odd cycle ⇔ 2-colorable.
  • DAG ⇔ topo order exists ⇔ DFS has no back edge.
  • Eulerian (undirected): all degrees even (cycle) or exactly two odd (path).
  • Max flow = min cut.
  • Brooks: χ(G) ≤ Δ(G) unless G is complete or an odd cycle.
  • König: max bipartite matching = min vertex cover.
Pitfalls
  • Off-by-one on 1-indexed vs 0-indexed vertices.
  • Overflow in Floyd / Bellman-Ford; cap INF at Long.MAX_VALUE / 4.
  • Dijkstra on negative weights — silently wrong.
  • BFS on weighted graphs — silently wrong.
  • DFS stack overflow on V > ~10⁵ — go iterative or bump -Xss.
  • Forgetting reverse edges in max-flow residual graph.
  • Confusing Euler (edges) with Hamilton (vertices).
  • Greedy coloring with a bad vertex order can use way more colors than necessary.
