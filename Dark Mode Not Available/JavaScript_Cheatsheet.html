Q1. [] + [] // ?   [] + {} // ?   {} + [] // ?
Reveal hint
[] + [] → "". [] + {} → "[object Object]". {} + [] → 0 at the start of a statement ({} parsed as a block, then +[] coerces to 0). Wrap in parens to force expression: ({}) + [] → "[object Object]".
Q2. null == undefined, null == 0, null >= 0 — what gives?
Reveal hint
null == undefined → true (special case). null == 0 → false (no coercion in == for null vs number). null >= 0 → true (relational ops do coerce: null → 0). One of JS's worst inconsistencies.

Q1. const f = () => { return { ok: true } } works. But const f = () => { ok: true } returns undefined. Why?
Reveal hint
Without parens, {} is parsed as a function body, not an object literal. ok: true becomes a labelled statement. Wrap the object: () => ({ ok: true }).
Q2. Why does new (() => {})() throw?
Reveal hint
Arrow functions have no [[Construct]] internal slot. Use a regular function or class for constructors.
Q3. Default param trick: function f(a, b = a * 2) — legal? What about function f(a = b, b)?
Reveal hint
First is fine — params are evaluated left-to-right. Second throws ReferenceError because b is in TDZ when a's default runs.

Q. Difference between fn.call(null, ...) and fn.apply(null, args) in 2026?
Reveal hint
Functionally identical — only the args shape differs (call: spread, apply: array). Modern code uses spread: fn(...args). call/apply remain useful when you also need to set this.

6. this Binding Rules

Resolved at call time for regular functions, at declare time for arrows. Precedence (highest first):

  1. new F() → fresh object linked to F.prototype.
  2. Explicit: f.call(t, ...), f.apply(t, ...), f.bind(t).
  3. Implicit (method): obj.f() → obj. Only the last dot matters: a.b.c.f() → a.b.c.
  4. Default: plain call → undefined in strict mode / modules / classes; global object in sloppy mode.
  5. Arrow: ignores all the above. Captures this lexically.
const obj = { x: 1, get(){ return this.x; } };
const g = obj.get;
obj.get();                  // 1   (implicit)
g();                        // undefined  (lost)
g.call(obj);                // 1   (explicit)
const h = g.bind(obj); h();// 1   (bound)
new g();                    // new obj is 'this'; .x = undefined
Mnemonic — "NEMO": New > Explicit > Method > Ordinary. Arrows skip the queue and ask their parent.
Q. const a = { x: 1, b: { x: 2, get(){ return this.x } } } — what does a.b.get() return?
Reveal hint
2. The implicit this is the object immediately to the left of the dot — a.b.

7. Closures

A closure is a function plus the variable bindings of the lexical scope where it was created. The function "remembers" those bindings even after the outer function returns.

function counter() {
  let n = 0;
  return {
    inc() { return ++n; },
    peek(){ return n; }
  };
}
const c = counter();
c.inc(); c.inc();          // n persists, but is private
c.peek();                  // 2

Common uses

  • Data privacy / module pattern (pre-ES2022 #private).
  • Memoization caches.
  • Partial application / currying.
  • Event handlers carrying state.
  • Once-only initializers.

Q. Implement a function once(fn) that runs fn only the first time and caches its result.
Reveal hint 
function once(fn) {
  let called = false, value;
  return function(...args) {
    if (!called) { value = fn.apply(this, args); called = true; }
    return value;
  };
}

8. Higher-Order Functions & Callbacks

Functions are first-class values. They can be passed, returned, stored, and composed.

// Compose: (f ∘ g)(x) = f(g(x))
const compose = (...fns) => x => fns.reduceRight((v, f) => f(v), x);
const pipe    = (...fns) => x => fns.reduce     ((v, f) => f(v), x);

// Curry: f(a,b,c) -> f(a)(b)(c)
const curry = fn => function curried(...args) {
  return args.length >= fn.length
    ? fn.apply(this, args)
    : (...more) => curried.apply(this, [...args, ...more]);
};

// Debounce: only fire after Xms of silence
const debounce = (fn, ms) => {
  let t;
  return (...args) => { clearTimeout(t); t = setTimeout(() => fn(...args), ms); };
};

// Throttle: at most 1 call per Xms
const throttle = (fn, ms) => {
  let last = 0;
  return (...args) => {
    const now = Date.now();
    if (now - last >= ms) { last = now; fn(...args); }
  };
};
Q. Why prefer arr.map(fn) to a manual for loop?
Reveal hint
Declarative intent ("transform each element") + always returns a new array (immutable input). Use for when you need early exit, async sequencing, or peak performance.

9. Generators & Iterators

An iterator is any object with a next() method returning {value, done}. An iterable implements [Symbol.iterator](). Generators are syntactic sugar that produce both.

// Hand-rolled iterator
function range(n) {
  let i = 0;
  return {
    [Symbol.iterator]() { return this; },
    next() { return i < n ? { value: i++, done: false } : { value: undefined, done: true }; }
  };
}

// Same thing as a generator
function* range2(n) { for (let i = 0; i < n; i++) yield i; }

// Two-way: yield expression returns whatever .next(v) is called with
function* echo() {
  while (true) {
    const got = yield;     // pauses here
    console.log(got);
  }
}

// Delegation
function* a() { yield 1; yield 2; }
function* b() { yield 0; yield* a(); yield 3; }   // 0,1,2,3
Use cases: lazy/infinite sequences, custom iteration over a tree, state machines, and as the basis of async (which is generators + promises before native syntax existed).

12. Event Loop, Microtasks vs Macrotasks

JS is single-threaded with a queue model:

  1. Run current synchronous code to completion (one "task").
  2. Drain the microtask queue entirely (Promise callbacks, queueMicrotask, MutationObserver).
  3. Render (browser) if needed.
  4. Pick the next macrotask (setTimeout, setInterval, I/O, setImmediate, message events).
  5. Repeat.
console.log("1");
setTimeout(() => console.log("2"), 0);     // macro
Promise.resolve().then(() => console.log("3")); // micro
queueMicrotask(() => console.log("4"));        // micro
console.log("5");
// Output: 1 5 3 4 2  (microtasks beat the timer)
Trap: a tight chain of .thens can starve the macrotask queue, blocking timers and I/O. Yield with await new Promise(r => setTimeout(r, 0)) if you need to share the loop.
Q. Predict the order: setTimeout(()=>console.log("A"),0); Promise.resolve().then(()=>{ console.log("B"); setTimeout(()=>console.log("C"),0); Promise.resolve().then(()=>console.log("D")); }); console.log("E");
Reveal hint
E, B, D, A, C. Sync first ("E"). Then microtask queue drains: "B" (which schedules "C" macro and "D" micro). Microtask queue keeps draining → "D". Then macros in order: "A", then "C".

13. Async Iteration & Async Generators

// Async iterable: implements [Symbol.asyncIterator]()
async function* lines(stream) {
  let buf = "";
  for await (const chunk of stream) {
    buf += chunk;
    let i;
    while ((i = buf.indexOf("\n")) >= 0) {
      yield buf.slice(0, i);
      buf = buf.slice(i + 1);
    }
  }
  if (buf) yield buf;
}

for await (const line of lines(file)) {
  console.log(line);
}
Use cases: paging APIs, streaming responses (fetch body), Node streams, and anywhere you'd otherwise build a manual while (await next()) loop.

15. Prototypes & Inheritance

Every object has an internal [[Prototype]] link. Property lookups walk the chain until they find the key or hit null.

function Animal(name) { this.name = name; }
Animal.prototype.speak = function(){ return `${this.name} makes a sound`; };

function Dog(name) { Animal.call(this, name); }
Dog.prototype = Object.create(Animal.prototype);
Dog.prototype.constructor = Dog;
Dog.prototype.speak = function(){ return `${this.name} barks`; };

const d = new Dog("Rex");
d.speak();              // "Rex barks"
d instanceof Dog;       // true
d instanceof Animal;    // true
TopicWrongRight
Modifying built-insArray.prototype.last = function(){...}Don't. Future ES versions or libraries may collide.
Mutating __proto__ at runtimeobj.__proto__ = X for "polymorphism"Major perf cliff (deopts the engine). Set the prototype at construction.
Shared mutable on prototypeFoo.prototype.list = [] — shared across instances.Initialize per-instance in the constructor.

19. Destructuring, Spread, Rest

// Object destructuring with rename + default + rest
const { name: n = "anon", age, ...other } = user;

// Array destructuring with skip + rest
const [first, , third, ...rest] = arr;

// Nested + default
const { a: { b = 0 } = {} } = input;

// Function params
function draw({ x = 0, y = 0, label = "" } = {}) { ... }

// Spread vs rest — same syntax, opposite roles
const a = [1, 2];
const b = [...a, 3];                // spread: expand
function f(...args) {}              // rest: collect

// Swap
[x, y] = [y, x];

// Clone (shallow)
const copy   = { ...obj };
const arrCopy = [...arr];

// Merge with later-wins precedence
const merged = { ...defaults, ...overrides };
Spread is shallow. Nested objects are shared. Use structuredClone(obj) for deep clones.
