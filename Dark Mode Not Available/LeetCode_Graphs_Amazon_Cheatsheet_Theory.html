0. What is a Graph? (The Real-Life Picture)

Picture a city. Each house is a dot (we call it a node). Each road joining two houses is a line (we call it an edge). The whole city map is a graph.

Graphs are everywhere in real life — friend lists on Instagram, metro maps, family trees, web links between websites, even a maze. Whenever something is "connected to" something else, you have a graph.

Two flavors of graphs

TypeReal-life exampleWhat it means
UndirectedFriendship on FacebookIf A is friends with B, then B is friends with A. Roads are two-way.
DirectedFollowing on Twitter / XA follows B does not mean B follows A. One-way streets.
WeightedMap with distances or costsEach road has a number — kilometers, money, time.
UnweightedPlain friendship listAll edges are "the same"; only "connected or not" matters.

How we store a graph in memory (no code, just the idea)

Storage stylePictureBest when
Adjacency listFor every house, write down a small list of houses it is directly connected to.Most problems. Saves memory when roads are few.
Adjacency matrixA big square table. Row A column B says "yes/no road between A and B".Small graphs (a few hundred nodes), or you need to check "is there a road" instantly.
Edge listJust a long list of pairs: (A, B), (B, C), (A, D)…When you need to look at every road one by one (like sorting them by cost).
Implicit gridA 2D board. Every cell is a node. Neighbors are the 4 cells up / down / left / right.Maze, island, water-flow problems.
Interview habit: before solving anything, ask four questions:
  1. Are roads one-way or two-way?
  2. Do edges have costs or are they all equal?
  3. Can a road loop back on the same node?
  4. Are nodes numbers (0, 1, 2…) or labels like words?
The answers decide how you store and walk the graph.

2. The 7 Big Patterns That Solve ~90% of Graph Problems

Graph problems look scary because they are dressed in different stories — islands, courses, flights, oranges. But almost all of them are one of these 7 patterns underneath.

#PatternWords in the problem that hint at itOne-line idea
1BFS (shortest path, no costs)"shortest", "minimum number of steps", "fewest moves"Spread out from the start in waves; the first time you see a node, that is the shortest distance.
2DFS (paint a region, count groups)"number of islands", "is reachable", "all paths"Pick a node, dive deep, mark everything you can reach.
3Multi-source BFS"distance from nearest X to every cell", "rotting oranges"Start from all sources at the same time. One sweep finds the nearest source for every cell.
4Topological sort"course schedule", "build order", "depends on"Do tasks that have no leftover prerequisites first; then "free" the next round of tasks.
5Union-Find"connected after these queries", "redundant edge", "merge groups"Keep a "boss" for each group. To merge two groups, point one boss to the other.
6Dijkstra (shortest with non-negative costs)"min cost", "min time", "min effort"Always expand the cheapest unfinished node next, like always taking the lowest-priced item first.
7Bellman-Ford / Floyd"at most K stops", "negative weights", "all pairs shortest path"Relax all edges many times, in rounds. Slower but handles tricky cases.
30-second pattern picker:
  1. Shortest path, all roads same cost? → BFS.
  2. Shortest path with positive costs? → Dijkstra.
  3. Shortest path with negative costs OR "at most K stops"? → Bellman-Ford.
  4. Distance from many sources to every cell? → Multi-source BFS.
  5. "Are these connected?" or "merge groups"? → Union-Find.
  6. Words "depends on / order / prerequisite"? → Topological sort.
  7. "How many islands / regions"? → DFS (or Union-Find).

3. BFS — The Ripple Walk

Drop a stone in a pond. Ripples spread out one circle at a time. BFS works the same way: from the start, you visit all neighbors first, then their neighbors, then theirs, and so on.

Why BFS gives the shortest path (when all roads are the same)

Because the first time a node is touched, the ripple has used the fewest possible steps to reach it. No other path can be shorter, since shorter paths would have arrived in an earlier ripple.

Steps of BFS in plain words

  1. Put the starting node in a queue (a line, first in first out).
  2. Mark it as visited right away.
  3. Take out the front of the queue. Look at all its neighbors.
  4. For each neighbor never visited, mark it visited and add it to the back of the queue.
  5. Keep going until the queue is empty or you reach the target.
Golden rule: mark a node visited the moment you put it in the queue, never when you pull it out. If you wait, the same node can be added many times by many neighbors, and your program slows down a lot.
Q. Why not use DFS for shortest path in an unweighted graph?
Reveal hint
DFS goes deep first. It might reach the target through a long, twisty path before it ever finds the short one. BFS, by spreading in rings, guarantees the first time it touches the target is via the shortest route.

4. DFS — The Maze Diver

Imagine you are inside a maze with a piece of chalk. You walk straight, marking every room you enter. When you hit a dead-end, you walk back to the last room with an unexplored door and try that one. That is exactly DFS.

Steps of DFS in plain words

  1. Start at a node. Mark it visited.
  2. Pick any neighbor that is not visited. Walk to it. Mark it visited.
  3. From there, repeat step 2 — keep going deeper.
  4. If you reach a node where every neighbor is already visited, back up to the previous one.
  5. Keep doing this until everywhere reachable has been marked.
When DFS shines: counting islands or regions, painting a connected area, finding any path (not the shortest), and exploring all combinations.
Watch out: on a very long, snake-like graph, recursion can run out of memory (stack overflow). The fix is to write DFS using an explicit stack instead of recursion.

5. Union-Find — The "Friend Groups" Trick

Imagine each person belongs to a small club. Every club has a leader. To check if two people are in the same club, ask each of them "who is your leader?". If the leaders match, they are friends. To merge two clubs, just have one leader bow down to the other — now everyone has the same boss.

The two operations you ever need

OperationPlain English
find(x)"Who is the leader of x's group right now?" — keep walking up bosses until someone is their own boss.
union(a, b)"Put a and b in the same group" — find both leaders, then make one the boss of the other.

Two cheap tricks that make it lightning fast

  1. Path compression: when you climb up the chain to find the leader, on the way back down, snap everyone directly to the top. Next time, find is one hop.
  2. Union by rank / size: always hang the smaller tree under the bigger tree. This keeps chains short.
When to pick Union-Find over BFS/DFS: when edges arrive one by one (online), or when you need a fast answer to "how many groups?" after each new edge.

6. Topological Sort — Putting Tasks in Order

Think of cooking pasta. You must boil water before adding pasta. You must cook the sauce before pouring it on. Some tasks depend on others. Topological sort gives you a valid order to do all the tasks.

The simplest version (Kahn's idea)

  1. For each task, count how many tasks must come before it (its in-degree).
  2. Put all tasks with in-degree zero (no prerequisites) into a queue. These are tasks you can start right now.
  3. Take a task out of the queue. Add it to your final order.
  4. For every task that was waiting on this one, reduce its in-degree by 1.
  5. If anyone's in-degree drops to zero, add it to the queue.
  6. Keep going until the queue is empty.
Free cycle detector: if at the end you have processed fewer tasks than the total number of tasks, that means some tasks are stuck waiting on each other in a circle. A cycle exists.
Q. Why does topological sort only work on directed graphs without cycles?
Reveal hint
A cycle means task A waits for B, B waits for C, and C waits for A. None of them can ever start, so there is no valid order. Direction matters because "depends on" is a one-way relation.

7. Dijkstra — Always Pick the Cheapest Next

You are shopping at a supermarket with a budget. To finish cheapest, at each step you reach for the cheapest item left in the basket of options. Dijkstra does this with paths: it always extends the path with the smallest cost so far.

Steps in plain words

  1. Give every node a "best cost so far" of infinity. The starting node gets 0.
  2. Put the start in a min-heap (a magical box that always pops the cheapest item).
  3. Pop the cheapest node. Look at its neighbors.
  4. For each neighbor, see if going through this node gives a cheaper cost than what we already had. If yes, update and push the neighbor into the heap.
  5. Repeat until the heap is empty.
Important rule: Dijkstra only works when no road has a negative cost. Negative edges break the "cheapest first" guarantee.

0-1 BFS — a faster cousin

If the only weights are 0 or 1, you can replace the heap with a deque (a queue with two ends). Add zero-cost neighbors to the front, one-cost neighbors to the back. Same answer, but faster.

8. Bellman-Ford & Floyd-Warshall — When Dijkstra Cannot Help

Bellman-Ford

Think of slowly relaxing a tight spring. Each round, you visit every road once and try to make distances a little bit smaller. After enough rounds, all distances settle.
  1. Set start distance to 0, everyone else to infinity.
  2. Repeat V−1 times: go through every edge, and if the path through it is shorter, update the destination's best distance.
  3. Do one more round. If anything still improves, there is a negative-cost cycle.
Use it when: negative edges exist, or the problem says "at most K stops" — then you do K+1 rounds.

Floyd-Warshall

Imagine asking, "for every pair of cities, what is the cheapest trip between them?". Floyd-Warshall fills out a giant table with that answer.
  1. Make a square table of best distances. Initially, the only known distances are direct edges.
  2. For each city K (try it as a possible "middle stop"), check every pair of cities (i, j) and ask: is going i → K → j cheaper than what we have? Update if yes.
  3. After trying every K as a middle stop, the table is full of best distances.
Cost: works only for small graphs (around 400 nodes or fewer). It checks all pairs, so it is slow.

9. MST — The Cheapest Way to Wire a City

You have to lay internet cables so every house has internet. You don't need every road to have a cable — you just need the cheapest set of cables that still keeps the whole city online. That is a Minimum Spanning Tree.

Kruskal — sort and pick

  1. List all roads with their costs.
  2. Sort the list cheapest first.
  3. Go down the list. Take a road if it joins two houses that are not yet connected. Skip if it would form a loop.
  4. Stop when every house is connected.

The "are they already connected" check is exactly what Union-Find is for.

Prim — grow from a seed

  1. Pick any house as your seed.
  2. Among all roads that touch the houses you've already taken, pick the cheapest one that goes to a new house.
  3. Add that house. Repeat until all houses are added.
Quick choice: if you have a list of edges, Kruskal is easier. If you have an adjacency list with many neighbors, Prim feels more natural.

10. Cycle Detection — Is There a Loop?

For undirected graphs (two-way roads)

While walking with DFS, if you bump into a node you've already visited and it is not the one you just came from, you've found a loop.

Or, with Union-Find: try to join the two ends of every edge. If both ends already have the same leader, this edge would create a loop.

For directed graphs (one-way roads)

Use three colors as you DFS:

ColorMeaning
WhiteNot seen yet.
GrayYou're currently inside this node's subtree (still walking through it).
BlackFully done with this node and everything below it.

If during DFS you ever step onto a gray node, you've walked into your own footprint — that is a cycle.

Easiest cycle test for directed graphs: just run topological sort. If you cannot place all nodes in order, there must be a cycle.

11. Bipartite Check — Two Teams Without Conflict

A school dance: you want to split kids into two teams so that every pair of friends sits on opposite teams. Possible only if no group of friends forms an odd-sized circle.

Steps

  1. Pick any node. Color it red.
  2. BFS from there. Color every neighbor blue, then their neighbors red, alternating.
  3. If you ever try to color a node and find it already has the wrong color, the graph cannot be split. Not bipartite.
  4. Repeat for any node not yet visited (the graph could have several components).

12. Common Mistakes (Learn From Others)

MistakeWhat goes wrongHow to avoid it
Marking visited too lateSame node enters the queue many times. Code becomes very slow.Always mark visited the moment a node enters the queue, never when it leaves.
Using Dijkstra with negative roadsWrong answers, silently.If any edge cost is negative, switch to Bellman-Ford.
Number overflow"Infinity + something" wraps around to a huge negative number.Skip the relax step if the source is still at infinity, or use a bigger number type.
Forgetting both directionsTwo-way roads end up being one-way.For undirected graphs, add the edge in both adjacency lists.
Recursion stack overflowDFS dies on a long chain of 100,000 nodes.Use an explicit stack instead of recursion when graphs are large.
Old, stale heap entries in DijkstraNodes are re-checked again and again.When you pop a node, check if its distance is still the best. If not, skip it.
Self-loops and parallel edgesCounted twice or cause infinite loops.Be explicit: ask the interviewer if these can exist; treat them carefully.

The Most-Asked Amazon Graph Problems — Theory & Tricks

For each problem: a real-life picture, the core idea, and the steps. No code, just understanding.

P1 — Number of Islands Medium DFS / BFS Flood Fill Amazon ★★★
Picture an aerial photo of the sea with a few patches of land. Two land cells are part of the same island only if they touch up, down, left, or right. Count how many separate land patches you can see.
Core idea: walk over every cell. Whenever you find land you have not seen, "paint" the entire island connected to it (so you don't count it again), and add 1 to your island counter.
  1. Loop through every cell of the grid.
  2. If the cell is land and unvisited, increment the island count.
  3. From that cell, dive into all 4 neighbors using DFS or BFS, marking each land cell visited.
  4. Continue the outer loop until done.
Trick: instead of a separate "visited" board, you can change every visited land cell to water as you walk. Saves memory.
P2 — Max Area of Island Medium DFS returning size
Same aerial photo. This time, find the biggest island.
Core idea: exactly like Number of Islands, but the DFS now returns how many land cells it painted. Track the largest number you have seen.
  1. Loop through cells.
  2. On each unvisited land cell, DFS and let it return the count of land cells in that island.
  3. Keep a running maximum.
P3 — Surrounded Regions Medium Reverse DFS from borders
A board of X's and O's. An O is "captured" only if it is fully ringed by X's. O groups touching the border escape.
Core idea — flip the question: instead of finding captured O's, find safe O's first. Any O that touches the border, plus anything connected to it, is safe. Everything else can be flipped.
  1. For every O on the border, run DFS and mark all reachable O's as "safe".
  2. Sweep the board: turn every unsafe O into X, and every safe mark back into O.
Trick name: "work from the easy frontier" — when the target is hard to detect, search from the border instead.
P4 — Walls and Gates Medium Multi-source BFS
A dungeon map. Some cells are gates, some are walls, the rest are empty rooms. For every empty room, write the distance to the nearest gate.
Core idea: doing BFS from every gate one by one is wasteful. Start BFS from all gates at once. The first time the wave reaches an empty room, that distance is the closest gate's distance.
  1. Put every gate cell into the queue at distance 0.
  2. Spread BFS one ring at a time. Update each empty cell to (distance + 1) when first seen.
  3. Stop when the queue is empty.
P5 — Rotting Oranges Medium Multi-source BFS + counting minutes Amazon ★★★
A grid of fresh and rotten oranges. Every minute, every rotten orange rots its 4 neighbors. How many minutes until all oranges rot? Or report it's impossible.
Core idea: all rotten oranges spread at the same time, so this is multi-source BFS. Each ring of BFS = one minute. If any fresh orange remains at the end, return -1.
  1. Count fresh oranges. Add all rotten oranges to the queue.
  2. Run BFS level by level. After each level, increase a "minutes" counter, and decrement the fresh count for every newly rotted orange.
  3. If fresh count is zero at the end, return minutes; otherwise return -1.
Watch out: handle the edge case "no fresh oranges to begin with" — the answer is 0, not -1.
P6 — Word Ladder Hard BFS on an invisible graph
Turn one word into another by changing one letter at a time, where every step must be a valid dictionary word. Shortest chain length, please.
Core idea: imagine each word is a node. Two words are neighbors if they differ in exactly one letter. The dictionary defines which words exist. Then it is just BFS for the shortest path.
  1. Put the starting word in a queue. Mark it visited.
  2. For the current word, try changing each position to every letter a–z. If the new word is in the dictionary and unvisited, add it to the queue.
  3. The first time you reach the target word, the BFS depth is your answer.
Speed-up: BFS from both ends at once (bidirectional). Two waves meeting in the middle finish much faster.
P7 — Clone Graph Medium DFS / BFS + a lookup map
You have a paper map of a city with all roads drawn. Make a perfect duplicate map, with new dots and new lines, that links the same way. Tricky part: the city has loops, so you must not redraw the same dot twice.
Core idea: walk the original graph; the moment you create a copy of a node, store it in a dictionary keyed by the original. Whenever you meet that original again, return the existing copy. This breaks loops naturally.
  1. If the original is null, return null.
  2. If you have already cloned it, return the saved clone.
  3. Otherwise, create a new node, save it in the map before looking at neighbors, then recursively clone each neighbor and link them.
Trick: save the clone in the map before recursing — otherwise a cycle will keep cloning forever.
P8 — Course Schedule Medium Topological Sort Amazon ★★★
Each course has prerequisites. Can you finish all courses? If yes, in what order?
Core idea: if the prerequisites form a graph with no cycle, you can finish. Topological sort both checks for cycles and gives an order.
  1. For each course, count how many prerequisites it has (in-degree).
  2. Put all courses with zero prerequisites into a queue.
  3. Take one out, add it to your order, and reduce the in-degree of every course that depended on it.
  4. Whenever a course's in-degree reaches zero, push it.
  5. If you placed all courses, you have a valid order. Otherwise, a cycle exists.
Trick: direction matters! If the input pair is "B is needed before A", the edge points B → A and you increase A's in-degree.
P9 — Alien Dictionary Hard Topological Sort on letters Amazon ★★★
You have a list of words written in an alien language, sorted alphabetically by the alien's rules. Figure out the alien's letter order.
Core idea: compare each pair of neighboring words letter by letter. The first letter where they differ tells you "this letter comes before that letter". These ordering rules form a directed graph. Topological sort gives the alphabet.
  1. Collect every letter that appears in any word.
  2. Walk through each pair of consecutive words. Compare letters one by one until you find the first difference; record that ordering edge.
  3. Edge case: if a word is a prefix of an earlier word (like "abc" before "ab"), the order is impossible.
  4. Run topological sort. If you can place every letter, that string is the alphabet. Otherwise return empty.
P10 — Pacific Atlantic Water Flow Medium Multi-source DFS from oceans
A grid of heights. Water flows from a cell to a neighbor if the neighbor is the same height or lower. The Pacific Ocean touches the top and left edges; the Atlantic touches the bottom and right edges. Find cells that drain into both oceans.
Core idea — flip it: instead of asking "from this cell, can water reach both oceans?", ask "starting at the ocean borders, which cells could send water to me?". Walk uphill from the borders.
  1. From every Pacific border cell, DFS uphill (only step to cells with equal or higher value). Mark all reached cells as "Pacific reachable".
  2. Do the same from Atlantic borders, marking "Atlantic reachable".
  3. The answer is every cell marked by both.
P11 — Number of Provinces Medium DFS or Union-Find
A square table tells you which cities are directly friendly. A "province" is a group of cities all reachable through friendships. Count provinces.
Core idea: count connected components. Either DFS each unvisited city, or union every friendly pair and count remaining groups.
  1. Walk through each city. If unvisited, DFS to mark every friend in the chain as visited; add 1 to the count.
  2. OR: use Union-Find — for every direct friendship, union the two cities. The number of distinct leaders is the answer.
P12 — Redundant Connection Medium Union-Find — first failed union
A tree of N nodes had one extra edge added, creating exactly one cycle. Find that extra edge.
Core idea: add edges one by one with Union-Find. The first edge that tries to connect two nodes already in the same group is the redundant one — adding it would form a loop.
  1. Start with N separate nodes.
  2. For each edge, try to union its two ends. If they already share a leader, that edge is the answer.
P13 — Accounts Merge Medium Union-Find on emails Amazon ★★★
You have multiple account entries for the same person, listed under different emails. If two accounts share even one email, they belong to the same person.
Core idea: treat every email as a node. Inside one account, union all emails together. Across accounts, shared emails will quietly merge groups. Then group emails by their leader and attach the owner's name.
  1. For each account, union the first email with each other email in the same account.
  2. Remember which name each email belongs to.
  3. After all unions, group emails by their leader, sort each group, prepend the name.
P14 — Network Delay Time Medium Dijkstra
A signal starts at one router and spreads to others along weighted links. How long until the slowest router gets it? If any router never gets it, return -1.
Core idea: shortest path from source to every other node. Dijkstra gives all those distances. The answer is the maximum among them.
  1. Run Dijkstra from the source.
  2. If any node still has distance infinity, return -1.
  3. Otherwise return the largest distance.
P15 — Cheapest Flights Within K Stops Medium Bellman-Ford rounds
Find the cheapest flight path from A to B, but you cannot take more than K stops in between.
Core idea: plain Dijkstra ignores the stop limit and may pick a too-long path. Bellman-Ford in K+1 rounds is perfect: each round can extend a path by one more flight.
  1. Set source distance to 0, others to infinity.
  2. Repeat K+1 times: take a snapshot of distances; for every flight, see if going through it improves the destination's distance using the snapshot. Only update from the snapshot to keep each round at one extra hop.
  3. Return the destination's final distance, or -1 if still infinity.
Watch out: using current distances directly (not a snapshot) lets one round chain many flights and breaks the K limit.
P16 — Path With Minimum Effort Medium Dijkstra with max instead of sum
A grid of heights. The "effort" of a path = the largest single height jump along it. Find the path from top-left to bottom-right with the smallest such largest jump.
Core idea: Dijkstra still works if the cost is "max of edge costs along the path" instead of sum, because max is also monotonic — extending a path never makes its max smaller.
  1. Track the best "effort" found to reach each cell.
  2. Use a min-heap, popping the cell with the smallest effort so far.
  3. For each neighbor, the new effort is the maximum of the current effort and the height jump to the neighbor. Update if smaller.
  4. Stop when you reach the destination.
Alternative: binary search on the answer + a simple BFS for "can I reach the end with all jumps ≤ guess?".
P17 — Swim in Rising Water Hard Dijkstra with max-along-path
A grid where each cell shows water depth. Each minute, water level rises by 1. You can step to a neighbor only when its depth is ≤ current water level. What is the earliest minute you can reach the bottom-right?
Core idea: the answer for any path is the maximum depth along it. Find the path that minimizes that maximum. Same shape as Min Effort.
  1. Use a min-heap holding (cell, max depth so far).
  2. Pop the smallest. For each neighbor, the new max is the larger of the current max and the neighbor's depth.
  3. The first time you pop the destination, that max is your answer.
P18 — Word Ladder II Hard BFS for layers + DFS to rebuild paths
Same as Word Ladder, but now find all shortest transformation paths.
Core idea: two-phase. First, BFS layer by layer until you reach the target, recording each word's parents in the previous layer. Second, DFS backwards from the target through the parent map to print every shortest path.
  1. Layer-by-layer BFS. For each new word, store the words from the previous layer that led to it.
  2. Stop when the target appears (finish the current layer to capture all parents at the same depth).
  3. DFS from the target back to the start using parents. Each completed walk is one shortest path.
P19 — Reconstruct Itinerary Hard Eulerian path (Hierholzer)
You have a stack of plane tickets and must use every single one exactly once, starting from JFK. If multiple orders work, choose the one that is alphabetically smallest at each choice.
Core idea: we want a path that uses every edge exactly once — that's an Eulerian path. Hierholzer's trick handles it.
  1. Sort each airport's outgoing destinations alphabetically.
  2. DFS from JFK: at each airport, fly to the alphabetically earliest unused ticket and remove it.
  3. When you get stuck, push the airport onto a "result" stack. Then back up.
  4. At the end, reverse the stack — that is your itinerary.
P20 — Critical Connections in a Network Hard Tarjan's bridges
A network of routers connected by cables. Find the cables whose failure would break the network into pieces. Those are the bridges.
Core idea: during DFS, give each node a "discovery time" (when it was first visited) and a "low" value (the earliest discovery time reachable through one back-edge). An edge is a bridge if no descendant on its other side can reach back above the parent.
  1. DFS from any node. Number nodes in order of visit.
  2. For each node, compute its low value as the minimum of its own discovery time and the low values of its children, including back-edges.
  3. For each tree edge (parent → child), if child's low value is bigger than parent's discovery time, that edge is a bridge.
P21 — Bus Routes Hard BFS over routes (not stops)
Each bus runs a fixed loop of stops. From your starting stop, find the minimum number of buses you must board to reach the target stop.
Core idea: the right "graph" here is not stops but buses. From a stop, you can hop on any bus that visits it. From any bus, you can ride to any stop on its route. BFS through buses gives the fewest transfers.
  1. Build a map: each stop → list of buses that visit it.
  2. Start BFS from your source stop. For each bus that visits a stop in your queue, mark that bus used. For every stop on that bus's route, if not yet seen, add it.
  3. Each layer of BFS is one extra bus used.
P22 — Shortest Path in Binary Matrix Medium BFS with 8 directions
A grid of 0s and 1s. You may walk on 0s, including diagonally (8 directions). Find the shortest path from top-left to bottom-right.
Core idea: all moves cost the same, so plain BFS does it. The only twist is using 8 neighbor offsets instead of 4.
  1. If the start or end cell is blocked, return -1.
  2. BFS from the start; mark cells visited as you enqueue.
  3. The depth at which you first reach the end is the answer.
P23 — Min Cost to Connect All Points Medium MST (Prim or Kruskal)
A bunch of points on a 2D map. The cost of connecting two points = their Manhattan distance. Connect all of them with minimum total cost.
Core idea: classic Minimum Spanning Tree. Either build the list of all pairwise distances and use Kruskal, or grow the tree from a starting point with Prim.
  1. Compute the cost of every possible connection (or compute on the fly if too many).
  2. Sort edges and add cheapest first while not forming a cycle (Kruskal). OR maintain "cheapest known distance to set" for each remaining point and always add the closest one (Prim).
  3. Stop when all points are connected. Sum of chosen costs is the answer.
P24 — Is Graph Bipartite Medium BFS 2-coloring
Can you split every node into two teams so that no edge goes inside the same team?
Core idea: color one node, then alternate colors as you BFS. A conflict (two neighbors same color) means it is impossible.
  1. Pick an unvisited node. Color it 1.
  2. BFS; color each neighbor with the opposite color of the current node.
  3. If you ever try to color a neighbor a different color from what it has, return false.
  4. Repeat for every component.
P25 — Reorder Routes to Make All Paths Lead to City Zero Medium DFS with edge orientation
A directed road network. You want every city to be able to reach city 0. Some roads point the wrong way and must be flipped. Count the minimum flips.
Core idea: store each road in both directions, but mark "real direction" as cost 1 (would need flipping) and "reverse" as cost 0 (free). Then DFS from city 0 outward; sum the costs you encounter.
  1. Build an adjacency list with two entries per road: original (cost 1) and reverse (cost 0).
  2. DFS from node 0, summing the cost of every edge taken to a new node.
  3. The total is the number of flips needed.

Final Tricky Round — 8 Conceptual Gotchas

Q1. All edges have positive costs. Why isn't BFS enough?
Reveal hint
BFS counts steps, not costs. A 2-step path costing 100 will be returned before a 5-step path costing 10. When costs are not equal, you need Dijkstra to always pick the cheapest path so far.
Q2. Why does Dijkstra fail if even one edge has a negative cost?
Reveal hint
Dijkstra "locks in" a node's distance the moment it's pulled from the heap, assuming nothing cheaper can be found later. With negative edges, a longer path can become cheaper later — but the node is already locked. Bellman-Ford handles negatives because it keeps re-checking every edge.
Q3. Why does Kahn's topological sort spot cycles for free?
Reveal hint
Kahn's repeatedly removes nodes whose in-degree is 0. Nodes inside a cycle never reach in-degree 0 because they always have an incoming edge from another cycle member. So if fewer nodes were placed than total, a cycle exists.
Q4. In Cheapest Flights with K stops, why doesn't Dijkstra work?
Reveal hint
Dijkstra finds the cheapest path overall, but that path might use too many stops. A pricier path with fewer stops could be the only valid one. Either include "stops used" in the state, or switch to Bellman-Ford with K+1 rounds.
Q5. Why must we mark visited at enqueue time, not dequeue time?
Reveal hint
If you wait until pulling the node out, the same node can be added many times by many neighbors before being processed. That blows up time and memory. Marking at enqueue ensures every node is added exactly once — the whole reason BFS is fast.
Q6. Multi-source BFS — why is starting from all sources at once correct?
Reveal hint
Imagine adding a fake "super source" with zero-cost roads to each real source. BFS from the super source gives every node its distance to the nearest real source — exactly what the problem wants — in one pass instead of K passes.
Q7. In Tarjan's bridge-finding, what does the "low" number mean?
Reveal hint
It is the earliest-discovered node reachable from this subtree using regular tree edges plus at most one back-edge. If a child's low value is still bigger than its parent's discovery time, no back-edge climbs above the parent — meaning the only way out of the child's subtree is through that parent edge. So that edge is a bridge.
Q8. Union-Find — what makes path compression so powerful?
Reveal hint
Each time you find a leader, you flatten the chain by pointing every node directly to the top. Future calls become almost instant. Combined with union-by-rank, the average operation cost becomes practically constant time.
