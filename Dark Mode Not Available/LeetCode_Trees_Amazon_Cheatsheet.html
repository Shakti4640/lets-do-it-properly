0. The Standard TreeNode & Setup

// LeetCode's canonical binary tree node — memorize it.
class TreeNode {
    int val;
    TreeNode left, right;
    TreeNode() {}
    TreeNode(int val) { this.val = val; }
    TreeNode(int val, TreeNode left, TreeNode right) {
        this.val = val; this.left = left; this.right = right;
    }
}
Interview habit: always ask the interviewer "can the tree be empty? can node values be negative? are values unique?" before coding. These three answers change the recursion base case and edge handling.

2. The 5 Core Patterns That Cover ~90% of Tree Problems

#PatternTrigger phrases in problemSkeleton
1Top-Down DFS
(pass info down)		 "path from root", "running sum", "depth of node" dfs(node, accumulatedFromRoot)
2Bottom-Up DFS / Tree DP
(return info up)		 "max/min over all paths", "diameter", "longest", "balanced" int dfs(node) → returns summary; combine L, R
3BFS / Level Order "level by level", "right view", "minimum depth", "zigzag" Queue<TreeNode> q; while(!q.empty()) for size...
4BST Inorder Trick "BST", "kth smallest", "validate", "convert to sorted" Inorder traversal yields ascending values.
5Re-rooting / Graph-ify "distance K from a node", "path between two nodes" without parent pointer Build Map<TreeNode, TreeNode> parent, then BFS.
Pattern picker (30-second decision):
1. Question asks about levels or breadth? → BFS.
2. Question asks for a global maximum/minimum across the whole tree? → Bottom-up DFS, keep a class-level best.
3. Question gives me state that grows from root (sum so far, path so far)? → Top-down DFS with extra params.
4. Word "BST" appears? → Try inorder first.
5. Need to move up the tree or sideways? → Build parent map.

3. The Recursion Mental Model

For every recursive function on a tree, answer three questions:

  1. Base case: what do I do when node == null? (Usually return 0, true, or null.)
  2. Recursive call: what do I ask my left child and right child to compute?
  3. Combine: how do I merge those answers + my own value into my answer?
// Universal bottom-up template
int dfs(TreeNode node) {
    if (node == null) return 0;        // (1) base
    int L = dfs(node.left);            // (2) ask left
    int R = dfs(node.right);           // (2) ask right
    // (optional) update a global answer using L, R, node.val
    return /* combined value to give to my parent */;
}
Q. Why do many tree solutions use a int[1] best = {Integer.MIN_VALUE}; or class field instead of returning the answer?
Reveal hint
Because the value returned to the parent (e.g., max single-side path sum) and the global answer you ultimately report (e.g., max path sum that bends through this node) are different quantities. Capture the global one in a side-channel.

4. Traversals — DFS & BFS

1 / \ 2 3 / \ \ 4 5 6 Preorder (Root,L,R): 1 2 4 5 3 6 Inorder (L,Root,R): 4 2 5 1 3 6 ← BST sorted order Postorder (L,R,Root): 4 5 2 6 3 1 ← bottom-up evaluation Level (BFS): 1 2 3 4 5 6 
// Preorder DFS (recursive)
void pre(TreeNode n, List<Integer> out) {
    if (n == null) return;
    out.add(n.val);
    pre(n.left, out);
    pre(n.right, out);
}

// BFS / Level order
List<List<Integer>> levelOrder(TreeNode root) {
    List<List<Integer>> res = new ArrayList<>();
    if (root == null) return res;
    Deque<TreeNode> q = new ArrayDeque<>();
    q.offer(root);
    while (!q.isEmpty()) {
        int size = q.size();
        List<Integer> level = new ArrayList<>(size);
        for (int i = 0; i < size; i++) {
            TreeNode n = q.poll();
            level.add(n.val);
            if (n.left  != null) q.offer(n.left);
            if (n.right != null) q.offer(n.right);
        }
        res.add(level);
    }
    return res;
}
"Process by level" trick: always snapshot q.size() at the start of the while-loop. That gives you the count of nodes at the current level — the secret behind right-view, zigzag, average-of-levels, min-depth, etc.

5. Iterative Traversals (when recursion stack is a concern)

// Iterative inorder — perfect for "Kth smallest in BST"
void inorderIterative(TreeNode root) {
    Deque<TreeNode> stk = new ArrayDeque<>();
    TreeNode cur = root;
    while (cur != null || !stk.isEmpty()) {
        while (cur != null) { stk.push(cur); cur = cur.left; }   // go left
        cur = stk.pop();
        // visit cur.val here
        cur = cur.right;
    }
}
Morris traversal (O(1) space) exists, but in an Amazon round, recognizing iterative inorder + stack is enough. Mention Morris only if asked for O(1) space.

6. BST Properties — The Hidden Superpower

PropertyImplication
Inorder = sorted"Validate BST", "Kth smallest", "Recover BST" all reduce to "scan an almost-sorted list".
Search/insert/deleteO(h). h = log n if balanced, n if skewed.
LCA via valuesIf p.val and q.val straddle node.val, node is LCA.
Range queries"Sum of nodes in [L,R]" prunes whole subtrees by comparing node.val to L/R.
Q. To validate a BST, why is "left.val < node.val < right.val" not enough?
Reveal hint
It only checks immediate children, not the whole subtree. A right grandchild could be smaller than the root. Carry (min, max) bounds down, OR do an inorder traversal and check it's strictly increasing.

7. Tree DP — The Pattern That Wins Hard Problems

Most "max ___ in a tree" problems share a body:

int best;                 // global answer (often Integer.MIN_VALUE)

int dfs(TreeNode node) {
    if (node == null) return 0;
    int L = Math.max(0, dfs(node.left));   // ignore negative branches
    int R = Math.max(0, dfs(node.right));
    best = Math.max(best, L + R + node.val); // path that bends here
    return Math.max(L, R) + node.val;        // path that continues up
}
Two-channel rule: the function returns the "extendable" answer (what a parent could continue), and updates best with the "terminating-here" answer (what cannot be extended further).

8. Common Pitfalls

PitfallWrongRight
Empty treeForget if (root == null) return ... on entry.Always handle null root explicitly. Often the first line of the method.
Negative valuesTree DP that assumes all positives.Use Math.max(0, dfs(child)) only when problem allows skipping a branch.
Comparing node refsUsing == for value equality.Use n1.val == n2.val for primitive int values; == is correct for identity (e.g., LCA finds the same node).
Mutating shared stateBacktracking List<Integer> path but adding it to result by reference.Add new ArrayList<>(path) when recording.
Stack overflowRecursing on a 50,000-deep skewed tree.Convert to iterative with explicit stack/queue, or note JVM stack size limits.
Inorder + global varForgetting to reset prev/count between test cases.Avoid static fields in LeetCode submissions; use instance fields or pass arrays.

P1 — Maximum Depth of Binary Tree (LC 104) Easy Bottom-Up DFS
Why asked: warm-up. Tests if you can write the recursion mental model cleanly.
Intuition: depth of a tree = 1 + max(depth of left, depth of right). Null tree has depth 0.
How: classic bottom-up DFS — three lines.
int maxDepth(TreeNode root) {
    if (root == null) return 0;
    return 1 + Math.max(maxDepth(root.left), maxDepth(root.right));
}
Twist: "minimum depth" (LC 111) is not symmetric — a node with only one child is not a leaf, so don't take min over a 0-side. Use BFS for early termination.
P2 — Same Tree (LC 100) Easy Parallel DFS
Intuition: two trees are equal iff roots equal AND left subtrees equal AND right subtrees equal. Both null is the success base case.
boolean isSameTree(TreeNode p, TreeNode q) {
    if (p == null && q == null) return true;
    if (p == null || q == null) return false;
    return p.val == q.val
        && isSameTree(p.left,  q.left)
        && isSameTree(p.right, q.right);
}
Trick: the order of the two null checks matters — both-null first, then either-null.
P3 — Symmetric Tree (LC 101) Easy Mirrored DFS
Intuition: a tree is symmetric iff its left subtree is the mirror of its right. To compare mirrors, recurse on (L.left, R.right) and (L.right, R.left).
boolean isSymmetric(TreeNode root) {
    return root == null || mirror(root.left, root.right);
}
boolean mirror(TreeNode a, TreeNode b) {
    if (a == null && b == null) return true;
    if (a == null || b == null) return false;
    return a.val == b.val
        && mirror(a.left,  b.right)
        && mirror(a.right, b.left);
}
P4 — Invert Binary Tree (LC 226) Easy Post-order swap
Intuition: recursively invert both subtrees, then swap the children of the current node. (Famously the "Homebrew interview" question.)
TreeNode invertTree(TreeNode root) {
    if (root == null) return null;
    TreeNode L = invertTree(root.left);
    TreeNode R = invertTree(root.right);
    root.left = R; root.right = L;
    return root;
}
P5 — Diameter of Binary Tree (LC 543) Easy Tree DP (two-channel)
Intuition: the diameter is the longest path between any two nodes. For each node, the longest path that bends at it = height(L) + height(R). Return max-side-height upward; track best globally.
int best = 0;
int diameterOfBinaryTree(TreeNode root) { height(root); return best; }
int height(TreeNode n) {
    if (n == null) return 0;
    int L = height(n.left), R = height(n.right);
    best = Math.max(best, L + R);          // edges, not nodes
    return 1 + Math.max(L, R);
}
Trick: diameter is counted in edges, so don't add 1 when updating best.
P6 — Path Sum / Path Sum II (LC 112 / 113) Easy / Medium Top-Down DFS + Backtracking
Intuition: root-to-leaf sum = subtract node value from target as you descend. Leaf hit + remainder == 0 ⇒ found. For "all such paths" version, carry a path list and backtrack.
// LC 113 — return all root-to-leaf paths summing to target
List<List<Integer>> pathSum(TreeNode root, int target) {
    List<List<Integer>> res = new ArrayList<>();
    dfs(root, target, new ArrayList<>(), res);
    return res;
}
void dfs(TreeNode n, int rem, List<Integer> path, List<List<Integer>> res) {
    if (n == null) return;
    path.add(n.val);
    if (n.left == null && n.right == null && rem == n.val)
        res.add(new ArrayList<>(path));    // copy!
    dfs(n.left,  rem - n.val, path, res);
    dfs(n.right, rem - n.val, path, res);
    path.remove(path.size() - 1);          // backtrack
}
Trick: add new ArrayList<>(path) on the success line — otherwise every entry in res points to the same (eventually empty) list.
P7 — Binary Tree Level Order Traversal (LC 102) Medium BFS
Intuition: standard BFS template. The "snapshot q.size()" pattern groups nodes by level.
List<List<Integer>> levelOrder(TreeNode root) {
    List<List<Integer>> res = new ArrayList<>();
    if (root == null) return res;
    Deque<TreeNode> q = new ArrayDeque<>();
    q.offer(root);
    while (!q.isEmpty()) {
        int sz = q.size();
        List<Integer> lvl = new ArrayList<>(sz);
        for (int i = 0; i < sz; i++) {
            TreeNode n = q.poll();
            lvl.add(n.val);
            if (n.left  != null) q.offer(n.left);
            if (n.right != null) q.offer(n.right);
        }
        res.add(lvl);
    }
    return res;
}
Variants spawned from this skeleton: Zigzag (LC 103) reverse alternate levels; Average per level (LC 637); Largest in each level (LC 515).
P8 — Binary Tree Right Side View (LC 199) Medium BFS — last node per level
Intuition: right-side view = the rightmost node at every level. Run level-order BFS; record the last node of each level.
List<Integer> rightSideView(TreeNode root) {
    List<Integer> res = new ArrayList<>();
    if (root == null) return res;
    Deque<TreeNode> q = new ArrayDeque<>();
    q.offer(root);
    while (!q.isEmpty()) {
        int sz = q.size();
        for (int i = 0; i < sz; i++) {
            TreeNode n = q.poll();
            if (i == sz - 1) res.add(n.val);   // rightmost
            if (n.left  != null) q.offer(n.left);
            if (n.right != null) q.offer(n.right);
        }
    }
    return res;
}
DFS alternative: visit right child first, record at depth equal to res.size().
P9 — Validate Binary Search Tree (LC 98) Medium BST bounds DFS
Intuition: a node must satisfy min < node.val < max. As you descend left, the upper bound becomes the parent's value; descending right, the lower bound becomes the parent's value. Use Long to avoid Integer.MIN_VALUE edge cases.
boolean isValidBST(TreeNode root) { return check(root, Long.MIN_VALUE, Long.MAX_VALUE); }
boolean check(TreeNode n, long lo, long hi) {
    if (n == null) return true;
    if (n.val <= lo || n.val >= hi) return false;
    return check(n.left, lo, n.val) && check(n.right, n.val, hi);
}
Alt: inorder traversal + verify strictly increasing. Either is acceptable; bounds version is shorter.
P10 — LCA of Binary Tree (LC 236) Medium Bottom-Up DFS Amazon ★★★
Intuition: recursion returns "did I find p or q in this subtree?". If both subtrees return non-null, the current node is the LCA. Otherwise propagate the non-null one up.
TreeNode lowestCommonAncestor(TreeNode root, TreeNode p, TreeNode q) {
    if (root == null || root == p || root == q) return root;
    TreeNode L = lowestCommonAncestor(root.left,  p, q);
    TreeNode R = lowestCommonAncestor(root.right, p, q);
    if (L != null && R != null) return root;   // split here ⇒ LCA
    return L != null ? L : R;
}
Trick: works because of the assumption that p and q both exist in the tree. If not guaranteed, do a post-pass to verify.
P11 — LCA of BST (LC 235) Easy BST property walk
Intuition: in a BST, the first node whose value lies between p.val and q.val (inclusive) is their LCA. Walk down from root.
TreeNode lcaBST(TreeNode root, TreeNode p, TreeNode q) {
    int lo = Math.min(p.val, q.val), hi = Math.max(p.val, q.val);
    while (root != null) {
        if (root.val < lo)      root = root.right;
        else if (root.val > hi) root = root.left;
        else return root;
    }
    return null;
}
P12 — Serialize / Deserialize Binary Tree (LC 297) Hard Preorder + null markers Amazon ★★★
Intuition: a preorder traversal is enough iff we record nulls explicitly. On deserialize, consume tokens in the same preorder.
// Serialize
String serialize(TreeNode root) {
    StringBuilder sb = new StringBuilder();
    ser(root, sb);
    return sb.toString();
}
void ser(TreeNode n, StringBuilder sb) {
    if (n == null) { sb.append("# "); return; }
    sb.append(n.val).append(' ');
    ser(n.left, sb);
    ser(n.right, sb);
}
// Deserialize
TreeNode deserialize(String s) {
    Deque<String> q = new ArrayDeque<>(Arrays.asList(s.split(" ")));
    return de(q);
}
TreeNode de(Deque<String> q) {
    String t = q.poll();
    if (t.equals("#")) return null;
    TreeNode n = new TreeNode(Integer.parseInt(t));
    n.left  = de(q);
    n.right = de(q);
    return n;
}
Trick: using a Deque as a token stream avoids passing an index by reference. Inorder alone is not enough — duplicate / null structure is ambiguous.
P13 — Binary Tree Maximum Path Sum (LC 124) Hard Tree DP — two-channel Amazon ★★★
Intuition: classic two-channel DP. Each call returns the best extendable path going through this node down one side. The bend (L + node + R) updates the global maximum and is not returned (a parent can't continue a bent path).
int best = Integer.MIN_VALUE;
int maxPathSum(TreeNode root) { gain(root); return best; }
int gain(TreeNode n) {
    if (n == null) return 0;
    int L = Math.max(0, gain(n.left));
    int R = Math.max(0, gain(n.right));
    best = Math.max(best, n.val + L + R);  // bent path through n
    return n.val + Math.max(L, R);         // straight path returned to parent
}
Trick: initialize best to Integer.MIN_VALUE — values can be negative and a valid path of one node is allowed.
P14 — Construct Tree from Preorder + Inorder (LC 105) Medium Recursion + index map
Intuition: preorder[0] is the root. Find that value's index in inorder — left of it is the left subtree, right is the right subtree. Recurse with corresponding slices. Use a hashmap of value→inorder-index for O(1) lookup.
Map<Integer,Integer> idx = new HashMap<>();
int p = 0;                                   // pointer into preorder
public TreeNode buildTree(int[] pre, int[] in) {
    for (int i = 0; i < in.length; i++) idx.put(in[i], i);
    return build(pre, 0, in.length - 1);
}
TreeNode build(int[] pre, int lo, int hi) {
    if (lo > hi) return null;
    int rootVal = pre[p++];
    TreeNode root = new TreeNode(rootVal);
    int mid = idx.get(rootVal);
    root.left  = build(pre, lo, mid - 1);
    root.right = build(pre, mid + 1, hi);
    return root;
}
Assumes values are unique. Without uniqueness, the inorder index is ambiguous.
P15 — Subtree of Another Tree (LC 572) Easy DFS + Same-tree check
Intuition: for every node in root, ask "is the subtree rooted here identical to subRoot?". Reuse the Same-Tree helper.
boolean isSubtree(TreeNode root, TreeNode sub) {
    if (root == null) return false;
    if (sameTree(root, sub)) return true;
    return isSubtree(root.left, sub) || isSubtree(root.right, sub);
}
boolean sameTree(TreeNode a, TreeNode b) {
    if (a == null && b == null) return true;
    if (a == null || b == null) return false;
    return a.val == b.val
        && sameTree(a.left, b.left)
        && sameTree(a.right, b.right);
}
Faster alt: serialize both trees with null markers and use string contains — O(n+m).
P16 — Kth Smallest Element in BST (LC 230) Medium Iterative inorder
Intuition: inorder of a BST yields ascending values. Stop after k pops.
int kthSmallest(TreeNode root, int k) {
    Deque<TreeNode> stk = new ArrayDeque<>();
    TreeNode cur = root;
    while (cur != null || !stk.isEmpty()) {
        while (cur != null) { stk.push(cur); cur = cur.left; }
        cur = stk.pop();
        if (--k == 0) return cur.val;
        cur = cur.right;
    }
    return -1; // unreachable if k is valid
}
Follow-up Amazon loves: "if BST is modified often, how do you make kth-smallest O(log n)?" — augment each node with subtree size.
P17 — Vertical Order Traversal (LC 314 / LC 987) Medium / Hard BFS + column index Amazon ★★
Intuition: assign column 0 to root, column−1 to left, column+1 to right. Group nodes by column. Use BFS for top-to-bottom, left-to-right ordering.
List<List<Integer>> verticalOrder(TreeNode root) {
    List<List<Integer>> res = new ArrayList<>();
    if (root == null) return res;
    TreeMap<Integer, List<Integer>> cols = new TreeMap<>();
    Deque<int[]> q = new ArrayDeque<>();
    Map<TreeNode, Integer> colOf = new HashMap<>();   // optional, see below
    Deque<TreeNode> nq = new ArrayDeque<>();
    nq.offer(root); colOf.put(root, 0);
    while (!nq.isEmpty()) {
        TreeNode n = nq.poll();
        int c = colOf.get(n);
        cols.computeIfAbsent(c, k -> new ArrayList<>()).add(n.val);
        if (n.left  != null) { nq.offer(n.left);  colOf.put(n.left,  c - 1); }
        if (n.right != null) { nq.offer(n.right); colOf.put(n.right, c + 1); }
    }
    res.addAll(cols.values());
    return res;
}
LC 987 twist: tie-break within the same (row, column) by node value — then you need to sort per cell. Switch to (col, row, val) tuples and sort lexicographically.
P18 — All Nodes Distance K from Target (LC 863) Medium Re-root: tree → graph → BFS Amazon ★★
Intuition: a binary tree only has child pointers, but we need to walk in three directions (left, right, parent). Build a parent map first, then BFS from target, treating it as an undirected graph.
List<Integer> distanceK(TreeNode root, TreeNode target, int k) {
    Map<TreeNode, TreeNode> par = new HashMap<>();
    buildParents(root, null, par);
    Deque<TreeNode> q = new ArrayDeque<>();
    Set<TreeNode> seen = new HashSet<>();
    q.offer(target); seen.add(target);
    int dist = 0;
    while (!q.isEmpty()) {
        if (dist == k) {
            List<Integer> out = new ArrayList<>();
            for (TreeNode n : q) out.add(n.val);
            return out;
        }
        int sz = q.size();
        for (int i = 0; i < sz; i++) {
            TreeNode n = q.poll();
            for (TreeNode nb : new TreeNode[]{n.left, n.right, par.get(n)}) {
                if (nb != null && seen.add(nb)) q.offer(nb);
            }
        }
        dist++;
    }
    return new ArrayList<>();
}
void buildParents(TreeNode n, TreeNode p, Map<TreeNode,TreeNode> par) {
    if (n == null) return;
    par.put(n, p);
    buildParents(n.left,  n, par);
    buildParents(n.right, n, par);
}
P19 — Count Good Nodes (LC 1448) Medium Top-Down DFS — carry running max
Intuition: a node X is "good" if no node on the path from root to X has a value greater than X.val. Carry the max-so-far down the tree.
int goodNodes(TreeNode root) { return dfs(root, Integer.MIN_VALUE); }
int dfs(TreeNode n, int maxSoFar) {
    if (n == null) return 0;
    int count = (n.val >= maxSoFar) ? 1 : 0;
    int newMax = Math.max(maxSoFar, n.val);
    return count + dfs(n.left, newMax) + dfs(n.right, newMax);
}
P20 — Path Sum III (LC 437) Medium Prefix-sum + DFS
Intuition: count downward paths with a given sum (don't have to start at root). Brute force is O(n²). Smarter: maintain a running prefix sum from root; the number of paths ending at the current node with sum target equals the count of seen prefix sums equal to currSum − target. Backtrack the map on the way up.
Map<Long, Integer> freq = new HashMap<>();
int target;
int pathSum(TreeNode root, int targetSum) {
    target = targetSum;
    freq.put(0L, 1);                 // empty prefix
    return dfs(root, 0L);
}
int dfs(TreeNode n, long curr) {
    if (n == null) return 0;
    curr += n.val;
    int found = freq.getOrDefault(curr - target, 0);
    freq.merge(curr, 1, Integer::sum);
    found += dfs(n.left, curr) + dfs(n.right, curr);
    freq.merge(curr, -1, Integer::sum);   // backtrack
    return found;
}
Trick: use long for the prefix sum — values can be up to 10⁹ and depth up to 1000.
P21 — Flatten Binary Tree to Linked List (LC 114) Medium Reverse-preorder DFS
Intuition: we want preorder order in the right pointers. Walk in reverse preorder (right, left, root) and chain every node to the previously visited one.
TreeNode prev = null;
void flatten(TreeNode root) {
    if (root == null) return;
    flatten(root.right);
    flatten(root.left);
    root.right = prev;
    root.left = null;
    prev = root;
}
O(1) space alt: Morris-like — for each node, find left subtree's rightmost, splice right into it, move right.
P22 — Implement Trie (LC 208) Medium Prefix Tree Amazon ★★
Intuition: a trie node holds an array of 26 children + an isEnd flag. Insert / search / startsWith all walk character by character.
class Trie {
    static class Node { Node[] ch = new Node[26]; boolean end; }
    private final Node root = new Node();

    public void insert(String w) {
        Node cur = root;
        for (char c : w.toCharArray()) {
            int i = c - 'a';
            if (cur.ch[i] == null) cur.ch[i] = new Node();
            cur = cur.ch[i];
        }
        cur.end = true;
    }
    public boolean search(String w)     { Node n = walk(w); return n != null && n.end; }
    public boolean startsWith(String p) { return walk(p) != null; }
    private Node walk(String s) {
        Node cur = root;
        for (char c : s.toCharArray()) {
            cur = cur.ch[c - 'a'];
            if (cur == null) return null;
        }
        return cur;
    }
}
When to use: autocomplete, longest common prefix, problems with a dictionary of words you'll query repeatedly.
P23 — Word Search II (LC 212) Hard Trie + DFS backtracking Amazon ★★
Intuition: doing a DFS per word from every cell is O(W · M·N · 4ᴸ). Build a trie of all words; one DFS per starting cell now follows trie edges, pruning aggressively. Mark cells visited; remove found words from the trie to avoid duplicates.
static class TN { TN[] ch = new TN[26]; String word; }
public List<String> findWords(char[][] board, String[] words) {
    TN root = new TN();
    for (String w : words) {                         // build trie
        TN cur = root;
        for (char c : w.toCharArray()) {
            int i = c - 'a';
            if (cur.ch[i] == null) cur.ch[i] = new TN();
            cur = cur.ch[i];
        }
        cur.word = w;
    }
    List<String> res = new ArrayList<>();
    for (int r = 0; r < board.length; r++)
        for (int c = 0; c < board[0].length; c++)
            dfs(board, r, c, root, res);
    return res;
}
void dfs(char[][] b, int r, int c, TN node, List<String> res) {
    char ch = b[r][c];
    if (ch == '#' || node.ch[ch - 'a'] == null) return;
    node = node.ch[ch - 'a'];
    if (node.word != null) { res.add(node.word); node.word = null; }   // de-dup
    b[r][c] = '#';
    if (r > 0)               dfs(b, r - 1, c, node, res);
    if (r < b.length - 1)    dfs(b, r + 1, c, node, res);
    if (c > 0)               dfs(b, r, c - 1, node, res);
    if (c < b[0].length - 1) dfs(b, r, c + 1, node, res);
    b[r][c] = ch;                                                      // backtrack
}
P24 — Boundary of Binary Tree (LC 545) Medium 3-pass DFS Amazon ★
Intuition: boundary = root + left boundary (top→bottom, excluding leaves) + all leaves (left→right) + right boundary (bottom→top, excluding leaves). Three traversals composed.
List<Integer> boundaryOfBinaryTree(TreeNode root) {
    List<Integer> res = new ArrayList<>();
    if (root == null) return res;
    if (!isLeaf(root)) res.add(root.val);
    addLeftBoundary(root.left, res);
    addLeaves(root, res);
    addRightBoundary(root.right, res);
    return res;
}
boolean isLeaf(TreeNode n) { return n.left == null && n.right == null; }
void addLeftBoundary(TreeNode n, List<Integer> res) {
    while (n != null) {
        if (!isLeaf(n)) res.add(n.val);
        n = (n.left != null) ? n.left : n.right;
    }
}
void addRightBoundary(TreeNode n, List<Integer> res) {
    Deque<Integer> stk = new ArrayDeque<>();
    while (n != null) {
        if (!isLeaf(n)) stk.push(n.val);
        n = (n.right != null) ? n.right : n.left;
    }
    while (!stk.isEmpty()) res.add(stk.pop());
}
void addLeaves(TreeNode n, List<Integer> res) {
    if (n == null) return;
    if (isLeaf(n)) { res.add(n.val); return; }
    addLeaves(n.left, res);
    addLeaves(n.right, res);
}
P25 — BST Iterator (LC 173) Medium Controlled iterative inorder
Intuition: the in-progress stack of iterative inorder is the iterator state. next() = pop, push right's left chain. hasNext() = stack non-empty. Average O(1) per call, O(h) space.
class BSTIterator {
    private final Deque<TreeNode> stk = new ArrayDeque<>();
    public BSTIterator(TreeNode root) { pushLeft(root); }
    public int next() {
        TreeNode n = stk.pop();
        pushLeft(n.right);
        return n.val;
    }
    public boolean hasNext() { return !stk.isEmpty(); }
    private void pushLeft(TreeNode n) {
        while (n != null) { stk.push(n); n = n.left; }
    }
}

Final Tricky Round — 8 Conceptual Gotchas

Q1. You compute height recursively; the input is a 100,000-node skewed tree. What goes wrong and how do you fix it?
Reveal hint
StackOverflowError on the JVM (default thread stack ~512KB → ~10⁴ frames). Convert to an iterative postorder using an explicit stack, or process in chunks. In an Amazon round, name the issue before writing the recursion.
Q2. In LCA (LC 236), why does returning the first non-null subtree result work even though we only check up to one level?
Reveal hint
Because once we encounter the LCA, that node bubbles up unchanged: above it, exactly one side is null and the other is the LCA reference, so the function just keeps returning that reference all the way to the root.
Q3. In LC 124 (Max Path Sum), why Math.max(0, gain(child)) instead of just gain(child)?
Reveal hint
If a subtree's best contribution is negative, we'd rather skip it than drag the path down. Clamping at 0 means "don't extend through this side". The bend update (L + R + node.val) still considers all combinations.
Q4. Validate BST: why use Long bounds, not Integer?
Reveal hint
Because a node's value can be Integer.MIN_VALUE or MAX_VALUE. With int bounds you can't express "strictly less than Integer.MIN_VALUE" without underflow. Use Long.MIN_VALUE / Long.MAX_VALUE, or use Integer objects with null sentinels.
Q5. Why can't you reconstruct a binary tree from preorder + postorder alone (without uniqueness or more info)?
Reveal hint
Pre + post is ambiguous when a node has only one child — you can't tell if it's a left-only or right-only child. Pre+In or Post+In disambiguates because inorder pinpoints where the root splits the array.
Q6. In Path Sum III (LC 437), why does the prefix-sum map need to be backtracked?
Reveal hint
Because a prefix sum belongs only to one root-to-node path. When you return up the recursion, that prefix should no longer be a candidate "starting point" for sibling subtrees, otherwise you'll miscount paths that don't actually exist along a single chain.
Q7. Why does a Trie use Node[26] arrays instead of a HashMap?
Reveal hint
Lower-case English alphabet has fixed size 26, so an array gives O(1) access with predictable cache behavior and zero hashing overhead. Use a Map<Character,Node> only when the alphabet is large or unknown (Unicode, file paths, etc.).
Q8. Serializing a tree as inorder alone — why is that not enough to deserialize?
Reveal hint
Inorder doesn't tell you which node is the root — many different trees produce the same inorder sequence. You need either preorder (with null markers) or a second traversal (in + pre) to anchor the structure.
