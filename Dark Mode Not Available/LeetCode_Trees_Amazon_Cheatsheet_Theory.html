0. What is a Tree? (The Real-Life Picture)

Picture an upside-down tree. The single trunk on top is the root. Each branching point is a node. The very tips with no branches are leaves. Every node (except the root) has exactly one parent above it.

A binary tree is the most common kind in coding interviews — every node has at most two children, called left and right. There is no left-right meaning beyond labeling, until we add a rule (like in a BST).

1 ← root / \ 2 3 ← children of root / \ \ 4 5 6 ← leaves

Key idea: a tree has no loops

Unlike a graph, a tree never circles back. From the root you can reach every node by exactly one path. That is what lets recursion work so naturally on trees.

Interview habit: before writing any code, ask three things:
  1. Can the tree be empty (root null)?
  2. Can node values be negative or zero?
  3. Are values unique, or can they repeat?
The answers change your base case and your edge cases.

  1. Question is about levels or breadth? → BFS.
  2. Question wants a global maximum/minimum across the whole tree? → Bottom-up DFS, with a global "best" tracker.
  3. Question is about state that grows from root (running sum, current path)? → Top-down DFS.
  4. Word "BST"? → Try inorder traversal first.
  5. Need to walk up from a node or move sideways? → Build a parent map and BFS like a graph.

3. The Recursion Mental Model

For any recursive function on a tree, always answer three questions:

  1. Base case: what do I return when the node is null? Usually 0, true, or null.
  2. Recursive call: what do I ask my left child and right child to compute?
  3. Combine: how do I merge those answers (and my own value) into my answer?
Think of every node as a manager. They ask each of their two reports for a small piece of information, then combine those pieces with their own knowledge into a single answer to send to their own manager.
Q. Why do many tree solutions use a global "best" variable instead of just returning the answer?
Reveal hint
Because two different things are happening. What you return upward is what your parent can extend (a single side-path, for example). What you record globally is the answer that ends here (a path that bends through this node and cannot be extended further). They are different quantities — one travels up, the other gets saved separately.

4. Traversals — DFS & BFS

"Traversal" just means visiting every node in some order. There are four classic orders:

1 / \ 2 3 / \ \ 4 5 6 Preorder (Root, Left, Right): 1 2 4 5 3 6 Inorder (Left, Root, Right): 4 2 5 1 3 6 ← BST sorted order Postorder (Left, Right, Root): 4 5 2 6 3 1 ← bottom-up evaluation Level (BFS, top to bottom): 1 2 3 4 5 6
OrderWhen to use it
PreorderCopy a tree, serialize it, print parent before children.
InorderBSTs — to get values in sorted order.
PostorderCompute something that needs both children's answers first (heights, deletions).
Level (BFS)Anything about depth, levels, or "the closest leaf".

BFS template idea

  1. Put the root in a queue.
  2. While the queue is not empty, snapshot its current size (= number of nodes on this level).
  3. Process exactly that many nodes; for each, push its non-null children to the back.
  4. Move on to the next level.
The "level snapshot" trick is the secret behind right-view, zigzag, average-of-levels, min-depth and many more. Always grab q.size() at the top of the loop.

5. Iterative Traversal — When Recursion Might Be Risky

If the tree is very tall (think 50,000 nodes in a line), recursion can run out of memory. Use an explicit stack instead.

Iterative inorder — the secret of "Kth smallest in BST"

  1. Start from the root. Keep going left, pushing every node on a stack as you go.
  2. When you can't go left anymore, pop a node and "visit" its value.
  3. Then move to that node's right child and repeat from step 1.
Morris traversal exists too — it gets you O(1) extra memory by temporarily linking nodes, but in interviews knowing iterative-with-stack is enough. Mention Morris only if asked for O(1) space.

6. BST — The Hidden Superpower

BST propertyWhat you can do with it
Inorder gives sorted valuesValidate BST, find Kth smallest, recover BST — they all become "scan an almost-sorted list" problems.
Search / insert / delete cost O(height)If balanced, that's O(log n). If skewed, O(n).
LCA via valuesIf your two targets straddle a node's value (one smaller, one bigger), that node is the LCA.

Q. Why isn't "left child smaller, right child bigger" enough to validate a BST?
Reveal hint
It only checks immediate children, not the entire subtree. A right grandchild could still be smaller than the root. You must carry min and max bounds down as you recurse, or do an inorder traversal and check that values come out strictly increasing.

7. Tree DP — The Pattern That Wins Hard Problems

Most "max ___ in a tree" problems share the same body. The function returns the answer the parent can extend, while a global variable tracks the answer that ends here.

  1. If the node is null, return 0 (or the neutral value).
  2. Recurse on left, recurse on right. If negatives are bad, ignore branches with negative results by treating them as 0.
  3. Update the global answer using both sides combined with the current node.
  4. Return only the better single side, plus the current value, so the parent can keep extending one straight path.
Two-channel rule: the function returns the "extendable" answer, and updates the global with the "terminating-here" answer. Memorize this — it shows up in Diameter, Max Path Sum, Longest Univalue Path, and many more.

The Most-Asked Amazon Tree Problems — Theory & Tricks

Each problem: a real-life picture, the core idea, and the steps. No code.

P1 — Maximum Depth of Binary Tree Easy Bottom-Up DFS
Find how tall a family tree is — count the longest chain of "child of a child of a child…" from the top down.
Core idea: the depth of any tree = 1 + the bigger of (left subtree depth, right subtree depth). Empty tree has depth 0.
  1. If the node is null, return 0.
  2. Ask left for its depth. Ask right for its depth.
  3. Return 1 + the bigger of the two.
Twist: "minimum depth" is not symmetric — a node with only one child is not a leaf, so don't take min over a 0-side. BFS lets you stop at the first leaf you encounter.
P2 — Same Tree Easy Parallel DFS
Place two trees side by side. They are equal only if every matching pair of nodes has the same value and the same shape.
Core idea: walk both trees together. Mismatch in shape or value at any point means not equal.
  1. If both nodes are null, they match.
  2. If only one is null, mismatch.
  3. Otherwise their values must match, and their left subtrees must match, and their right subtrees must match.
P3 — Symmetric Tree Easy Mirrored DFS
A tree is symmetric if you could fold it down the middle and the two halves match like a butterfly.
Core idea: compare the left subtree with the mirror of the right subtree. The mirror of a tree swaps left and right at every level, so recurse on (left.left vs right.right) and (left.right vs right.left).
P4 — Invert Binary Tree Easy Post-order swap
Hold the tree up to a mirror. Every left child becomes the right and vice versa, all the way down.
Core idea: recursively invert both subtrees, then swap the children at the current node.
P5 — Diameter of Binary Tree Easy Tree DP (two-channel)
The diameter is the longest possible "string" you can stretch through the tree connecting two nodes. It might pass through the root, or it might not — it could be entirely inside one subtree.
Core idea: for each node, the longest path that bends at it = left height + right height. Track the maximum across all nodes. Each node returns its single-side height upward.
Trick: diameter is counted in edges, not nodes, so don't add 1 when updating the global max.
P6 — Path Sum (and Path Sum II) Easy / Medium Top-Down DFS + Backtracking
Find a route from the root to any leaf where the values along the way add up to a target number.
Core idea: as you go down, subtract the current value from the target. When you reach a leaf and the leftover equals that leaf's value, you found one. For "all such paths", carry a running list and pop when backtracking.
  1. Add the current node to the path.
  2. If you're at a leaf and the remaining target equals this node's value, save a copy of the path.
  3. Otherwise recurse into left and right with target reduced by the current value.
  4. Remove the current node from the path before returning (backtrack).
Trick: always save a copy of the path, never the same list — otherwise all answers end up pointing to the same (eventually empty) list.
P7 — Binary Tree Level Order Traversal Medium BFS
Imagine taking a photo of the tree level by level — the root in the first picture, both kids in the second, grandkids in the third, and so on.
Core idea: standard BFS with the "snapshot the queue size" trick to group nodes per level.
Spawned variants: Zigzag (reverse alternate levels), average per level, maximum per level — all use the same skeleton.
P8 — Binary Tree Right Side View Medium BFS — last node per level
Stand to the right of the tree. What nodes can you see, blocked by no other?
Core idea: the rightmost node at every level. BFS each level and record the last node processed.
Alternative: DFS visiting right children first, recording at depths you haven't seen yet.
P9 — Validate Binary Search Tree Medium BST bounds DFS
Each node has a "valid range" inherited from its ancestors. Going left, the upper bound becomes the parent's value. Going right, the lower bound becomes the parent's value.
Core idea: check that every node's value is strictly between its inherited min and max. As you recurse, tighten the bounds.
Watch out: values can equal Integer.MIN_VALUE or MAX_VALUE — use a wider type for bounds, or use the inorder approach to avoid the issue.
P10 — LCA of a Binary Tree Medium Bottom-Up DFS Amazon ★★★
In a family tree, the lowest common ancestor of two cousins is their nearest shared grandparent — the one closest to them, not the great-great-grandparent.
Core idea: recursion returns the node if it is one of the two targets, or null. If both children return non-null for some node, that means the targets split here — so this node is the LCA. Otherwise, propagate the non-null result up.
  1. If the node is null, return null.
  2. If the node is one of the targets, return the node itself.
  3. Recurse left and right.
  4. If both sides return non-null, this node is the LCA.
  5. Otherwise return whichever side was non-null.
P11 — LCA of a BST Easy BST property walk
In a BST, all smaller values are on the left and bigger ones on the right. So to find the meeting point of two values, walk down from the root: if both are smaller go left, if both are bigger go right; the moment they "split", you are at the LCA.
  1. Compare both target values to the current node.
  2. If both are smaller, go left. If both are bigger, go right.
  3. Otherwise, the current node is the LCA.
P12 — Serialize / Deserialize Binary Tree Hard Preorder + null markers Amazon ★★★
Pack the tree into a string, then unpack it later to rebuild the exact same tree. Like flattening a 3D object into a 2D blueprint.
Core idea: a preorder traversal alone is ambiguous — many different trees can produce the same preorder. Add explicit "null" markers wherever a child is missing, and now the preorder uniquely defines the tree.
  1. To serialize: do a preorder traversal. Output each value or "null" separated by commas.
  2. To deserialize: read tokens left to right. The first token is the root; recursively build the left subtree, then the right subtree.
P13 — Binary Tree Maximum Path Sum Hard Tree DP (two-channel) Amazon ★★★
Find any path between any two nodes (it doesn't have to start at the root) where the sum of values is largest.
Core idea: for each node, two things happen. The "best path that bends at this node" = node value + best left side + best right side (each side ignored if negative). The "best straight path through this node going up to the parent" = node value + the better of the two sides. Update a global max with the bending one, return the straight one.
  1. Compute the best non-negative gain from left and right subtrees.
  2. Update global best with current value + left gain + right gain.
  3. Return current value + the better single side (so the parent can extend).
Trick: taking max(0, child gain) lets the algorithm "skip" subtrees with negative totals.
P14 — Construct Binary Tree from Preorder + Inorder Medium Recursion + index map
Two clues about a tree's structure. Use them together to figure out which node was the root and how the rest splits.
Core idea: the first value of preorder is always the root. Find that value in inorder; everything to its left is the left subtree, everything to its right is the right subtree. Recurse on both halves.
  1. Build a map of value → index in inorder for fast lookup.
  2. Track a pointer into the preorder list.
  3. Recursively pick the next preorder value as the current root, split inorder by that root, and recurse on left half then right half.
P15 — Subtree of Another Tree Easy DFS + same-tree check
Look for a smaller tree fully matching somewhere inside a bigger tree.
Core idea: at every node of the big tree, ask "are this node and the subtree's root the same exact tree?" using the Same Tree procedure.
  1. If big tree is null, return false.
  2. If sameTree(big, sub) is true, return true.
  3. Otherwise recurse into big.left or big.right.
P16 — Kth Smallest Element in a BST Medium Iterative inorder
Inorder traversal of a BST gives you the values in sorted order. So the Kth one to come out is your answer.
Core idea: use iterative inorder so you can stop as soon as the Kth value pops out. No need to traverse the whole tree.
  1. Walk left, pushing nodes on a stack.
  2. Pop a node; that is the next-smallest value. Decrement K.
  3. If K hits 0, return that node's value.
  4. Otherwise switch to its right child and continue.
P17 — Binary Tree Vertical Order Traversal Medium BFS with column index
Imagine vertical slits running through the tree. Group nodes by which slit they fall into, going left to right.
Core idea: assign each node a column. Root is column 0, left child is parent − 1, right child is parent + 1. BFS so that within each column, the order is top-down. Group nodes by column, then sort columns left to right.
P18 — All Nodes Distance K in Binary Tree Medium Graph-ify + BFS
Find every node exactly K steps away from a target node, treating parent-child links as two-way roads.
Core idea: a tree only has child pointers, but distance K can mean going up to a parent first. Build a parent map by walking the tree once, then BFS from the target, treating left, right, and parent as three neighbors.
P19 — Count Good Nodes in Binary Tree Medium Top-Down DFS
A "good" node is one that sees no bigger value on the way down from the root. Count them.
Core idea: as you walk down, carry the maximum value seen so far. If the current value is at least that maximum, count it as good and update the max.
P20 — Path Sum III Medium DFS + prefix sum map
Count paths going downward (parent to child) whose values sum to a target. The path doesn't have to start at the root or end at a leaf.
Core idea: as you walk from the root, keep a running sum. A path ending at the current node with sum target = some earlier running sum equals (current − target). So track how many times each running sum has occurred, and look up that difference.
  1. Maintain a running sum and a counter map (sum → number of times seen so far on the current path).
  2. At each node, look up (running − target) in the map; that count adds to the answer.
  3. Add current running sum to the map, recurse into children, then remove it (backtrack).
P21 — Flatten Binary Tree to Linked List Medium Reverse preorder
Take the tree and squash it into a single right-going chain that follows preorder.
Core idea: walk the tree in reverse preorder (right, left, root), keeping a pointer to the previously visited node. At each step, set current.right = previous and current.left = null. Update previous to current.
P22 — Implement Trie (Prefix Tree) Medium N-ary tree of letters
A trie is like a tree where every path from the root spells out a word. Common prefixes share the same starting branches.
Core idea: each node has up to 26 children (for a–z) and a flag "is this the end of a word?". To insert, walk through letters creating missing children and set the flag at the end. To search, follow the letters and check the flag.
  1. Insert: for each letter, if no child exists, create one. Move to it. After the last letter, set the end flag.
  2. Search: walk the letters. If any are missing, return false. At the end, return the flag value.
  3. StartsWith: same as search, but at the end always return true.
P23 — Word Search II (Trie + DFS) Hard Trie pruning + grid DFS
A grid of letters and a long list of words to find inside it. Build a trie of all the words first; then DFS from each cell, walking the trie alongside, so you only explore prefixes that exist in the dictionary.
Core idea: without the trie, each word forces a separate DFS — too slow. The trie acts as a giant filter: at each grid step, the trie tells you whether continuing in this direction is even worth it.
  1. Build a trie from all the words.
  2. DFS from every cell, descending the trie based on the current letter.
  3. If the current trie node marks the end of a word, save that word and clear the marker so it won't be added twice.
  4. Mark cells visited (and unmark when backtracking) to avoid reusing letters in the same path.
P24 — Boundary of Binary Tree Medium Three custom walks
Walk around the outside of the tree as if tracing it with a pencil — top to bottom on the left, then across all the leaves at the bottom, then bottom to top on the right.
Core idea: three small DFS walks combined: collect the left boundary going down, collect leaves left to right, collect the right boundary going down (then reverse it). Concatenate them, careful not to double-count corners.
P25 — Binary Search Tree Iterator Medium Iterative inorder using a stack
A "next smallest value" button for a BST. Each press should give you the next element in sorted order, using as little memory as possible.
Core idea: store partial inorder progress using a stack. Push leftmost-spine when initializing or whenever you move to a right subtree. Each "next" pops from the stack and then pushes the right child's leftmost spine.
  1. Initialize by pushing the root and then keep going left, pushing every node along the way.
  2. "Next": pop a node; that is the answer. If it has a right child, push the right child and keep going left, pushing each one.
  3. "HasNext": stack is not empty.

Final Tricky Round — 8 Conceptual Gotchas

Q1. In Diameter, why do we count edges, not nodes?
Reveal hint
"Diameter" is the longest path measured by number of edges between two leaves. If you count nodes by mistake, your answer is always one too big. The fix is simple: when updating the global max, don't add 1 — only the heights of the two sides combine.
Q2. Why does "left value < root < right value" not validate a BST?
Reveal hint
Because a BST rule applies to all descendants, not just immediate children. A right grandchild could be smaller than the root and still satisfy the local rule. You need to pass min/max bounds down or use inorder traversal.
Q3. In Path Sum II, why must we copy the path before saving it?
Reveal hint
If you save the same list reference, every entry in your result points to the very same list. As recursion backtracks and pops elements off, all entries empty out at the same time. A fresh copy snapshots the path at the moment of saving.
Q4. In LCA of Binary Tree, what does the recursion actually return?
Reveal hint
It returns one of three things: a target node if the subtree contains it, the LCA node if both targets were found below, or null if neither target is in the subtree. The "merge" rule is: if both subtree results are non-null, the current node is the LCA.
Q5. Why is preorder alone not enough to rebuild a binary tree?
Reveal hint
Many different shapes produce the same preorder. For example, "1, 2, 3" could be a left-leaning chain or a right-leaning chain. Either pair preorder with inorder (which fixes the shape) or insert null markers in the preorder string.
Q6. In Max Path Sum, why do we use max(0, child) when adding sides?
Reveal hint
If a child's best path sum is negative, including it can only hurt our total. Treating it as 0 means "skip that subtree entirely". Note this only applies because the problem allows paths of any shape — for problems that require visiting a child, you cannot drop it.
Q7. In All Nodes Distance K, why do we build a parent map?
Reveal hint
A tree's pointers only go down (parent → children). Distance K from a target may include nodes above the target or in a sibling's subtree. By recording each node's parent in a map, you can move in three directions during BFS, treating the tree like an undirected graph.
Q8. In Path Sum III, why is the prefix-sum trick faster than checking every pair?
Reveal hint
Naively, you would start a DFS from every node — O(N²). The prefix-sum approach asks "is there an earlier running sum equal to (current − target)?" using a hashmap. That answers each query in O(1), so the total cost drops to O(N).
