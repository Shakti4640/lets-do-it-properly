1. Core Patterns Overview

Pattern Problem Cue / When to Use Go-to Java Collection / API Complexity Intuition · Tips · Tricks · Pitfalls
Two Pointers EM Sorted array, pair/triplet sum, remove duplicates, palindrome, merge sorted. int[], char[], String.toCharArray() O(n) / O(1) Tip: sort first if order doesn't matter. Trick: skip duplicates with while(l<r && a[l]==a[l+1]) l++;. Pitfall: off-by-one when l==r.
Sliding Window M "Longest/shortest substring/subarray with …", "at most K", "exactly K" (= atMost(K) − atMost(K−1)). HashMap<Character,Integer>, int[26]/int[128] freq, Deque for monotonic. O(n) / O(k) Template: expand right, shrink left while invalid. Trick: for char-set windows prefer int[128] over HashMap (5–10× faster). Pitfall: forgetting to update answer after shrinking.
Fast & Slow Pointers E Linked list cycle, middle of list, happy number, palindrome LL. ListNode refs, no extra collection. O(n) / O(1) Tip: slow=slow.next; fast=fast.next.next; always null-check fast AND fast.next. Trick: Floyd's — reset slow to head to find cycle start.
Prefix Sum EM Range sum queries, subarray sum = K, equal 0/1 arrays. long[] prefix, HashMap<Long,Integer> for count of prefix seen. O(n) / O(n) Tip: seed map with {0:1} to count subarrays starting at index 0. Pitfall: use long to avoid overflow.
Difference Array M Many range updates then one query (e.g., car pooling, range addition). int[] diff of size n+1. O(n+u) / O(n) Trick: diff[l]+=v; diff[r+1]-=v; then prefix-sum.
Hash Map / Set E Two-sum, anagrams, de-dup, lookup O(1), frequency. HashMap, HashSet, LinkedHashMap (LRU-ish), getOrDefault, merge. O(n) / O(n) Tip: map.merge(k,1,Integer::sum) is the cleanest counter. Pitfall: autoboxing — avoid in hot loops with int[].
Sorting + Greedy M Interval merge, meeting rooms, activity selection, min platforms. Arrays.sort(a,(x,y)->x[0]-y[0]), PriorityQueue for active set. O(n log n) Pitfall: never use x[0]-y[0] for long/large ints (overflow); use Integer.compare. Trick: sort by end-time for max-nonoverlapping intervals.
Binary Search M Sorted array, "find minimum X such that…", rotated array, monotonic predicate. Arrays.binarySearch (exact), custom lo/hi for "search on answer". O(log n) Template: while(lo<hi){mid=lo+(hi-lo)/2; if(ok(mid)) hi=mid; else lo=mid+1;}. Pitfall: (lo+hi)/2 overflows — always use lo+(hi-lo)/2.
Binary Search on Answer H "Minimum capacity", "split array largest sum", Koko eats bananas. long lo, hi; write boolean feasible(mid). O(n log range) Trick: if predicate flips monotonically from false→true, pick leftmost true.
Monotonic Stack M Next greater/smaller, largest rectangle, daily temperatures, stock span. Deque<Integer> st = new ArrayDeque<>(); (never Stack). O(n) / O(n) Tip: push indices, not values. Trick: append a sentinel (e.g., 0 or ∞) to flush stack at end. Pitfall: Stack class is legacy & synchronized — slow.
Monotonic Deque H Sliding window max/min, shortest subarray sum ≥ K. ArrayDeque<Integer> of indices. O(n) Tip: pop from back while a[back] ≤ a[i] (for max), pop from front when out of window.
Heap / Priority Queue M Top-K, K-th largest/smallest, merge K lists, median stream, task scheduler. PriorityQueue (min-heap default); max-heap via Collections.reverseOrder() or (a,b)->b-a. O(n log k) Trick: keep size = K, poll when exceeding ⇒ top-K in O(n log k). Median: two heaps, keep low.size() ∈ {hi.size(), hi.size()+1}.
Intervals (Sweep Line) M Meeting rooms II, skyline, calendar booking. PriorityQueue of end-times, or TreeMap<Integer,Integer> for event counts. O(n log n) Trick: +1 on start, −1 on end, sort events, running max = answer.
BFS (Graph/Grid) M Shortest path in unweighted graph, level order, min steps, rotten oranges. ArrayDeque<int[]> queue, boolean[][] visited. O(V+E) Tip: process by levels with size snapshot. Trick: multi-source BFS — push all sources first.
DFS / Backtracking MH Permutations, combinations, subsets, N-Queens, word search, Sudoku. List<List<Integer>> result, Deque as path, boolean[] used. O(branch^depth) Template: choose → recurse → un-choose. Trick: sort then if(i>start && a[i]==a[i-1]) continue; to skip dup subsets. Pitfall: forgetting to copy the path: new ArrayList<>(path).
Union-Find (DSU) MH Connected components, redundant connection, accounts merge, Kruskal's MST. int[] parent, rank; path compression + union by rank. O(α(n)) ≈ O(1) Tip: always compress: parent[x]=find(parent[x]);. Trick: encode 2D grid cells as r*cols+c.
Topological Sort M Course schedule, build order, task deps. Kahn's BFS: int[] indeg + ArrayDeque; or DFS with post-order & stack. O(V+E) Pitfall: if result size < V ⇒ cycle. Trick: use List<List<Integer>> adjacency for sparse graphs.
Dijkstra M Shortest path, non-negative weights, network delay time, cheapest flights. PriorityQueue<int[]> of {dist,node}, int[] dist. O(E log V) Tip: lazy — skip if popped dist > dist[node]. Pitfall: negative edges ⇒ use Bellman-Ford / SPFA.
Bellman-Ford H Negative edges, detect negative cycle, k-stop shortest path. int[] dist, relax V−1 times. O(V·E) Trick: for "at most k stops" relax exactly k+1 times on a copy of dist.
Floyd-Warshall M All-pairs shortest path, transitive closure, small V (≤ 400). int[][] d. O(V³) Tip: loop order must be k,i,j.
Trie MH Prefix search, word break, autocomplete, XOR max pair. Custom Node{Node[] ch=new Node[26]; boolean end;}. O(L) per op Trick: store word at terminal node for word-search II. Pitfall: avoid HashMap children unless alphabet is huge — arrays are 5× faster.
Segment Tree / BIT H Range sum/min/max with point updates, count of smaller after self. int[] bit (Fenwick) or long[] seg. O(log n) per op BIT: for(;i<=n;i+=i&-i) update; for(;i>0;i-=i&-i) query.
Dynamic Programming MH "Max/min/count ways", overlapping subproblems, optimal substructure. int[], int[][], sometimes HashMap for memo. varies Recipe: state → transition → base → order. Trick: space-compress row DP to 1D (knapsack loop right→left). Pitfall: forgetting base case for empty input.
Bitmask DP H TSP, assignment problem, n ≤ 20 subset iteration. int[] dp = new int[1<<n]. O(2ⁿ · n) Trick: iterate submasks: for(int s=mask; s>0; s=(s-1)&mask).
Greedy M Jump game, gas station, candy, task scheduler, partition labels. Usually just arrays + a PQ or HashMap. O(n) / O(n log n) Tip: prove exchange argument mentally before committing. Pitfall: greedy ≠ optimal — DP if in doubt.
Matrix Traversal EM Islands, flood fill, spiral, rotate, word search. 2D int[][], dir array {{1,0},{-1,0},{0,1},{0,-1}}. O(m·n) Trick: mark visited in-place (flip '1'→'0') to save space. Pitfall: bounds check before recursion.
LinkedList Manipulation EM Reverse, reorder, merge, partition, detect cycle. ListNode with dummy head. O(n) Trick: always use a dummy node — eliminates edge cases on head.
Tree DFS (pre/in/post) EM Path sum, diameter, LCA, validate BST, serialize. Recursion + int[] or global field for answers. O(n) Trick: return a tuple via int[] for (height, something) per node. Pitfall: stack overflow on skewed trees — iterative with Deque.
Tree BFS E Level order, right view, zigzag, min depth. ArrayDeque<TreeNode>. O(n) Tip: snapshot level size at the start of each level.
LCA / Binary Lifting H Tree ancestor queries, kth ancestor, path queries. int[][] up = new int[LOG][n]; O((n+q) log n) Trick: precompute up[k][v] = up[k-1][ up[k-1][v] ].
Kadane's E Max subarray sum, circular variant, product. Single pass, two ints. O(n) Trick: circular = max(kadane, total − minKadane) (handle all-negative case).
Reservoir Sampling M Random node in LL, linked list with stream. Random, single variable. O(n) / O(1) Trick: replace answer with prob 1/i at the i-th element.
Design (LRU/LFU/etc.) MH LRU cache, LFU, insert/delete/random O(1), Twitter. LinkedHashMap (LRU in 5 lines), doubly-linked list + HashMap for hand-rolled LFU. O(1) per op Trick: new LinkedHashMap<>(cap,0.75f,true) + override removeEldestEntry.

2. Java Collections — Which One & Why

Collection Use When Don't Use When Key Ops (avg) Tricks & Gotchas
ArrayList<E> Dynamic array, index access, backtracking path, result list. Frequent insert/delete at front or middle (O(n)). get/set O(1), add-end amortized O(1) Use list.subList(a,b) as a view; wrap in new ArrayList<>(...) to copy. Prefer Arrays.asList only for fixed-size.
ArrayDeque<E> Stack, queue, deque, BFS, monotonic. Always prefer over Stack / LinkedList. Need thread safety or random-access by index. push/pop/peek O(1) offer/poll/peek for queue, push/pop/peek for stack. Does NOT allow null.
LinkedList<E> Almost never in practice — only if you need list+deque semantics with iterator removal. Anything else — use ArrayDeque or ArrayList. get O(n) 2× memory of ArrayDeque; poor cache locality.
HashMap<K,V> Unordered key→value lookup, counters, memoization. Need order, need range queries. put/get O(1) avg merge(k,1,Integer::sum) for counters; computeIfAbsent(k, x->new ArrayList<>()).add(v) for grouping.
LinkedHashMap<K,V> Preserve insertion order, LRU cache (access-order constructor). Hot-path where every ns matters (slightly slower than HashMap). O(1) avg Pass true as 3rd arg for access-order → natural LRU.
TreeMap<K,V> Sorted keys, floor/ceiling/higher/lower, range queries, calendar problems. Plain counters (HashMap is faster). O(log n) floorKey, ceilingKey, subMap(lo,hi) are the secret weapons. Red-black tree under the hood.
HashSet<E> Dedup, membership, visited. Need sorted iteration. O(1) avg For visited-in-grid prefer boolean[][] — no boxing.
TreeSet<E> Sorted unique set, closest value queries. Plain dedup. O(log n) ceiling/floor for nearest-neighbor in sliding window (e.g., contains-duplicate III).
PriorityQueue<E> Heap: top-K, Dijkstra, merge K sorted. Need random access or sorted iteration (it's NOT sorted on iterate!). offer/poll O(log n) Default = min-heap. Max-heap: new PriorityQueue<>(Comparator.reverseOrder()).
int[] / int[][] Performance-critical DP, grids, freq counters over fixed alphabet. Dynamic resizing needed. O(1) Always beats boxed Integer[]. Use Arrays.fill, Arrays.copyOf.
StringBuilder String concatenation in loops, building output. Short concat of 2-3 strings (just use +). append O(1) amortized Pre-size with new StringBuilder(n) when n known. reverse() is O(n).
String Immutable text. Many concatenations in loop (quadratic). charAt O(1) toCharArray() once, then index — faster than repeated charAt in hot loops.
BitSet Sieve of Eratosthenes, visited flags for huge N, bitmask ops. Small N — just use long. O(1) per bit 64× memory savings vs boolean[]; has and/or/xor/cardinality.
Deque<Integer> (monotonic) Sliding window max/min, next greater element. Need random access. O(1) amortized Store indices, not values, so you can check window bounds.
Map.Entry<K,V> Passing pairs around without a custom class. When you need mutability of both sides (prefer int[]). — Map.entry(k,v) (Java 9+) is immutable. For mutable pair, use int[]{a,b}.

Binary search (leftmost true) 
int lo = 0, hi = n;
while (lo < hi) {
    int mid = lo + (hi - lo) / 2;
    if (ok(mid)) hi = mid;
    else         lo = mid + 1;
}
return lo; // smallest index where ok==true
DSU with path compression + union by rank 
int[] p, r;
int find(int x){ while (p[x]!=x){ p[x]=p[p[x]]; x=p[x]; } return x; }
boolean union(int a, int b){
    a=find(a); b=find(b);
    if (a==b) return false;
    if (r[a]<r[b]) { int t=a; a=b; b=t; }
    p[b]=a;
    if (r[a]==r[b]) r[a]++;
    return true;
}
Topological sort (Kahn's) 
int[] indeg = new int[n];
List<List<Integer>> g = new ArrayList<>();
for (int i=0;i<n;i++) g.add(new ArrayList<>());
for (int[] e : edges){ g.get(e[0]).add(e[1]); indeg[e[1]]++; }
Deque<Integer> q = new ArrayDeque<>();
for (int i=0;i<n;i++) if (indeg[i]==0) q.offer(i);
List<Integer> order = new ArrayList<>();
while (!q.isEmpty()){
    int u = q.poll(); order.add(u);
    for (int v : g.get(u)) if (--indeg[v]==0) q.offer(v);
}
if (order.size() != n) { /* cycle */ }
LRU cache in 8 lines 
class LRU<K,V> extends LinkedHashMap<K,V> {
    private final int cap;
    LRU(int cap){ super(cap, 0.75f, true); this.cap = cap; }
    @Override protected boolean removeEldestEntry(Map.Entry<K,V> e){ return size() > cap; }
}
Sliding window template 
int l = 0, best = 0;
int[] freq = new int[128];
for (int r = 0; r < s.length(); r++){
    freq[s.charAt(r)]++;
    while (/* invalid */) {
        freq[s.charAt(l)]--;
        l++;
    }
    best = Math.max(best, r - l + 1);
}
Dijkstra 
int[] dist = new int[n];
Arrays.fill(dist, Integer.MAX_VALUE);
dist[src] = 0;
PriorityQueue<int[]> pq = new PriorityQueue<>((a,b) -> a[0]-b[0]);
pq.offer(new int[]{0, src});
while (!pq.isEmpty()){
    int[] cur = pq.poll();
    int d = cur[0], u = cur[1];
    if (d > dist[u]) continue;
    for (int[] nb : g.get(u)){
        int v = nb[0], w = nb[1];
        if (d + w < dist[v]){ dist[v] = d + w; pq.offer(new int[]{dist[v], v}); }
    }
}

5. Interview Gotchas (fast list)

  • Overflow: sum of two ints can overflow — use long or Math.addExact.
  • Comparator: never return a-b for longs or possibly-huge ints — use Long.compare.
  • PriorityQueue iteration: iterator is NOT sorted; only poll() is.
  • Autoboxing: Map<Integer,Integer> is 6–10× slower than int[] in hot loops.
  • HashMap capacity: pre-size with new HashMap<>(n*4/3 + 1) to avoid resize churn.
  • String equality: use .equals, never == (except for interned literals).
  • Recursion depth: JVM default ~10k — iterative for skewed trees / big grids.
  • Modulo: in Java % can be negative — normalize with ((x % m) + m) % m.
  • Array clone: arr.clone() is shallow; for 2D use Arrays.stream(a).map(int[]::clone).toArray(int[][]::new).
  • Char ↔ int: c - '0' for digits, c - 'a' for lowercase index.
