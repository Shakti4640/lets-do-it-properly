0. Built-in Types & Conversions (Python's "Primitives")

Python has no true primitives — everything is an object. But a small set of built-in types plays the role of int/float/bool/str/bytes from other languages. They are all immutable and inherit (eventually) from object.

Q1. a = 256; b = 256; a is b vs a = 257; b = 257; a is b. Why do these differ?
Reveal hint
CPython caches small integers (-5..256) as singletons, so a is b is True. For 257, they're fresh objects, so is is False. Never use is for value equality.
Q2. bool("False") — what does it return?
Reveal hint
True. bool(s) is truthiness of any object; any non-empty string is truthy. Parse explicitly for semantic booleans.
Q3. Why does isinstance(True, int) return True?
Reveal hint
Because bool is a subclass of int. That's by design: True is 1, False is 0. Use type(x) is int to exclude booleans.
Q4. 0.1 + 0.2 == 0.3 — and the fix?
Reveal hint
False. Use math.isclose(a, b) for general floats, or Decimal for exact decimal arithmetic like money.

1. The Four OOP Pillars — Overview

PillarOne-line ideaKey Python hookSmell if misused
EncapsulationHide state, expose behavior via methods/properties._name, __name, @propertyBare attributes everywhere, no invariants.
Inheritance"is-a" reuse.class Sub(Base):, super()Deep hierarchies; subclassing for reuse only.
PolymorphismSame call, different behavior — usually via duck typing.Matching method signatures; protocols.Long isinstance ladders.
AbstractionModel what, not how.abc.ABC, typing.ProtocolOne-impl interfaces with no purpose.
Python twist: polymorphism usually doesn't require a common base class. If it walks like a duck, it's a duck. Use Protocol for static typing, ABC for explicit contracts.
Q. Does Python need an interface to get polymorphism?
Reveal hint
No. Any two classes exposing the same method name work polymorphically. Protocol gives you static checks without requiring inheritance.

Q. What does class A: log = [] followed by two A()s and a1.log.append("x") do?

class Celsius:
    def __init__(self, temp: float):
        self.temp = float(temp)
    @classmethod
    def from_fahrenheit(cls, f: float) -> "Celsius":

Q. Can __init__ return an object?
Reveal hint
No. Returning non-None from __init__ raises TypeError. Only __new__ produces the instance.

Q. What does self.__x really become at runtime inside class Foo?
Reveal hint

5. Encapsulation & @property

TopicWrongRight
Start with getters/settersWriting Java-style get_x() / set_x() from day 1.Use plain attributes. Switch to @property only when you need validation/computation.
Validation in setterAllowing invalid state silently.Raise ValueError in the setter when invariants are violated.
Leaking internalsReturning the internal list directly.Return a tuple or a copy: return tuple(self._items).
Public mutable defaultsStoring mutable input directly.Copy on input: self._d = dict(d).
 
class Account:
    def __init__(self, balance: float):
        self._balance = 0.0
        self.balance = balance
    @property
    def balance(self) -> float: return self._balance
    @balance.setter
    def balance(self, v: float):
        if v < 0: raise ValueError("balance cannot be negative")
        self._balance = float(v)
Q. Private fields, only getters, returns a list — is the class immutable?
Reveal hint
No. If the getter hands back the same list, the caller can mutate it. Return a tuple or a copy for true isolation.

6. Inheritance & MRO

RuleWrongRight
Multiple inheritanceclass C(A, B): with no thought for MRO.Design "mix-ins" small & single-purpose; call super().__init__.
super() chainCalling Base.__init__(self, ...) directly.Always super().__init__(...); cooperates with MRO.
MROAssuming left-to-right DFS.Python uses C3 linearization (Cls.__mro__).
LSPChild violates parent's contract.Must stay substitutable — same or weaker preconditions, same or stronger postconditions.
Reuse via inheritanceSubclass just to reuse a helper.Prefer composition or a standalone function.
 
class A:          pass
class B(A):       pass
class C(A):       pass
class D(B, C):    pass
D.__mro__   # (D, B, C, A, object) — C3 linearization
Q. In class D(B, C) where both B and C override foo, which wins?
Reveal hint
The first one in the MRO (B, since it's listed first). Inspect with D.__mro__ to be sure — surprises happen with deeper diamonds.

7. Polymorphism & Duck Typing

TopicWrongRight

EAFP vs LBYL"Look before you leap" everywhere: if hasattr(x,"read"): x.read()."Easier to Ask Forgiveness than Permission": try: x.read() except AttributeError: ....

from functools import singledispatch
@singledispatch
def area(shape): raise NotImplementedError
@area.register
def _(s: Circle): return 3.14159 * s.r * s.r
@area.register

Q. When is isinstance check actually the right call?
Reveal hint
At API boundaries (validating inputs), and for explicit multi-dispatch via singledispatch. Avoid it for dispatching behavior — prefer polymorphism.

8. Abstraction (ABC / Protocol)

TopicWrongRight
Instantiating an abstract classShape() when Shape has @abstractmethod.Subclass must implement all abstract methods first. Otherwise TypeError.
Missing decoratorDeclaring a method intended to be abstract without @abstractmethod.Every abstract method must be explicitly decorated.
No ABC baseUsing @abstractmethod without inheriting from ABC.Inherit from abc.ABC (or use metaclass=ABCMeta).
Hiding representationExposing every field via getters.Expose behaviors (verbs), hide representation.
 
from abc import ABC, abstractmethod
class Shape(ABC):
    @abstractmethod
    def area(self) -> float: ...
class Circle(Shape):
    def __init__(self, r): self.r = r
    def area(self): return 3.14159 * self.r * self.r
Q. Can an ABC have a constructor and concrete methods?
Reveal hint
Yes. An ABC can mix abstract and concrete methods, and define __init__. You just can't instantiate it directly while abstract methods remain unimplemented.

9. ABC vs Protocol

AspectABC (abc.ABC)Protocol (typing.Protocol)
RelationshipExplicit: must class X(Base):.Structural: anything with the right shape fits.
Runtime enforcementYes — can't instantiate if abstract methods missing.Only at type-check time (unless @runtime_checkable).
Good forFramework contracts, shared base logic.Duck-typed APIs in a typed codebase.
Multiple inheritanceOK but watch MRO.Free — no inheritance at all.
 
from typing import Protocol, runtime_checkable
@runtime_checkable
class SupportsClose(Protocol):
    def close(self) -> None: ...
def shutdown(x: SupportsClose) -> None:
    x.close()
Q. Can a class satisfy a Protocol without inheriting from it?
Reveal hint
Yes — that's the whole point. Structural typing: if the class has the right methods/attributes, it qualifies. Add @runtime_checkable to use it in isinstance.

10. Overloading vs Overriding

AspectOverloadingOverriding
Built-in?Not supported like Java — the second def replaces the first.Supported via subclasses.
WorkaroundsDefault args, *args/**kwargs, functools.singledispatch, typing.overload for type hints only.Define method again in subclass; call super() if chaining.
Decorator—No @override before 3.12 (now typing.override for type checkers).

from typing import overload
@overload
def parse(x: int) -> int: ...
@overload
def parse(x: str) -> int: ...
def parse(x):
    return int(x)
Q. Defining def f(self, x): ... twice in a class — what happens?
Reveal hint
The second definition silently replaces the first. No "overload" error. Use @singledispatch or branch on type inside one method.

11. @classmethod and @staticmethod

DecoratorFirst argUse case
@classmethodclsAlt constructors / factory; operates on the class itself.
@staticmethodNoneUtility grouped with the class but doesn't need self/cls.
Instance methodselfWorks with instance state.
 
class Date:
    def __init__(self, y, m, d): self.y, self.m, self.d = y, m, d
    @classmethod
    def from_iso(cls, s: str) -> "Date":
        y, m, d = map(int, s.split("-"))
        return cls(y, m, d)
    @staticmethod
    def is_leap(year: int) -> bool:
        return year % 4 == 0 and (year % 100 != 0 or year % 400 == 0)
Q. Why is @classmethod preferred over @staticmethod for alt constructors?
Reveal hint
Because it gets cls. A subclass calling Sub.from_iso(...) will correctly produce a Sub, not the parent type.

Reveal hint

Q1. Is class MyList(list): ... usually a good idea?
Reveal hint
Rarely. Python's list has ~40 methods that now form your contract; internal self-calls can bypass your overrides. Compose a list and implement only what you need.
Q2. Penguins don't fly. Where do you put fly()?
Reveal hint
Not on Bird. Make Flyable a Protocol; let Sparrow implement it and Penguin implement Swimmable instead.
Q3. Composition vs aggregation for Order.items?
Reveal hint
Usually composition — line items die with the order. Aggregation would be if the line items were shared entities referenced elsewhere (unusual).

Reveal hint

Q3. What's the fastest way to count words in a list?

Q4. Is dict ordered?
Reveal hint
Yes, insertion order is preserved since Python 3.7 (guaranteed by the language spec). OrderedDict is mostly legacy now.

22. Iterators, Generators & itertools — Python's "Streams"

Python doesn't have Java's Stream class, but it has something more general: iterators and generators. Plus itertools for pipeline combinators and functools.reduce for folding. They share the same spirit — lazy, chainable, one-shot.

Core mental model

  Source  →  [generators / itertools combinators ... lazy]  →  Terminal (eager)
  iter    →   filter / map / chain / islice                  →   list() / sum() / next() / for-loop
PropertyMeaningConsequence
LazyCombinators build a pipeline; nothing runs until you iterate.No terminal op = no work.
Single-useMost iterators are exhausted after one pass.Re-wrap the source (or use itertools.tee) to reiterate.
Possibly infinitecount, cycle, repeat.Must short-circuit (islice, takewhile, next).
Non-interferingDon't mutate the underlying source.Yield copies or use functional style.

Performance & best practices

  • Prefer generator expressions over list comprehensions when you don't need the list.
  • Materialize once if you'll iterate multiple times (or use itertools.tee).
  • For numeric work, reach for numpy/pandas; they vectorize in C.
  • Use operator.itemgetter / attrgetter instead of lambdas in sort keys for speed.
  • Counter, set, dict beat any hand-written O(n²) idiom.
  • Avoid stateful lambdas in generator pipelines; keep them pure for clarity and parallelization.
  • Short-circuit with any/all/next when you don't need every element.
Q1. it = iter([1,2,3]); list(it); list(it) — what's the second result?
Reveal hint
[]. Iterators are exhausted after one pass. Call iter(src) again, or use itertools.tee.
Q2. next(x for x in count() if x > 1_000_000) — does this finish?
Reveal hint
Yes. next is short-circuiting and the generator is lazy. count()'s infinite tail is never evaluated.
Q3. Why does itertools.groupby(items, key=f) often return "wrong" groups?
Reveal hint
It only groups consecutive equal keys. Sort by the same key first, or use defaultdict(list) for a global group-by.
Q4. list(genexpr) vs [list_comp] — when to pick which?
Reveal hint
Pick a generator expression when you stream or compose; pick a list comprehension when you need a real list (e.g., to index, slice, reiterate).
Q5. Why doesn't ThreadPoolExecutor speed up a pure-Python math loop?
Reveal hint
The GIL serializes Python bytecode. Use ProcessPoolExecutor for CPU-bound Python, or move heavy math to numpy/numba/C extensions that release the GIL.
Q6. What's the fastest way to dedupe a list while preserving order?
Reveal hint
list(dict.fromkeys(seq)). Dict insertion order is preserved and lookup is O(1).
Q7. When will parallelizing via concurrent.futures hurt?
Reveal hint
Tiny payloads (dispatch overhead dominates), high inter-process data copies, or when the work is I/O-bound with an async-friendly API (use asyncio instead).
