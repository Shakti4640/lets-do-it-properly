Q1. Why does let c = s.chars().nth(5); have type Option<char>?
Reveal hint
UTF-8 strings may be shorter than 5 chars, or a given byte offset may not align to a char boundary. Rust forces you to handle "no such char".
Q2. let x = 200u8 + 100u8; — what happens?
Reveal hint
Debug build: panics (overflow). Release build: wraps to 44. Use .checked_add(), .wrapping_add(), or .saturating_add() to state your intent.
Q3. What's the difference between &str and String?
Reveal hint
String owns its buffer (heap-allocated, growable). &str is a borrowed view — a pointer + length. A String automatically derefs to &str.

1. OOP Pillars in Rust

PillarJava hookRust realization
Encapsulationprivate fieldsFields are module-private by default. pub to expose. Module = privacy boundary.
InheritanceextendsDoes not exist. Use composition + traits + default methods.
PolymorphismvirtualTraits. Static dispatch via generics (T: Trait); dynamic dispatch via &dyn Trait / Box<dyn Trait>.

Rust's twist: no class hierarchy, no null, no exceptions. The type system catches what Java's runtime catches — ownership, mutability, and variants are all compile-time.
Q. Rust has no inheritance. How do you share implementation between types?
Reveal hint
Traits with default method bodies, plus composition (embed the shared type as a field). Prefer this even in languages that do have inheritance.

2. struct — the "Class with Data"

#[derive(Debug, Clone)]
pub struct Point {
    pub x: f64,
    pub y: f64,
}

impl Point {
    pub fn new(x: f64, y: f64) -> Self {
        Self { x, y }                 // field init shorthand
    }

    pub fn distance(&self, other: &Self) -> f64 {
        let dx = self.x - other.x;
        let dy = self.y - other.y;
        (dx*dx + dy*dy).sqrt()
    }
}

Q. What does #[derive(Clone, Debug, PartialEq)] do?
Reveal hint
Generates trait implementations. Clone → .clone(); Debug → "{:?}" printing; PartialEq → ==. Each requires all fields to implement the same trait.

3. "Constructors" & Drop

Rust has no constructor keyword — use associated functions by convention named new. Destruction is automatic via the Drop trait when a value goes out of scope.

pub struct File {
    handle: std::fs::File,
}

impl File {
    pub fn open(path: &str) -> std::io::Result<Self> {
        Ok(Self { handle: std::fs::File::open(path)? })
    }
}

impl Drop for File {
    fn drop(&mut self) {
        // automatic cleanup — run when the value leaves scope
    }
}
TopicWrongRight
Fallible "ctor"Panicking on bad input.Return Result<Self, Err> from new or try_new.
Multiple constructorsOverloading new.Give descriptive names: Date::today(), Date::from_iso(s), Date::new(y, m, d).
Running init logicForgetting to implement Drop for a handle.Wrap raw resources and implement Drop so cleanup happens automatically.
Partial movesMoving one field out of a struct, then using the struct.Move everything, clone, or use mem::replace.
Manual dropCalling .drop() directly.Use std::mem::drop(x) to drop early — you can't call Drop::drop yourself.
Q. Can you call MyType::drop(x) directly?
Reveal hint
No. That would let you destroy an object twice. Use std::mem::drop(x) to trigger drop early; the compiler enforces single-drop.

5. Encapsulation via Module Privacy

pub mod account {
    pub struct Account {
        balance: f64,                 // private field
    }

    impl Account {
        pub fn new(initial: f64) -> Result<Self, String> {
            if initial < 0.0 { return Err("negative".into()); }
            Ok(Self { balance: initial })
        }
        pub fn balance(&self) -> f64 { self.balance }
        pub fn deposit(&mut self, amount: f64) -> Result<(), String> {
            if amount < 0.0 { return Err("negative".into()); }
            self.balance += amount;
            Ok(())
        }
    }
}
Rule of thumb: your invariants live inside impl blocks. Because fields default to private, external callers must go through your methods. Unlike Java's private, this is enforced by the module system, not just field-by-field.

6. "Inheritance" — there isn't any

Rust deliberately omits inheritance. The tools you use instead:

GoalRust tool
Share method bodiesTrait with default method implementations.
"is-a" substitutabilityUse a trait; &dyn Trait everywhere both can appear.
"has-a" for reusePlain composition — embed the struct as a field.
Forward methodsImplement Deref / AsRef — used cautiously.
Extension methodsDefine a new trait + blanket impl.
 
pub trait Greet {
    fn name(&self) -> &str;
    // default implementation
    fn hello(&self) -> String {
        format!("hi {}", self.name())
    }
}

struct Dog { name: String }
impl Greet for Dog {
    fn name(&self) -> &str { &self.name }
    // hello() inherited automatically
}
Q. I want "Cat IS-A Animal with extra stuff". Do I subclass Animal?
Reveal hint
You don't. Define trait Animal with the behavior you care about. Make Cat and Dog each implement it. Use &dyn Animal or impl Animal as the base type.

7. Polymorphism — Traits & dyn

Static dispatch (monomorphization)

fn shout<T: Greet>(x: &T) { println!("{}!", x.hello()); }
// OR equivalently (impl Trait):
fn shout2(x: &impl Greet) { println!("{}!", x.hello()); }

Dynamic dispatch (trait object)

fn shout_dyn(x: &dyn Greet) { println!("{}!", x.hello()); }

let items: Vec<Box<dyn Greet>> = vec![
    Box::new(Dog{ name: "Rex".into() }),
    Box::new(Cat{ name: "Ada".into() }),
];
for it in &items { shout_dyn(it.as_ref()); }
AspectStatic dispatch (impl Trait, generics)Dynamic dispatch (dyn Trait)
HowCompiler generates a copy per concrete type (monomorphization).Runtime vtable lookup via fat pointer.
SpeedInline-friendly; fastest.Indirect call; small cost.
Binary sizeCan grow with type combinations.Compact.
Heterogeneous collectionNot possible — all elements same type.Perfect fit: Vec<Box<dyn Trait>>.
Object safetyDoesn't matter.Trait must be object-safe: no generic methods, no Self by value in return.
Watch — object safety: fn clone(&self) -> Self makes a trait not object-safe (return type is Self). You can't make Box<dyn Clone>. Workaround: dyn_clone crate or separate method returning Box<dyn Trait>.
Q. I want fast dispatch and still want the speed of generics. Static or dynamic?
Reveal hint
Static (impl Trait / T: Trait). Compiler generates specialized code per concrete type. Use dyn when you need heterogeneous containers or to reduce binary size.

8. Abstraction via Trait Objects

pub trait Shape {
    fn area(&self) -> f64;
    fn name(&self) -> &str;
}

pub struct Circle { pub r: f64 }
impl Shape for Circle {
    fn area(&self) -> f64 { std::f64::consts::PI * self.r.powi(2) }
    fn name(&self) -> &str { "circle" }
}
Tip — default methods: put shared logic into the trait itself with fn foo(&self) { … }. That's Rust's "template method" pattern.

Q. Two fn new(x: i32) and fn new(x: &str) in the same impl — does it compile?
Reveal hint
No, duplicate name. Use different names, or a generic fn new<T: Into<X>>(x: T), or implement From.

Q. Difference between const and static?
Reveal hint
const is inlined at each use site (no fixed address). static has a single address and lifetime 'static. Mutable statics require unsafe.

Q. Why doesn't Rust need super?
Reveal hint
No inheritance. When you call a trait's default implementation from your own impl, that's still just calling a trait method — qualified with Trait::method(&self) if needed.

16b. Is-a vs Has-a — Deep Dive (Rust examples)

Rust folds both ideas into traits + composition:
• is-a → "X implements trait Y" (and can be used wherever a &dyn Y / impl Y is expected).
• has-a → "X has a field of type Y".
There's no "subclass" relationship at all; composition is the only structural reuse mechanism.

Snippets — the right way

// IS-A via trait: Circle and Square share the Shape capability
pub trait Shape { fn area(&self) -> f64; }
pub struct Circle { pub r: f64 }
pub struct Square { pub side: f64 }
impl Shape for Circle { fn area(&self) -> f64 { std::f64::consts::PI * self.r.powi(2) } }
impl Shape for Square { fn area(&self) -> f64 { self.side.powi(2) } }
// HAS-A composition: Car owns Engine + Wheels, borrows Logger
pub struct Car<'a> {
    pub engine: Engine,
    pub wheels: [Wheel; 4],
    pub log:    &'a dyn Logger,
}
// Decorator: new struct wraps another and forwards trait methods
pub struct BufferedWriter<W: Write> { inner: W, buf: Vec<u8> }
impl<W: Write> Write for BufferedWriter<W> { /* flushes buffered data to self.inner */ }

Red flags ("I think I want subclass")

  • You want to "extend" a struct to add a method — use a trait with a blanket impl or a free function.
  • You want method override — define a trait with a default method, implement it differently per type.
  • You want "common fields" — embed them as fields in every struct, or use composition.
  • You want heterogeneous collection — Vec<Box<dyn Trait>> or enum variants.
Q. How do you share behavior without inheritance?
Reveal hint
Traits with default method bodies. Any type implementing the trait inherits the default unless it overrides — this is like Java's default interface methods, just at the language core.

17. Downcasting — Any

Rust has no RTTI by default. To downcast a trait object you need std::any::Any.

use std::any::Any;

fn inspect(v: &dyn Any) {
    if let Some(s) = v.downcast_ref::<String>() {
        println!("string: {s}");
    } else if let Some(n) = v.downcast_ref::<i32>() {
        println!("int: {n}");
    }
}
Watch: Any requires 'static. You cannot downcast borrowed data with non-static lifetimes.
Q. Why does idiomatic Rust rarely reach for Any?
Reveal hint
Long downcast ladders are an anti-pattern. Prefer an enum of variants (closed set) or add a trait method that distinguishes cases polymorphically.

18. Immutability by Default

RequirementHow
Variables immutableDefault. let x = 5; can't be reassigned.
Struct fields immutableBindings decide. If let p = Point{..};, you can't mutate p.x through p.
Interior mutabilityCell<T>, RefCell<T>, Mutex<T>, RwLock<T>, AtomicI32. Mutate through &.
Frozen recordsExpose only getters; no &mut self methods.
Deep immutabilityUse Arc<T> for shared-read, not Arc<Mutex<T>>.
Q. Why use RefCell if the compiler already enforces borrowing?
Reveal hint
It moves the borrow check to runtime. Useful when the compile-time check is too restrictive (e.g., graph structures, callbacks). Panics if you break the rules.

19. Errors — Result & ?

ToolPurpose
Result<T, E>Either Ok(T) or Err(E) — no exceptions.
Option<T>Some(T) or None — Rust's null.
? operatorEarly-return on Err / None. Must match the function's return type.
thiserror / anyhowCrates: thiserror for library errors, anyhow for application boundaries.

From blanket implLets ? auto-convert error types.
 
fn read_config(path: &str) -> Result<Config, MyError> {
    let text = std::fs::read_to_string(path)?;     // io::Error → MyError via From
    let cfg  = serde_json::from_str(&text)?;         // serde_json::Error → MyError
    Ok(cfg)
}
Tip: prefer ? and Result throughout. Save .unwrap() / .expect() for prototypes and tests; they panic.
Q. Can Rust "throw" and "catch"?
Reveal hint
Not exceptions in the Java sense. panic! unwinds the stack (can be caught with catch_unwind at a boundary), but normal error flow uses Result + ?.

21. Ownership / Borrowing / Lifetimes — the "C++ RAII" done right

RuleMeaning
Single ownerEvery value has exactly one owner. When the owner drops, the value drops.
Move by defaultAssigning or passing a non-Copy value moves it — the source is invalidated.
Borrow rulesMany &T OR one &mut T — never both.
LifetimesCompiler tracks how long references are valid. Explicit in signatures when ambiguous.
Smart pointersBox<T> heap; Rc<T> shared single-threaded; Arc<T> shared across threads; Weak<T> non-owning.
 
fn longest<'a>(a: &'a str, b: &'a str) -> &'a str {
    if a.len() >= b.len() { a } else { b }
}
TopicWrongRight
Dangling referenceReturning a &T to a local.Return the value, or take it as a borrowed input and return the borrow.
Aliased mutationTwo &mut to the same value.Compiler refuses — restructure, or use RefCell/Mutex.
Cycle in RcRc-reachable cycle.Break with Weak<T> — Rc/Arc don't detect cycles.

Q. Why does Rust panic on an Rc cycle instead of silently leaking?
Reveal hint
It doesn't panic — Rc cycles leak memory silently. Prevent by downgrading one side to Weak<T>.

Quick Interview Gotchas

#GotchaAnswer
1Does Rust have inheritance?No. Traits + default methods + composition.
2Does Rust have exceptions?No. Result<T, E> + ?. panic! is for unrecoverable bugs.
3What is Self vs self?Self (capital) is the current type. self is the instance parameter.
4Why does Vec<dyn Trait> not compile?Trait objects are unsized. Use Vec<Box<dyn Trait>> or Vec<&dyn Trait>.
5Can a closure live longer than captured references?Only if you move the captures. Otherwise lifetimes will keep it short.
6Does Copy imply Clone?Yes — Copy requires Clone. Copy is bitwise, Clone can be arbitrary.
7Can you extend a struct from another crate?Not by inheritance. Define a trait (in your crate) and impl it for the foreign struct (orphan rule: one of the trait or the type must be yours).
8Why can't I have static mut without unsafe?Unsynchronized global mutation is a data-race risk. Use Mutex, RwLock, or atomics.
9What is object safety?A trait is object-safe (usable as dyn Trait) if no method takes Self by value or has generic type parameters.
10What's the "orphan rule"?To implement Trait for Type, at least one of them must be defined in your crate. Prevents conflicting impls.
