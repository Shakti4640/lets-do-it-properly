Section 00 — The Idea

What is K-Way Merge?

You have K sorted lists. You want to combine them into one sorted output — or find the Kth smallest element across all of them.

The naive way? Dump everything into one array and sort it → O(n·K log(n·K)). That's slow and wastes the fact that lists are already sorted.

The smart way? Use a Min-Heap (Priority Queue). Always pull the globally smallest element in O(log K) time. This is the entire pattern.

Core Insight: At any moment, the next element in the merged output must be the smallest among all current front elements of the K lists. A min-heap lets you find that in O(log K) instead of O(K).

Section 01 — The Heap Trick

What do you store in the heap?

This is the most important design decision. You never store just the value. You always store enough info to fetch the next element.

❌ Wrong — just values

  • heap.add(node.val)
  • After popping, you don't know which list it came from
  • Can't fetch the next element
  • Works only for finding min, not for full merge

✅ Right — store a tuple

  • heap.add(new int[]{value, listIndex, elementIndex})
  • After popping, you know exactly which list and position
  • Can advance that pointer and push next element
  • Works for any K-way merge problem
For LinkedList problems: Store the ListNode itself in the heap. The comparator uses node.val. After popping, push node.next.
Section 02 — Core Template

The Master Template

Two versions: one for arrays, one for linked lists. Same logic, different data.

1
Initialize: Push the first element (head) of each of the K lists into a min-heap
2
Pop min: Extract the smallest element from the heap — this goes into your output
3
Push next: From whatever list the popped element came from, push its next element into the heap
4
Repeat until the heap is empty

Version A — For K Sorted Arrays

import java.util.*;

public class KWayMerge {

    /**
     * Merge K sorted arrays into one sorted list.
     * Time:  O(n log k)  — n total elements, k lists in heap
     * Space: O(k)        — heap holds at most k elements at once
     */
    public List<Integer> mergeKSortedArrays(int[][] arrays) {

        // Min-heap stores: [value, listIndex, elementIndex]
        PriorityQueue<int[]> heap = new PriorityQueue<>((a, b) -> a[0] - b[0]);

        // ── STEP 1: Push first element of each list ────────────
        for (int i = 0; i < arrays.length; i++) {
            if (arrays[i].length > 0) {
                heap.offer(new int[]{arrays[i][0], i, 0});
                //                    ^value  ^list  ^index
            }
        }

        List<Integer> result = new ArrayList<>();

        // ── STEPS 2 & 3: Pop min, push next ────────────────────
        while (!heap.isEmpty()) {
            int[] curr = heap.poll();
            int val   = curr[0];
            int li    = curr[1]; // which list
            int idx   = curr[2]; // which position in that list

            result.add(val);   // ✅ smallest element goes to output

            // Push next element from the same list (if exists)
            if (idx + 1 < arrays[li].length) {
                heap.offer(new int[]{arrays[li][idx + 1], li, idx + 1});
            }
        }

        return result;
    }
}

Version B — For K Sorted Linked Lists (LC #23)

// ListNode definition
class ListNode {
    int val;
    ListNode next;
    ListNode(int val) { this.val = val; }
}

public ListNode mergeKLists(ListNode[] lists) {

    // Comparator on node.val — heap stores actual nodes
    PriorityQueue<ListNode> heap =
        new PriorityQueue<>((a, b) -> a.val - b.val);

    // ── Push head of each list ──────────────────────────────
    for (ListNode node : lists) {
        if (node != null) heap.offer(node);
    }

    ListNode dummy = new ListNode(0); // dummy head trick
    ListNode tail  = dummy;

    while (!heap.isEmpty()) {
        ListNode curr = heap.poll();   // smallest node
        tail.next = curr;
        tail = tail.next;              // advance result pointer

        if (curr.next != null) {
            heap.offer(curr.next);     // push next node from same list
        }
    }

    return dummy.next; // skip dummy head
}

Section 04 — Code for Each Type

Type-by-Type Templates

Type 02 — Kth Smallest in K Sorted Lists

Same as full merge — but stop early. After popping K elements, you have your answer. You never build the full merged list.

public int kthSmallest(int[][] arrays, int k) {

    PriorityQueue<int[]> heap =
        new PriorityQueue<>((a, b) -> a[0] - b[0]);

    for (int i = 0; i < arrays.length; i++) {
        if (arrays[i].length > 0)
            heap.offer(new int[]{arrays[i][0], i, 0});
    }

    int count = 0, result = -1;

    while (!heap.isEmpty()) {
        int[] curr = heap.poll();
        result = curr[0];
        count++;

        if (count == k) return result;  // ✅ Stop early!

        int li = curr[1], idx = curr[2];
        if (idx + 1 < arrays[li].length)
            heap.offer(new int[]{arrays[li][idx + 1], li, idx + 1});
    }

    return result;
}

Type 03 — Smallest Range Covering K Lists (LC #632)

Keep one element from each list in the heap at all times. Track the current max separately. The range is [heap_min, current_max]. Shrink it greedily by advancing the list that holds the current minimum.

public int[] smallestRange(List<List<Integer>> nums) {

    // heap stores: [value, listIndex, elementIndex]
    PriorityQueue<int[]> heap =
        new PriorityQueue<>((a, b) -> a[0] - b[0]);

    int curMax = Integer.MIN_VALUE;

    // Seed: push first element of every list
    for (int i = 0; i < nums.size(); i++) {
        int val = nums.get(i).get(0);
        heap.offer(new int[]{val, i, 0});
        curMax = Math.max(curMax, val);
    }

    int[] best = {0, Integer.MAX_VALUE};

    while (heap.size() == nums.size()) {  // must keep one from each list
        int[] curr = heap.poll();
        int curMin = curr[0], li = curr[1], idx = curr[2];

        // Update best range if current [min, max] is smaller
        if (curMax - curMin < best[1] - best[0]) {
            best = new int[]{curMin, curMax};
        }

        // Advance the list that had the minimum (the popped one)
        if (idx + 1 < nums.get(li).size()) {
            int nextVal = nums.get(li).get(idx + 1);
            heap.offer(new int[]{nextVal, li, idx + 1});
            curMax = Math.max(curMax, nextVal);
        }
        // else: a list is exhausted → heap.size() drops → loop ends
    }

    return best;
}

Type 04 — K Pairs with Smallest Sums (LC #373)

Think of it as a virtual matrix: matrix[i][j] = nums1[i] + nums2[j]. Each row is already sorted. Start with first element of each row and explore lazily.

public List<List<Integer>> kSmallestPairs(int[] n1, int[] n2, int k) {

    List<List<Integer>> res = new ArrayList<>();
    if (n1.length == 0 || n2.length == 0) return res;

    // heap stores: [sum, i, j] where sum = n1[i] + n2[j]
    PriorityQueue<int[]> heap =
        new PriorityQueue<>((a, b) -> a[0] - b[0]);

    // Seed: fix each i, start with j=0
    for (int i = 0; i < Math.min(n1.length, k); i++) {
        heap.offer(new int[]{n1[i] + n2[0], i, 0});
    }

    while (!heap.isEmpty() && res.size() < k) {
        int[] curr = heap.poll();
        int i = curr[1], j = curr[2];

        res.add(Arrays.asList(n1[i], n2[j]));

        // Only advance j (column) — i is fixed per "row"
        if (j + 1 < n2.length) {
            heap.offer(new int[]{n1[i] + n2[j + 1], i, j + 1});
        }
    }

    return res;
}

Type 05 — Kth Smallest in Sorted Matrix (LC #378)

Each row of the matrix is a sorted list. Treat it as K sorted lists and find the Kth element.

public int kthSmallestMatrix(int[][] matrix, int k) {

    int n = matrix.length;
    // heap: [value, row, col]
    PriorityQueue<int[]> heap =
        new PriorityQueue<>((a, b) -> a[0] - b[0]);

    // Push first element of each row
    for (int r = 0; r < Math.min(n, k); r++) {
        heap.offer(new int[]{matrix[r][0], r, 0});
    }

    int count = 0, result = 0;

    while (!heap.isEmpty()) {
        int[] curr = heap.poll();
        result = curr[0];
        int r = curr[1], c = curr[2];
        count++;

        if (count == k) return result;  // done!

        if (c + 1 < n)
            heap.offer(new int[]{matrix[r][c + 1], r, c + 1});
    }

    return result;
}
Section 05 — Complexity

Time & Space Summary

Problem TypeTimeSpaceKey Note
Merge K Sorted Lists/ArraysO(n log k)O(k)n = total elements, k = num lists
Kth Smallest (stop early)O(k log k)O(k)Only pop k times, not all n
Smallest Range (LC 632)O(n log k)O(k)n = total elements across lists
K Pairs Smallest SumsO(k log k)O(k)Seed with min(n1.len, k) rows
Kth Smallest in MatrixO(k log n)O(n)n = matrix row count
Why O(n log k) and not O(n log n)? Because the heap only ever holds K elements at a time. Each push/pop is O(log k), and you do it n times → O(n log k). Since k ≤ n, this is always faster than sorting.
Section 06 — Quick Reference

The "Which Approach?" Cheat Sheet

If the problem says…→ ApproachHeap stores
"merge K sorted lists"Master template, full output[node] or [val, list, idx]
"Kth smallest across K lists"Stop after K pops[val, list, idx]
"smallest range from K lists"Keep one per list, track max[val, list, idx] + curMax
"K pairs with smallest sums"Virtual matrix, fix i advance j[sum, i, j]
"Kth smallest in sorted matrix"Each row = one list[val, row, col]
Interview tip: The moment you see "K sorted" + "smallest/merge", say — "I'll use a min-heap. I'll seed it with the first element of each list and then pop-and-push until done. Time complexity will be O(n log k)." That's the entire pattern in one sentence.
K-Way Merge vs Merge Intervals: They sound similar but are different. Merge Intervals = sort + scan on a single list of ranges. K-Way Merge = heap-based extraction across K independently sorted sequences.

Section 08 — Edge Cases

Pitfalls & Boundary Decisions

!
Empty lists in the input
Always guard with if (arrays[i].length > 0) (or node != null) before seeding. Pushing from an empty list throws or corrupts the heap.
!
Comparator overflow
For large values use Integer.compare(a[0], b[0]) instead of a[0] - b[0]; the subtraction can overflow int range.
!
Storing value only
For arrays you must store [value, list, idx]. With just the value you can't find the next element to push.
!
Smallest-range loop guard
LC #632 loops while (heap.size() == numLists). The moment any list is exhausted the range can't cover all K — stop immediately.
!
Seeding more than needed
For "K pairs / Kth smallest" seed only min(len, k) rows — seeding all n rows wastes memory and time.
!
All elements equal
Ties are fine — the heap just pops them in arbitrary order. Output stays sorted because equal keys are interchangeable.
When NOT to use a heap: if you only have two sorted lists, a plain two-pointer merge is simpler and O(n) with no log factor. The heap pays off once K ≥ 3 (or K is large/unknown).
