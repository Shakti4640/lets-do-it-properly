Section 00 — The Idea

What even is "merging intervals"?

An interval is just a range — like a meeting from 2pm to 4pm, or an array range [2, 4]. The core question is: do two intervals overlap?

Two intervals [a, b] and [c, d] overlap if b >= c (assuming a ≤ c after sorting). If they overlap, you merge them into [a, max(b, d)].

Input A
[1, 4]
Input B
[3, 6]
Input C
[8,11]
↓ merge overlapping
Merged
[1, 6]
Kept
[8,11]

A overlaps B (4 ≥ 3), so they merge → [1,6]. C doesn't overlap [1,6] (8 > 6), so it stays separate.

Golden Rule: Always sort by start time first. After that, a single left-to-right scan is enough to merge everything. That's the whole trick.
Section 01 — Core Template

The Master Template

This one function covers ~70% of all Merge Intervals problems. Read it once, understand it forever.

1
Sort all intervals by their start value → O(n log n)
2
Start with the first interval as your "current" working interval
3
Scan each remaining interval: if it overlaps current, expand current's end; else save current and move on
4
Return the result list
import java.util.*;

public class MergeIntervals {

    /**
     * Merge all overlapping intervals.
     * Time:  O(n log n)  ← sorting dominates
     * Space: O(n)        ← result list
     */
    public int[][] merge(int[][] intervals) {

        // Edge case: 0 or 1 interval → nothing to merge
        if (intervals == null || intervals.length <= 1) return intervals;

        // ── STEP 1: Sort by start time ─────────────────────────
        Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));

        List<int[]> result = new ArrayList<>();

        // ── STEP 2: Start with the first interval ──────────────
        int[] curr = intervals[0].clone(); // clone to avoid mutating input

        // ── STEP 3: Scan remaining intervals ───────────────────
        for (int i = 1; i < intervals.length; i++) {
            int[] next = intervals[i];

            if (curr[1] >= next[0]) {
                // ✅ Overlap! Expand current's end if needed
                curr[1] = Math.max(curr[1], next[1]);
            } else {
                // ❌ No overlap. Save current, move to next
                result.add(curr);
                curr = next.clone();
            }
        }

        result.add(curr); // Don't forget the last interval!

        return result.toArray(new int[result.size()][]);
    }
}
Common mistake: Forgetting result.add(curr) after the loop. The last interval never gets added inside the loop — always add it after!

Section 03 — Code for Each Type

Type-by-Type Templates

Type 02 — Insert Interval (LC #57)

You're given a sorted non-overlapping list. Add a new interval and merge. Easiest trick: just add it to the list and call merge.

public int[][] insert(int[][] intervals, int[] newInterval) {

    List<int[]> list = new ArrayList<>(Arrays.asList(intervals));
    list.add(newInterval);           // just throw it in

    return merge(list.toArray(new int[0][]));  // reuse the master template!
}

Type 03 — Remove Minimum (Non-overlapping, LC #435)

Question: "How many intervals to remove so none overlap?" Answer: total intervals minus how many survive after merging.

public int eraseOverlapIntervals(int[][] intervals) {

    int[][] merged = merge(intervals);   // use master template

    // intervals that "disappeared" during merge = ones we must remove
    return intervals.length - merged.length;
}

Type 04 — Interval Intersections (LC #986)

Two separate sorted lists. Find their overlapping parts. Use 2-pointer: at each step, collect intersection and advance the pointer with the smaller end.

public int[][] intervalIntersection(int[][] A, int[][] B) {

    List<int[]> res = new ArrayList<>();
    int i = 0, j = 0;

    while (i < A.length && j < B.length) {

        // Intersection = overlap between A[i] and B[j]
        int lo = Math.max(A[i][0], B[j][0]);
        int hi = Math.min(A[i][1], B[j][1]);

        if (lo <= hi)
            res.add(new int[]{lo, hi});  // valid intersection

        // Advance the pointer with smaller end time
        if (A[i][1] < B[j][1]) i++;
        else j++;
    }

    return res.toArray(new int[res.size()][]);
}

Type 05 — Meeting Rooms II (LC #253)

Simple merge doesn't work here. You need the peak number of simultaneous meetings. A min-heap tracks ongoing meeting end times.

public int minMeetingRooms(int[][] intervals) {

    // Sort by start time (same as always)
    Arrays.sort(intervals, (a, b) -> a[0] - b[0]);

    // Min-heap of end times = rooms currently in use
    PriorityQueue<Integer> heap = new PriorityQueue<>();

    for (int[] m : intervals) {
        if (!heap.isEmpty() && heap.peek() <= m[0]) {
            heap.poll();   // earliest room is free, reuse it
        }
        heap.add(m[1]);   // allocate a room ending at m[1]
    }

    return heap.size(); // rooms still occupied = answer
}

Type 06 — Burst Balloons / Min Arrows (LC #452)

Sort by end time (not start). Greedily place an arrow at each balloon's end point — it bursts all overlapping balloons too.

public int findMinArrowShots(int[][] points) {

    // KEY difference: sort by END time, not start!
    Arrays.sort(points, (a, b) -> Integer.compare(a[1], b[1]));

    int arrows = 1;
    int arrowPos = points[0][1]; // shoot at end of first balloon

    for (int i = 1; i < points.length; i++) {
        if (points[i][0] > arrowPos) {    // balloon starts after last arrow
            arrows++;
            arrowPos = points[i][1];        // fire new arrow
        }
        // else: current arrow already bursts this balloon
    }

    return arrows;
}

Type 07 — Find Free Time / Gaps (LC #759)

Merge everything first. Then look at the "holes" between consecutive merged intervals — those are your free slots.

public List<int[]> employeeFreeTime(int[][] allIntervals) {

    List<int[]> merged = mergeToList(allIntervals); // use master template
    List<int[]> freeTime = new ArrayList<>();

    for (int i = 1; i < merged.size(); i++) {
        int gapStart = merged.get(i - 1)[1]; // end of prev interval
        int gapEnd   = merged.get(i)[0];     // start of next interval
        freeTime.add(new int[]{gapStart, gapEnd});
    }

    return freeTime;
}

Section 05 — Quick Reference

The "Which Template?" Cheat Sheet

Sort by start? → Types 1, 2, 3, 4, 5, 7 all sort by start time.
Sort by end? → Only Type 6 (Burst Balloons / Arrows).
Need a heap? → Only Type 5 (Meeting Rooms II).
Two lists? → Type 4 uses 2-pointer, not the merge template.
If the problem says…→ Use this approach
"merge overlapping intervals"Master template directly
"insert and merge"Add to list, call merge
"minimum removals / non-overlapping"merge → count difference
"can attend all meetings?"If merge changes nothing → true
"minimum rooms / resources"Sort start + min-heap of ends
"minimum arrows / points"Sort by END + greedy counter
"find intersection of two lists"2-pointer: max(lo), min(hi)
"find free time / gaps"Merge all, collect gaps
Interview tip: As soon as you see intervals, say out loud — "I'll sort by start time first, then do a linear scan." That signals to the interviewer that you know the pattern. Then adapt based on what they actually want.

Tracing the Master Template

Input: [[1,3], [2,6], [8,10], [15,18]]. Already sorted by start. Watch curr evolve.

Watch the merge at i=1: the end becomes max(3, 6) = 6, not just 6. If the next interval is fully swallowed (e.g. current [1,10] meets [2,4]), max keeps the larger existing end. Using plain assignment here is the most common bug.
Section 07 — Edge Cases

Pitfalls & Boundary Decisions

!
Touching = overlap?
Do [1,2] and [2,3] merge? For number ranges, usually yes (use >=). For half-open time slots, often no (use >). Always confirm.
!
Empty / single input
Length 0 or 1 → return as-is. The master template guards this up front so the intervals[0] access never throws.
!
Mutating the input
We clone() the first interval. Without it, extending curr[1] would silently edit the caller's array.
!
Forgetting the last add
The loop only saves curr when a non-overlap appears. The final curr always needs an explicit add after the loop.
!
Sort comparator overflow
Prefer Integer.compare(a[0], b[0]) over a[0] - b[0]; subtraction overflows for large/negative coordinates.
!
Already sorted?
If the input is guaranteed sorted by start, skip the sort and the whole pass drops to O(n).
Overlap test, stated precisely: after sorting by start, intervals curr and next overlap iff curr.end ≥ next.start. You never need to compare starts again — sorting guarantees curr.start ≤ next.start.
