Section 00 — The Idea

What is the Sliding Window?

You have a contiguous sequence — an array or a string — and you want something about a range of it: the longest substring, the max sum of K elements, the smallest window containing a target. The brute force checks every sub-range in O(n²) or worse.

The sliding window keeps two pointers — a left and a right — that bound a window. You expand right to include new elements, and shrink left when the window breaks a rule. Each element enters and leaves the window at most once, so the whole scan is O(n).

Core Insight: Instead of recomputing each window from scratch, you reuse the previous window's work — add the entering element, remove the leaving one. That incremental update is what turns O(n²) into O(n).

Section 01 — Two Flavours

Fixed vs Dynamic Windows

Every sliding window problem is one of two kinds. Recognising which one you're facing tells you the entire loop structure.

Fixed-size window

  • Window length k is given and never changes
  • right advances every step; left follows k behind
  • Add arr[right], remove arr[right - k]
  • Examples: max sum of k, averages, anagrams

Dynamic (variable) window

  • Window grows and shrinks based on a condition
  • right expands; left shrinks via a while loop
  • "Longest valid" or "shortest valid" subarray
  • Examples: longest no-repeat, min window substring
The deciding question: "Is the window size handed to me?" If yes → fixed. If the problem asks for the longest/shortest window meeting some rule → dynamic, and you'll shrink left in a while loop.
Section 02 — Core Templates

The Two Master Templates

Memorise these two skeletons. Almost every sliding window problem is an adaptation of one of them.

1
Expand: move right forward, pulling the new element into the window state
2
Check: is the window still valid? (size reached, or condition satisfied / violated)
3
Shrink: move left forward, removing elements until the window is valid again
4
Record: update your answer at the right moment (inside or after the shrink)

Template A — Fixed-size window

import java.util.*;

public class FixedWindow {

    /**
     * Max sum of any window of exactly size k.
     * Time:  O(n)   ← each element added & removed once
     * Space: O(1)
     */
    public int maxSumFixed(int[] nums, int k) {

        int windowSum = 0, best = Integer.MIN_VALUE;
        int left = 0;

        for (int right = 0; right < nums.length; right++) {

            windowSum += nums[right];          // ── 1. expand: add entering element

            if (right - left + 1 == k) {        // ── 2. window is full
                best = Math.max(best, windowSum); // ── 4. record answer
                windowSum -= nums[left];       // ── 3. shrink: drop leaving element
                left++;
            }
        }
        return best;
    }
}

Template B — Dynamic window (longest valid)

/**
 * Generic "longest window satisfying a condition".
 * Expand always; shrink only while the window is INVALID.
 * Time:  O(n)   Space: O(k) for the state map
 */
public int longestValid(int[] nums) {

    Map<Integer, Integer> state = new HashMap<>();
    int left = 0, best = 0;

    for (int right = 0; right < nums.length; right++) {

        // ── 1. expand: include nums[right] in the window state
        state.merge(nums[right], 1, Integer::sum);

        // ── 3. shrink while the window breaks the rule
        while (windowIsInvalid(state)) {
            int leaving = nums[left++];
            if (state.merge(leaving, -1, Integer::sum) == 0)
                state.remove(leaving);
        }

        // ── 4. record: window [left..right] is now valid
        best = Math.max(best, right - left + 1);
    }
    return best;
}
Shortest vs Longest — the flip: For longest, you record the answer after the while-shrink (window is valid). For shortest, you flip it: shrink while the window is still valid and record inside that while loop, capturing the smallest valid window before it breaks.

Section 04 — Code for Each Type

Type-by-Type Templates

Type 02 — Longest Substring Without Repeating Characters (LC #3)

Keep the last index of each character. When a repeat falls inside the window, jump left past its previous position.

public int lengthOfLongestSubstring(String s) {

    Map<Character, Integer> lastSeen = new HashMap<>();
    int left = 0, best = 0;

    for (int right = 0; right < s.length(); right++) {
        char c = s.charAt(right);

        // If c is in the window, move left past its last occurrence
        if (lastSeen.containsKey(c) && lastSeen.get(c) >= left) {
            left = lastSeen.get(c) + 1;
        }

        lastSeen.put(c, right);
        best = Math.max(best, right - left + 1); // window is always valid here
    }
    return best;
}

Type 03 — Longest Substring with At Most K Distinct (LC #340)

Count distinct characters with a frequency map. Shrink from the left while the map holds more than K keys.

public int lengthOfLongestSubstringKDistinct(String s, int k) {

    Map<Character, Integer> freq = new HashMap<>();
    int left = 0, best = 0;

    for (int right = 0; right < s.length(); right++) {
        freq.merge(s.charAt(right), 1, Integer::sum);

        // Too many distinct → shrink until we're back to k
        while (freq.size() > k) {
            char leaving = s.charAt(left++);
            if (freq.merge(leaving, -1, Integer::sum) == 0)
                freq.remove(leaving);
        }

        best = Math.max(best, right - left + 1);
    }
    return best;
}

Type 04 — Minimum Window Substring (LC #76)

The classic "shortest valid" window. Expand until the window covers every needed character, then shrink greedily to find the smallest such window.

public String minWindow(String s, String t) {

    if (s.length() < t.length()) return "";

    int[] need = new int[128];
    for (char c : t.toCharArray()) need[c]++;

    int left = 0, missing = t.length();
    int bestLen = Integer.MAX_VALUE, bestStart = 0;

    for (int right = 0; right < s.length(); right++) {
        if (need[s.charAt(right)]-- > 0) missing--; // consumed a needed char

        // Window is valid — try to shrink it from the left
        while (missing == 0) {
            if (right - left + 1 < bestLen) {
                bestLen = right - left + 1;
                bestStart = left;
            }
            if (need[s.charAt(left)]++ == 0) missing++; // about to break validity
            left++;
        }
    }
    return bestLen == Integer.MAX_VALUE ? "" : s.substring(bestStart, bestStart + bestLen);
}

Type 05 — Find All Anagrams (LC #438)

Fixed window the size of the pattern. Compare frequency arrays as the window slides; a match means the window is an anagram.

public List<Integer> findAnagrams(String s, String p) {

    List<Integer> res = new ArrayList<>();
    if (s.length() < p.length()) return res;

    int[] need = new int[26], win = new int[26];
    for (char c : p.toCharArray()) need[c - 'a']++;

    int k = p.length();
    for (int right = 0; right < s.length(); right++) {
        win[s.charAt(right) - 'a']++;          // add entering char

        if (right >= k)                            // window overflowed size k
            win[s.charAt(right - k) - 'a']--;     // remove leaving char

        if (Arrays.equals(win, need))
            res.add(right - k + 1);              // window start index
    }
    return res;
}

Type 06 — Sliding Window Maximum (LC #239)

A plain max-per-window is O(n·k). A monotonic deque of indices — kept in decreasing value order — gives O(n). The front of the deque is always the current window's maximum.

public int[] maxSlidingWindow(int[] nums, int k) {

    int n = nums.length;
    int[] res = new int[n - k + 1];
    Deque<Integer> dq = new ArrayDeque<>(); // stores indices, values decreasing

    for (int right = 0; right < n; right++) {

        // Drop indices that fell out of the window on the left
        if (!dq.isEmpty() && dq.peekFirst() <= right - k)
            dq.pollFirst();

        // Pop smaller values from the back — they can never be the max
        while (!dq.isEmpty() && nums[dq.peekLast()] < nums[right])
            dq.pollLast();

        dq.offerLast(right);

        if (right >= k - 1)                  // window fully formed
            res[right - k + 1] = nums[dq.peekFirst()];
    }
    return res;
}
Section 05 — Complexity

Time & Space Summary

Problem TypeTimeSpaceKey Trick
Fixed-size max / averageO(n)O(1)Running sum, slide by 1
Longest no-repeatO(n)O(min(n, charset))Jump left past duplicate
Longest at-most-K distinctO(n)O(k)Shrink while size > k
Minimum window substringO(n + m)O(charset)Shrink while still valid

Sliding window maximumO(n)O(k)Monotonic decreasing deque
Why O(n) and not O(n²)? Both left and right only ever move forward. Across the whole run, each pointer travels at most n steps, so the total work is 2n → O(n) — even though there's a nested while loop, it never resets.
Section 06 — Quick Reference

The "Which Window?" Cheat Sheet

Fixed size given? → Template A: slide by 1, add right / drop right−k.
"Longest … such that"? → Template B: record after the shrink loop.
"Shortest / minimum … such that"? → Shrink while valid, record inside the shrink.
"Window maximum / minimum"? → Monotonic deque, not a plain scan.
If the problem says…→ Use this approach
"max/min sum of k consecutive"Fixed window, running sum
"longest substring without repeating"Dynamic + last-seen map
"at most K distinct / K replacements"Dynamic + shrink while > k
"smallest window containing all of t"Shortest variant, shrink while valid
"find all anagrams / permutation in"Fixed window + frequency match
"maximum in each window of size k"Monotonic deque of indices
"minimum size subarray sum ≥ target"Shortest variant on running sum
Interview tip: As soon as you see "contiguous subarray / substring" plus "longest / shortest / max / min", say out loud — "This is a sliding window. I'll expand right, and shrink left when the window breaks the condition. That's O(n)." Then decide fixed vs dynamic and whether you record before or after shrinking.
Common mistakes:
• Forgetting to update the answer at the right moment (before vs after shrink).
• Removing the leaving element from the state map but not deleting zero-count keys — breaks map.size() checks.
• Using a window when the subarray need not be contiguous — sliding window only works on contiguous ranges.

Section 08 — The Shortest Variant

Minimum Size Subarray Sum (LC #209)

This is the mirror image of "longest". You expand to satisfy the condition (sum ≥ target), then shrink while it still holds, recording the smallest valid window as you go.

public int minSubArrayLen(int target, int[] nums) {

    int left = 0, sum = 0;
    int best = Integer.MAX_VALUE;

    for (int right = 0; right < nums.length; right++) {
        sum += nums[right];                 // expand

        // Shrink WHILE the window is still valid (sum stays ≥ target)
        while (sum >= target) {
            best = Math.min(best, right - left + 1); // record inside the shrink
            sum -= nums[left++];
        }
    }
    return best == Integer.MAX_VALUE ? 0 : best;
}
Longest vs Shortest — the one-line difference: for longest you record after the shrink loop (window just became valid); for shortest you record inside the shrink loop (window is valid and you're squeezing it smaller). Same skeleton, opposite record point.
Section 09 — Edge Cases

Pitfalls & Boundary Decisions

!
No valid window exists
For shortest problems, initialise best = MAX_VALUE and return 0 (or -1) if it never changes. Don't return MAX_VALUE by accident.
!
Negative numbers
Classic sliding window assumes the window metric is monotonic as it grows. Negatives break "minimum subarray sum" — use a prefix-sum + deque instead.
!
Window size 0 / k > n
For fixed windows, bail early if k > nums.length. Otherwise the "window full" check never fires.
!
Stale map keys
When a count hits 0, remove() the key. Leaving zero-count entries corrupts any map.size()-based distinct check.
!
Deque holds indices
For window maximum, store indices not values — you need the index to know when a candidate has slid out of range.
!
Char vs Unicode
A 26- or 128-length array assumes ASCII. For full Unicode strings use a HashMap instead of a fixed array.
