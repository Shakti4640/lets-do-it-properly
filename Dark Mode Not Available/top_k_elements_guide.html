Section 00 — The Idea

What is the Top K pattern?

You have n elements and want the K largest, K smallest, or Kth element. The naive way sorts everything in O(n log n). The smart way uses a heap of size K — never more.

There are two heap flavours depending on what you want:

Max-Heap → find K Smallest

  • Heap holds K smallest seen so far
  • Max (biggest) sits at the top
  • New element smaller than top? → evict top, insert new
  • At end: heap = K smallest elements

Min-Heap → find K Largest

  • Heap holds K largest seen so far
  • Min (smallest of the big ones) sits at top
  • New element bigger than top? → evict top, insert new
  • At end: heap = K largest elements
Memory trick: To find K largest, use a min-heap. To find K smallest, use a max-heap. The heap type is always the opposite of what you're looking for!

Section 01 — Core Template

The Master Template

1
Create heap — min-heap for K largest, max-heap for K smallest
2
Stream elements one by one, adding each to the heap
3
If heap size exceeds K, call poll() — evicts the element that doesn't belong
4
When done, heap contains exactly the K elements you want. peek() gives the Kth element itself.

Version A — Top K Largest

import java.util.*;

/**
 * Top K Largest using Min-Heap of size K
 * Time:  O(n log k)
 * Space: O(k)
 */
public List<Integer> topKLargest(int[] nums, int k) {

    PriorityQueue<Integer> minHeap = new PriorityQueue<>(); // default = min

    for (int num : nums) {
        minHeap.offer(num);
        if (minHeap.size() > k)
            minHeap.poll(); // removes smallest → only top K stay
    }

    return new ArrayList<>(minHeap); // all K largest
}

// To get just the Kth largest: return minHeap.peek();

Version B — Top K Smallest

/**
 * Top K Smallest using Max-Heap of size K
 * Time:  O(n log k)
 * Space: O(k)
 */
public List<Integer> topKSmallest(int[] nums, int k) {

    PriorityQueue<Integer> maxHeap =
        new PriorityQueue<>(Collections.reverseOrder()); // max at top

    for (int num : nums) {
        maxHeap.offer(num);
        if (maxHeap.size() > k)
            maxHeap.poll(); // removes largest → only K smallest stay
    }

    return new ArrayList<>(maxHeap);
}

// To get just the Kth smallest: return maxHeap.peek();

Section 03 — Code for Each Type

Type-by-Type Templates

Type 01 — Kth Largest Element (LC #215)

Heap of size K. After processing all elements, the top of the heap is the Kth largest (smallest among the top K).

public int findKthLargest(int[] nums, int k) {

    PriorityQueue<Integer> minHeap = new PriorityQueue<>();

    for (int num : nums) {
        minHeap.offer(num);
        if (minHeap.size() > k) minHeap.poll();
    }

    return minHeap.peek(); // Kth largest = min of top-K heap
}

Type 02 — Top K Frequent Elements (LC #347)

Step 1: count frequencies. Step 2: min-heap keyed by frequency, evict least frequent when size exceeds K.

public int[] topKFrequent(int[] nums, int k) {

    // Step 1: frequency map
    Map<Integer, Integer> freq = new HashMap<>();
    for (int n : nums)
        freq.put(n, freq.getOrDefault(n, 0) + 1);

    // Step 2: min-heap by frequency — stores [element, freq]
    PriorityQueue<int[]> heap =
        new PriorityQueue<>((a, b) -> a[1] - b[1]);

    for (Map.Entry<Integer,Integer> e : freq.entrySet()) {
        heap.offer(new int[]{e.getKey(), e.getValue()});
        if (heap.size() > k) heap.poll(); // evict least frequent
    }

    // Step 3: extract
    int[] res = new int[k];
    for (int i = k - 1; i >= 0; i--) res[i] = heap.poll()[0];
    return res;
}

Type 03 — Top K Frequent Words (LC #692)

Same flow, but the comparator must handle ties: same frequency → alphabetically earlier word wins.

public List<String> topKFrequent(String[] words, int k) {

    Map<String, Integer> freq = new HashMap<>();
    for (String w : words)
        freq.put(w, freq.getOrDefault(w, 0) + 1);

    // Min-heap: lower freq → top. Same freq → later alphabetically → top (evicted first)
    PriorityQueue<String> heap = new PriorityQueue<>(
        (a, b) -> freq.get(a).equals(freq.get(b))
            ? b.compareTo(a)           // tie: reverse alpha at top
            : freq.get(a) - freq.get(b) // lower freq at top
    );

    for (String w : freq.keySet()) {
        heap.offer(w);
        if (heap.size() > k) heap.poll();
    }

    List<String> res = new LinkedList<>();
    while (!heap.isEmpty())
        ((LinkedList<String>) res).addFirst(heap.poll()); // reverse for final order
    return res;
}

Type 04 — K Closest Points to Origin (LC #973)

Use distance squared (x*x + y*y) — no sqrt needed for comparison. Max-heap keeps the K closest; farthest gets evicted.

public int[][] kClosest(int[][] points, int k) {

    // Max-heap by distance squared — farthest point at top
    PriorityQueue<int[]> maxHeap = new PriorityQueue<>(
        (a, b) -> (b[0]*b[0] + b[1]*b[1]) - (a[0]*a[0] + a[1]*a[1])
    );

    for (int[] p : points) {
        maxHeap.offer(p);
        if (maxHeap.size() > k) maxHeap.poll(); // evict farthest
    }

    return maxHeap.toArray(new int[k][]);
}

Type 05 — Sort Characters by Frequency (LC #451)

Max-heap by count. Pop each character and repeat it count times to build the output string.

public String frequencySort(String s) {

    Map<Character, Integer> freq = new HashMap<>();
    for (char c : s.toCharArray())
        freq.put(c, freq.getOrDefault(c, 0) + 1);

    PriorityQueue<Character> maxHeap =
        new PriorityQueue<>((a, b) -> freq.get(b) - freq.get(a));
    maxHeap.addAll(freq.keySet());

    StringBuilder sb = new StringBuilder();
    while (!maxHeap.isEmpty()) {
        char c = maxHeap.poll();
        for (int i = 0; i < freq.get(c); i++) sb.append(c);
    }
    return sb.toString();
}

Type 06 — Task Scheduler (LC #621)

Always run the most frequent available task. If it's on cooldown, idle. Track cooldown with a queue that re-admits tasks after n time slots.

public int leastInterval(char[] tasks, int n) {

    int[] freq = new int[26];
    for (char t : tasks) freq[t - 'A']++;

    PriorityQueue<Integer> maxHeap =
        new PriorityQueue<>(Collections.reverseOrder());
    for (int f : freq) if (f > 0) maxHeap.offer(f);

    int time = 0;
    Queue<int[]> cooldown = new LinkedList<>(); // [remaining, ready_at]

    while (!maxHeap.isEmpty() || !cooldown.isEmpty()) {
        time++;

        if (!maxHeap.isEmpty()) {
            int rem = maxHeap.poll() - 1;
            if (rem > 0) cooldown.offer(new int[]{rem, time + n});
        }
        // else: idle this slot

        if (!cooldown.isEmpty() && cooldown.peek()[1] == time)
            maxHeap.offer(cooldown.poll()[0]);
    }
    return time;
}

Type 07 — QuickSelect: O(n) Average for Kth Element

Idea: Partition array around a pivot. After partitioning, pivot lands at its correct sorted position. If that's exactly the target index — done! Otherwise recurse only on one half. Average O(n), no heap needed. 
public int findKthLargest(int[] nums, int k) {
    // Kth largest = (n-k)th index from left in sorted order
    return quickSelect(nums, 0, nums.length - 1, nums.length - k);
}

private int quickSelect(int[] a, int lo, int hi, int target) {
    if (lo == hi) return a[lo];

    int pivot = a[hi], p = lo;

    for (int i = lo; i < hi; i++) {
        if (a[i] <= pivot) {
            int tmp = a[i]; a[i] = a[p]; a[p] = tmp;
            p++;
        }
    }
    int tmp = a[p]; a[p] = a[hi]; a[hi] = tmp; // pivot to final position

    if      (p == target) return a[p];
    else if (p < target)  return quickSelect(a, p + 1, hi, target);
    else                  return quickSelect(a, lo, p - 1, target);
}

• K-Way Merge = combine K already-sorted sequences → heap seeds one element from each list

Section 06 — The O(n) Trick

Bucket Sort for Top K Frequent

When the answer is "top K frequent", you can beat the heap entirely. A frequency can be at most n, so bucket each element by its count into an array of size n + 1, then walk it from the high end. No log factor — pure O(n).

public int[] topKFrequentBucket(int[] nums, int k) {

    Map<Integer, Integer> freq = new HashMap<>();
    for (int n : nums)
        freq.merge(n, 1, Integer::sum);

    // bucket[f] = list of elements that appear exactly f times
    List<Integer>[] bucket = new List[nums.length + 1];
    for (int key : freq.keySet()) {
        int f = freq.get(key);
        if (bucket[f] == null) bucket[f] = new ArrayList<>();
        bucket[f].add(key);
    }

    // Walk from highest frequency downward until we collect k
    int[] res = new int[k];
    int idx = 0;
    for (int f = nums.length; f >= 1 && idx < k; f--) {
        if (bucket[f] == null) continue;
        for (int val : bucket[f]) {
            if (idx == k) break;
            res[idx++] = val;
        }
    }
    return res;
}
Heap vs Bucket: the heap is O(n log k) and works for any "top K" question. Bucket sort is O(n) but only applies when the sort key is a bounded integer count (frequencies). If frequencies can be huge or sparse, the heap is the safer default.
Section 07 — Edge Cases

Pitfalls & Boundary Decisions

!
Heap type is inverted
K largest → min-heap; K smallest → max-heap. Picking the wrong one evicts exactly the elements you wanted to keep.
!
k > n
If k exceeds the element count, just return everything. Guard before assuming the heap fills to size k.
!
Distance overflow
For K-closest, x*x + y*y can overflow int with large coordinates. Use long for the squared distance.
!
Tie-breaking rules
"Top K frequent words" needs alphabetical tie-breaks. The comparator must handle equal frequencies explicitly, or order is undefined.
!
QuickSelect worst case
A bad pivot gives O(n²). Randomise the pivot (or shuffle first) to make the worst case astronomically unlikely.
!
QuickSelect mutates input
Partitioning reorders the array in place. If the caller still needs the original order, copy first.
