0. What is Spring Boot? (the big idea)

Spring is a big Java framework: it creates your objects, wires them together (dependency injection), and gives you tools for web, data, security, and more. Spring Boot sits on top and removes the setup pain: it guesses sensible defaults, pulls in matching libraries, and packs everything into one runnable jar with a web server inside.

Pain in plain SpringWhat Boot does
Hundreds of lines of XML or @Configuration to set up a web app.Auto-configuration: if a library is on the classpath, Boot configures it for you (a DataSource if a JDBC driver exists, Jackson if it is a web app…).
Picking 30 compatible library versions.Starters: one dependency like spring-boot-starter-web brings a tested set.
Deploy a WAR into a separate Tomcat.Embedded server: Tomcat (or Jetty / Undertow / Netty) runs inside your jar. java -jar app.jar.
Where are settings? How do I see health?application.yml with profiles; Actuator for health, metrics, env.
WordPlain meaning
BeanAn object that Spring creates and manages for you.
ApplicationContext (the container)The box that holds all beans and hands them out.
Dependency Injection (DI)You do not new your collaborators; Spring passes them in (usually via the constructor).
Inversion of Control (IoC)The framework calls your code and builds your objects, not the other way round. DI is how IoC is done.
Auto-configurationBoot's "if X is present and you did not define Y, create Y" rules.
StarterA dependency bundle: spring-boot-starter-<thing>.
ProfileA named set of config: dev, test, prod.
 
@SpringBootApplication          // = @Configuration + @EnableAutoConfiguration + @ComponentScan
public class ShopApplication {
    public static void main(String[] args) {
        SpringApplication.run(ShopApplication.class, args);   // builds the context, starts Tomcat on 8080
    }
}
Mental model: you write small classes and mark them. At start-up Spring scans your package, builds one object for each marked class, works out who needs whom, and connects them. Then the web server starts and sends requests to your controllers.
Versions (2026): Spring Boot 3.x needs Java 17+ and uses Jakarta EE packages (jakarta.persistence, not javax.persistence). Boot 4 / Spring Framework 7 continue that line. If you see javax.* in a tutorial, it is Boot 2 era.
Q. What does @SpringBootApplication scan, and what does it miss?
Reveal hint
It scans the package of the class it sits on and all sub-packages. A @Service in a sibling or parent package is never found. Keep the main class at the top of your package tree (e.g. com.shop), or add scanBasePackages.

Q. Both application.properties and application.yml exist. Which wins?
Reveal hint
Both are loaded; .properties values override .yml for the same key. Confusing — keep only one format. YAML is the common choice.

How the container starts (what happens in SpringApplication.run)

#Step
1Read application.yml, env vars, args → the Environment. Decide active profiles.
2Scan packages for @Component classes; read @Bean methods; load auto-configuration classes from META-INF/spring/…AutoConfiguration.imports. Result: bean definitions (recipes, no objects yet).
3Evaluate conditions (@ConditionalOn…). Drop definitions whose conditions fail.
4Create singletons: build the dependency graph, instantiate in order, inject, run @PostConstruct, wrap with proxies where needed (@Transactional, @Cacheable, @Async).
5Start the embedded server; publish ApplicationReadyEvent; run CommandLineRunner / ApplicationRunner beans.
TopicWrongRight
Injection style@Autowired private OrderRepository orders; (field injection): hidden dependencies, hard to test, can be null in a unit test.Constructor injection with final fields. Lombok @RequiredArgsConstructor if you like.
Circular beansA needs B, B needs A → start-up fails ("The dependencies of some of the beans form a cycle").A design smell. Extract the shared part into C, or use events. @Lazy on one side is the band-aid.
Doing newnew OrderService(new OrderRepository()) inside a controller.Let Spring create and inject. new is fine for plain value objects (DTOs, records).
State in singletonsA @Service with a mutable field like currentUser.Singletons are shared by all threads. Keep them stateless; pass data as parameters.
Self-invocationCalling this.save() (a @Transactional method) from another method in the same class — the annotation is ignored.Proxies only see calls from outside. Move the method to another bean, or inject self via ObjectProvider.
Why proxies matter: @Transactional, @Cacheable, @Async, @PreAuthorize, @Retryable all work by wrapping your bean in a generated subclass that runs extra code before and after the real method. That is why the method must be public (or at least non-private, non-final) and must be called through the injected reference.
Q. Two beans implement PaymentProvider. You inject PaymentProvider p. What happens?
Reveal hint
Start-up fails: "expected single matching bean but found 2". Fix with @Primary on one, @Qualifier("stripe") at the injection point, or inject a List<PaymentProvider>. If the parameter name matches a bean name, Spring also uses that as a tie-breaker.

4. REST APIs — controllers, validation, errors

@RestController
@RequestMapping("/api/orders")
public class OrderController {
    private final OrderService service;
    public OrderController(OrderService service) { this.service = service; }

    @GetMapping("/{id}")
    public OrderDto get(@PathVariable long id) {
        return service.find(id);                     // 200 + JSON; throws NotFound → 404 (see handler)
    }

    @GetMapping
    public Page<OrderDto> list(@RequestParam(defaultValue = "NEW") String status,
                               @PageableDefault(size = 20) Pageable page) {
        return service.list(status, page);           // ?status=PAID&page=1&size=50&sort=createdAt,desc
    }

    @PostMapping
    @ResponseStatus(HttpStatus.CREATED)
    public OrderDto create(@Valid @RequestBody CreateOrderRequest req) {
        return service.create(req);                  // 201
    }

    @PutMapping("/{id}/cancel")
    public ResponseEntity<Void> cancel(@PathVariable long id) {
        service.cancel(id);
        return ResponseEntity.noContent().build();   // 204, full control of status/headers
    }
}

public record CreateOrderRequest(
        @NotNull Long customerId,
        @NotEmpty List<@Valid LineItem> items,     // @Valid cascades into the list
        @Size(max = 200) String note) {}

One place for errors

@RestControllerAdvice
class ApiExceptionHandler {

    @ExceptionHandler(OrderNotFoundException.class)
    ProblemDetail notFound(OrderNotFoundException e) {
        var pd = ProblemDetail.forStatusAndDetail(HttpStatus.NOT_FOUND, e.getMessage());
        pd.setProperty("orderId", e.getId());
        return pd;                                   // RFC 9457 JSON: {type,title,status,detail,instance,orderId}
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    ProblemDetail invalid(MethodArgumentNotValidException e) {
        var pd = ProblemDetail.forStatus(HttpStatus.BAD_REQUEST);
        pd.setProperty("errors", e.getFieldErrors().stream()
            .map(f -> f.getField() + ": " + f.getDefaultMessage()).toList());
        return pd;
    }
}
// or simply: spring.mvc.problemdetails.enabled=true for the built-in ones

Q. @Valid on the @RequestBody but the nested items are never checked. Why?
Reveal hint
Validation does not cascade by default. Put @Valid on the nested field or on the generic type: List<@Valid LineItem>. Also make sure spring-boot-starter-validation is on the classpath — without it all constraints are silently ignored.

5. Data access — Spring Data JPA and transactions

@Entity
@Table(name = "orders")
public class Order {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, length = 20)
    @Enumerated(EnumType.STRING)                       // never ORDINAL — reordering the enum corrupts data
    private OrderStatus status;

    @ManyToOne(fetch = FetchType.LAZY)                 // LAZY by hand: @ManyToOne is EAGER by default
    @JoinColumn(name = "customer_id")
    private Customer customer;

    @OneToMany(mappedBy = "order", cascade = CascadeType.ALL, orphanRemoval = true)
    private List<OrderLine> lines = new ArrayList<>();

    @Version private Long version;                      // optimistic locking
    @CreationTimestamp private Instant createdAt;
    protected Order() {}                               // JPA needs a no-arg constructor
}

public interface OrderRepository extends JpaRepository<Order, Long> {
    List<Order> findByStatusAndCustomerId(OrderStatus status, Long customerId);   // derived query
    Page<Order> findByStatus(OrderStatus status, Pageable p);

    @Query("select o from Order o join fetch o.lines where o.id = :id")    // JPQL, avoids N+1
    Optional<Order> findWithLines(Long id);

    @Query(value = "select * from orders where created_at > now() - interval '1 day'", nativeQuery = true)
    List<Order> recent();

    @Modifying @Query("update Order o set o.status = 'EXPIRED' where o.status = 'NEW' and o.createdAt < :t")
    int expireOlderThan(Instant t);                      // bulk update, no entity loading

    List<OrderSummary> findSummaryByStatus(OrderStatus s);   // interface/record projection → only needed columns
}

@Transactional — the rules that bite

@Service
@Transactional(readOnly = true)                         // class default: read-only (lets Hibernate skip dirty checks)
public class OrderService {

    @Transactional                                      // write method overrides to read-write
    public OrderDto create(CreateOrderRequest req) {
        Order o = new Order(...);
        orders.save(o);                                 // INSERT runs at commit (flush), not here
        stock.reserve(req.items());                     // same transaction: if this throws, the INSERT rolls back
        return OrderDto.from(o);
    }
}
SettingMeaning
propagation = REQUIRED (default)Join the caller's transaction if one exists, else start one.
REQUIRES_NEWAlways a new transaction; the outer one is suspended. For audit logs that must survive a rollback.
MANDATORY / NEVER / SUPPORTS / NOT_SUPPORTEDMust have one / must not / join if present / run without.
isolationDB isolation level (DEFAULT = the DB's; usually READ_COMMITTED).
readOnly = trueHint: no flush, may route to a replica, Hibernate skips snapshots.
rollbackFor = Exception.classBy default only unchecked exceptions roll back. Checked ones commit!
timeoutSeconds before the transaction is aborted.
TopicWrongRight
N+1 queriesLoad 100 orders, then order.getCustomer().getName() in a loop → 101 queries.join fetch, @EntityGraph(attributePaths = "customer"), or a DTO projection. Turn on spring.jpa.show-sql or hibernate.generate_statistics in dev to see it.
Open Session in ViewLeaving spring.jpa.open-in-view=true (the default!) so lazy loads "work" in controllers — at the cost of a DB connection held for the whole request.Set it false. Load what you need inside the service transaction; return DTOs.
LazyInitializationExceptionTouching a lazy field outside a transaction.Fetch it in the query, or map to a DTO inside the @Transactional method.
Checked exception rollbackthrows IOException from a transactional method and expecting rollback.@Transactional(rollbackFor = Exception.class), or wrap in a RuntimeException.
Catching insideCatch an exception inside the transactional method after a failed SQL, then continue — commit fails with "Transaction silently rolled back because it has been marked as rollback-only".Let it propagate, or use REQUIRES_NEW for the risky part.
equals/hashCodeLombok @Data on entities: hashCode uses the id, which is null before save → broken Sets; toString recurses through relations.No @Data on entities. Equality by id with a null-safe rule, or a natural business key.
save() everywhereCalling repo.save(entity) after every setter.A managed entity is dirty-checked: changes inside the transaction are flushed at commit automatically. save is for new objects.
Bulk inserts10,000 save() calls, one INSERT each.spring.jpa.properties.hibernate.jdbc.batch_size=50 + order_inserts=true; use SEQUENCE ids (IDENTITY disables batching). Or plain JDBC for ETL.
Alternatives to JPA: Spring Data JDBC (aggregates, no lazy loading, no dirty checking — simpler), JdbcClient / JdbcTemplate (you write SQL), jOOQ (type-safe SQL). JPA shines for rich domain models; for reporting and batch, plain SQL usually wins.
Q. A @Transactional method is private. Does the transaction start?
Reveal hint
No. The proxy can only intercept calls that come from outside the bean to a non-private method. Private methods (and self-calls through this) bypass the proxy entirely. Make it public and call it from another bean.

6. Security — filter chain, JWT, method rules

Spring Security is a chain of servlet filters that runs before your controller. Each filter does one job: read a token, check a session, enforce CSRF, decide authorization. Adding the starter locks every URL and generates a random password until you configure it.

@Configuration
@EnableMethodSecurity                                   // turns on @PreAuthorize
class SecurityConfig {

    @Bean
    SecurityFilterChain api(HttpSecurity http) throws Exception {
        return http
            .csrf(csrf -> csrf.disable())                   // stateless token API: no cookies → no CSRF risk
            .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/actuator/health", "/api/public/**").permitAll()
                .requestMatchers(HttpMethod.DELETE, "/api/**").hasRole("ADMIN")
                .anyRequest().authenticated())
            .oauth2ResourceServer(o -> o.jwt(Customizer.withDefaults()))   // validate Bearer JWTs
            .build();
    }

    @Bean
    PasswordEncoder encoder() { return PasswordEncoderFactories.createDelegatingPasswordEncoder(); } // bcrypt by default
}

Q. The JWT has "roles": ["admin"] but hasRole("ADMIN") fails. Why?
Reveal hint
Spring reads the scope claim and prefixes with SCOPE_; it does not know your roles claim. Add a JwtAuthenticationConverter with a JwtGrantedAuthoritiesConverter that reads roles and prefixes ROLE_ (upper-cased).

@Service
class CheckoutService {

    private final Timer paymentTimer;
    CheckoutService(MeterRegistry reg) {
        checkouts    = reg.counter("shop.checkouts", "channel", "web");
        paymentTimer = reg.timer("shop.payment.latency");
    }
    @Observed(name = "checkout")                     // one annotation → timer + span
    void checkout(Cart c) {
        checkouts.increment();
        paymentTimer.record(() -> payments.charge(c));
    }
}

Transactional outbox: to publish a Kafka/Rabbit message reliably when a DB row is saved, write the event into an outbox table in the same transaction, and let a poller (or Debezium) publish it. Spring Modulith's event publication registry does this for internal events.
Q. @EventListener on OrderPlaced sends an email, but the order insert later rolls back. Was the email sent?
Reveal hint
Yes — plain @EventListener runs immediately, inside the publishing transaction, before commit. Use @TransactionalEventListener(phase = AFTER_COMMIT) so side effects happen only when the data is really saved.

Q. Kubernetes sends SIGTERM but the readiness probe still says ready for a few seconds. What happens to requests?
Reveal hint
Some still arrive while the app is shutting down. Boot flips /health/readiness to OUT_OF_SERVICE on shutdown, but kube-proxy needs a moment to notice. Add a preStop sleep of 5–10 s in the Pod spec so traffic drains before the JVM gets SIGTERM.
