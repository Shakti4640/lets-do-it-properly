0. What Angular is (and the mental model for a Java developer)

Angular is a complete framework for building browser apps in TypeScript: components (UI pieces), a router, an HTTP client, forms, dependency injection, a test setup and a CLI, all designed together. If Spring Boot is your backend, Angular is its closest front-end cousin: opinionated, typed, DI-based, and batteries included.

Mental model: an Angular app is a tree of components, like a Swing/JavaFX component tree but declared in HTML. Each component owns a small piece of state; the template is a function of that state; when a signal changes, only the parts of the page that read it are updated. Services are the shared beans the components talk to, and the router swaps which subtree is on screen.
Q. Is Angular a library like React, or something else?
Reveal hint
A framework. React gives you components and leaves routing, HTTP, forms, DI and testing to third-party choices. Angular ships one answer to each, which is why Angular code bases from different companies look alike — the same reason Spring Boot projects do.

Q. Where is the equivalent of Spring's component scan — how does Angular find a component?
Reveal hint
There is none. Angular is compiled: a component is reachable only if something imports it (a route's loadComponent, another component's imports: [...]). Unreferenced code is tree-shaken out of the bundle. Forgetting to add a child component to imports gives the classic "'app-x' is not a known element" error.

2. Components and templates (bindings, control flow, inputs/outputs, lifecycle)

A component = a TypeScript class (state + behaviour) + an HTML template (view) + optional styles, glued by @Component. Think of it as a small, self-contained view-model with its own render tree. Data flows down through inputs and up through outputs (events).

// orders/order-card/order-card.component.ts
@Component({
  selector: 'app-order-card',
  imports: [CurrencyPipe, DatePipe],
  changeDetection: ChangeDetectionStrategy.OnPush,          // always, for every component (Section 3)
  template: `
    <article [class.urgent]="order().priority === 'HIGH'">        <!-- property binding: [prop]="expr" -->
      <h3>#{{ order().id }} · {{ order().total | currency:'INR' }}</h3>   <!-- interpolation + pipe -->
      <p>{{ order().createdAt | date:'dd MMM yyyy, HH:mm' }}</p>

      @if (order().status === 'SHIPPED') {                          <!-- built-in control flow (v17+) -->
        <span class="tag">Shipped</span>
      } @else if (order().status === 'CANCELLED') {
        <span class="tag muted">Cancelled</span>
      } @else {
        <button (click)="ship.emit(order().id)" [disabled]="busy()">Ship</button>  <!-- event binding: (event)="handler" -->
      }

      @for (line of order().lines; track line.sku) {                <!-- track is REQUIRED: stable key, like React key -->
        <li>{{ $index + 1 }}. {{ line.sku }} × {{ line.qty }}</li>
      } @empty {
        <li>No lines</li>
      }

      @switch (order().channel) {
        @case ('WEB')    { <i class="ic-web"></i> }
        @case ('MOBILE') { <i class="ic-phone"></i> }
        @default         { <i class="ic-store"></i> }
      }
      <ng-content />                                                <!-- slot: parent projects extra markup here -->
    </article>
  `,
})
export class OrderCardComponent {
  // signal inputs (v17.1+): read as order(); required = compile error if parent forgets it
  order = input.required<Order>();
  busy  = input(false);
  // transform: accept "true"/"" from the template, store a boolean
  compact = input(false, { transform: booleanAttribute });
  // output: parent listens with (ship)="onShip($event)"
  ship = output<number>();
  // model(): two-way binding with [(selected)]="sel" in the parent
  selected = model(false);
  // derived state: recomputed only when order() changes
  lineCount = computed(() => this.order().lines.length);
}

Q. A child component shows stale data after the parent updates an array with this.orders.push(o). Nothing re-renders. Why, and what is the fix?
Reveal hint
With OnPush (and in zoneless apps), Angular re-checks a component when an input reference changes or a signal it read changes. push mutates the same array, so the reference is identical and nothing fires. Fix: keep the list in a signal and update immutably — this.orders.update(list => [...list, o]). The same rule as equals() on an unchanged object: same identity, no change detected.

3. Signals and change detection (signal / computed / effect, OnPush, zoneless)

A signal is a box holding a value that records who reads it. When the value changes, only the readers (templates, computeds, effects) are told. This replaces the old model where zone.js guessed "something may have changed" after every click, timer, or HTTP response and re-checked the whole component tree.

import { signal, computed, effect, untracked, linkedSignal } from '@angular/core';

// writable signal
const cart = signal<Line[]>([]);
cart.set([{ sku: 'A1', qty: 2, price: 99 }]);          // replace
cart.update(l => [...l, { sku: 'B2', qty: 1, price: 49 }]); // derive from old — always a NEW array/object

// computed: lazy, memoised, read-only; re-evaluates only if a dependency changed
const total = computed(() => cart().reduce((s, l) => s + l.qty * l.price, 0));
const isEmpty = computed(() => cart().length === 0);

// effect: side effects (logging, localStorage, sync to a non-Angular lib). NOT for setting other signals.
effect(() => {
  localStorage.setItem('cart', JSON.stringify(cart()));
  const user = untracked(() => auth.user());             // read without subscribing
});

// linkedSignal (v19+): writable state that resets when a source changes (e.g. selected item resets when list reloads)
const selected = linkedSignal(() => cart()[0]?.sku ?? null);

// custom equality: avoid notifying when the new value is "the same"
const filter = signal({ q: '', page: 1 }, { equal: (a, b) => a.q === b.q && a.page === b.page });

// RxJS bridge (Section 6): Observable → signal, signal → Observable
const orders = toSignal(http.get<Order[]>('/api/orders'), { initialValue: [] });
const filter$ = toObservable(filter);

Mental model for a Java dev. signal ≈ an observable property with identity-based change detection; computed ≈ a memoised getter whose cache invalidates automatically; effect ≈ a listener that re-runs when any property it touched changes. The scheduler batches: ten set() calls in one tick cause one render.
Q. Your computed() never updates even though the signal it reads clearly changes. The computed reads the signal inside an if that was false on first run. What happened?
Reveal hint
Nothing wrong — dependencies are tracked dynamically per run. If the first run never executed the branch that reads x(), x is not a dependency yet. Once another tracked signal flips the if to true and the computed re-runs, it will pick up x. If you need it tracked always, read it before the branch. (Also check you did not wrap the read in untracked().)

4. Services and dependency injection (inject(), providedIn, tokens, scopes)

Angular has a real DI container, hierarchical like Spring's parent/child contexts. A service is just a class with @Injectable. providedIn: 'root' = one singleton for the app (like a Spring @Service). Providing in a component's providers array or a route = a new instance per component / per route subtree (like a request/prototype scope).

// orders/order.service.ts — the "@Service" layer
@Injectable({ providedIn: 'root' })                       // singleton, tree-shakable (dropped if nobody injects it)
export class OrderService {
  private readonly http = inject(HttpClient);          // inject() instead of constructor params (v14+)
  private readonly api  = inject(API_BASE_URL);        // injection token for a plain value

  // state owned by the service, exposed read-only
  private readonly _orders = signal<Order[]>([]);
  readonly orders = this._orders.asReadonly();
  readonly openCount = computed(() => this._orders().filter(o => o.status === 'OPEN').length);

  load(): Observable<Order[]> {
    return this.http.get<Order[]>(`${this.api}/orders`).pipe(tap(o => this._orders.set(o)));
  }
}

// core/tokens.ts — InjectionToken: typed key for non-class values (like @Value / @Qualifier)
export const API_BASE_URL = new InjectionToken<string>('API_BASE_URL', {
  providedIn: 'root',
  factory: () => environment.apiBaseUrl,                 // default value; override in app.config or tests
});

// app.config.ts — the provider recipes (like @Bean methods)
providers: [
  { provide: API_BASE_URL, useValue: '/api' },                          // useValue
  { provide: Logger, useClass: environment.production ? RemoteLogger : ConsoleLogger }, // useClass (interface → impl)
  { provide: Clock, useFactory: () => new SystemClock(inject(LOCALE_ID)) },   // useFactory with deps
  { provide: LegacyOrderApi, useExisting: OrderService },                // alias
  { provide: ErrorHandler, useClass: GlobalErrorHandler },             // replace a framework service
  provideAppInitializer(() => inject(ConfigService).load()),           // run before first render (v19; was APP_INITIALIZER)
]

5. Routing (lazy loading, functional guards and resolvers, route params as inputs)

The router maps the URL to a component tree. It is a client-side DispatcherServlet: the browser never reloads; the router swaps what sits inside <router-outlet>. Lazy routes download their feature's code only when first visited.

// app.routes.ts
export const routes: Routes = [
  { path: '', redirectTo: 'orders', pathMatch: 'full' },
  { path: 'login', loadComponent: () => import('./auth/login.component').then(m => m.LoginComponent) },
  {
    path: 'orders',
    canMatch: [authGuard],                                   // guard the whole feature; falls through to the next route if false
    loadChildren: () => import('./orders/orders.routes'),  // lazy: separate JS chunk, loaded on first visit
    providers: [OrdersStore],                                // route-scoped service (Section 4)
  },
  { path: '**', component: NotFoundComponent },             // wildcard LAST
];

// orders/orders.routes.ts — the feature's own table (default export so loadChildren needs no .then)
export default [
  { path: '', component: OrderListComponent, title: 'Orders' },
  {
    path: ':id',
    component: OrderDetailComponent,
    title: (r) => `Order #${r.params['id']}`,
    resolve: { order: orderResolver },                       // data ready before the component shows
    canDeactivate: [unsavedChangesGuard],
  },
] satisfies Routes;

// core/auth.guard.ts — functional guard (class guards are deprecated)
export const authGuard: CanMatchFn = () => {
  const auth = inject(AuthService), router = inject(Router);
  return auth.isLoggedIn() ? true : router.createUrlTree(['/login'], { queryParams: { next: location.pathname } });
};

// orders/order.resolver.ts
export const orderResolver: ResolveFn<Order> = (route) =>
  inject(OrderService).get(Number(route.paramMap.get('id')));

// OrderDetailComponent — withComponentInputBinding() turns params/query/data/resolve into inputs
export class OrderDetailComponent {
  id    = input.required<string>();          // from :id  (always a string in the URL!)
  order = input.required<Order>();           // from resolve key "order"
  tab   = input<string>('summary');          // from ?tab=
  private readonly router = inject(Router);
  goBack() { this.router.navigate(['/orders'], { queryParams: { page: 2 }, queryParamsHandling: 'merge' }); }

Q. After a production deploy, users who kept the old tab open get ChunkLoadError when they click a lazy route. Why, and how do you handle it?
Reveal hint
The old index.html references chunk orders-ABC123.js; the new deploy replaced it with orders-DEF456.js, so the request 404s. Handle it: listen for NavigationError (or a global error handler matching ChunkLoadError) and location.reload() once; and on the server keep the previous build's hashed files around for a short overlap, or serve old assets from a versioned path. Hashed names are correct — this is normal cache-busting behaviour.

6. HttpClient and RxJS — talking to a Spring Boot API (interceptors, JWT, CORS, proxy)

HttpClient returns Observables (RxJS): a lazy stream that does nothing until subscribed and can emit many times. For a single HTTP call it emits once and completes. You rarely subscribe by hand — hand the stream to the async pipe, toSignal, or httpResource, and let Angular manage the subscription.

// orders/order.service.ts
@Injectable({ providedIn: 'root' })
export class OrderService {
  private readonly http = inject(HttpClient);
  private readonly base = '/api/orders';                   // relative: same origin in prod, proxied in dev

  list(page = 0, size = 20) {
    return this.http.get<Page<Order>>(this.base, { params: { page, size, sort: 'createdAt,desc' } }); // Spring Pageable
  }
  create(cmd: CreateOrder) { return this.http.post<Order>(this.base, cmd); }        // JSON body + header set for you
  ship(id: number)       { return this.http.patch<Order>(`${this.base}/${id}/ship`, {}); }
  download(id: number)   { return this.http.get(`${this.base}/${id}/invoice`, { responseType: 'blob' }); }
  upload(file: File) {
    const fd = new FormData(); fd.append('file', file);     // → @RequestParam MultipartFile file
    return this.http.post('/api/files', fd, { reportProgress: true, observe: 'events' });
  }
}

// core/auth.interceptor.ts — functional interceptor (like a servlet Filter, but outgoing)
export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const token = inject(AuthService).token();
  const authed = token && req.url.startsWith('/api')
    ? req.clone({ setHeaders: { Authorization: `Bearer ${token}` } })   // requests are immutable → clone
    : req;
  return next(authed);
};

// core/error.interceptor.ts — map Spring's ProblemDetail / 401 / 5xx in one place
export const errorInterceptor: HttpInterceptorFn = (req, next) => {
  const router = inject(Router), toast = inject(ToastService);
  return next(req).pipe(
    retry({ count: 2, delay: 300, resetOnSuccess: true }),               // only safe for GET — check req.method!
    catchError((e: HttpErrorResponse) => {
      if (e.status === 401) router.navigateByUrl('/login');
      else if (e.status === 0) toast.error('Network / CORS error');      // status 0 = browser blocked it
      else toast.error(e.error?.detail ?? `HTTP ${e.status}`);          // ProblemDetail.detail from Spring 6
      return throwError(() => e);
    }),
  );
};

Q. A GET with Authorization: Bearer … works in Postman but the browser shows "blocked by CORS policy: Response to preflight request doesn't pass access control check". Postman ignores CORS — so what exactly is failing, and where is the fix?
Reveal hint
The custom Authorization header makes the request "non-simple", so the browser first sends OPTIONS /api/orders with Access-Control-Request-Headers: authorization. Spring Security answers 401/403 to that OPTIONS (no token on a preflight), so the browser never sends the real GET. Fix on the server: enable http.cors(...) with a CorsConfigurationSource that lists the Angular origin and the Authorization header; Spring's CorsFilter then runs before authentication and answers the preflight with 200. Nothing in Angular can fix CORS — it is a browser-enforced server policy.

7. Forms (typed reactive forms, validation, server errors)

Two systems: template-driven ([(ngModel)], logic in HTML — fine for a login box) and reactive (the form model lives in the class as FormGroup/FormControl — testable, typed, composable). Use reactive for anything with more than two fields. Since v14 reactive forms are strictly typed: form.value.email is string | undefined, not any.

// customers/customer-form.component.ts
@Component({ selector: 'app-customer-form', imports: [ReactiveFormsModule], templateUrl: './customer-form.component.html' })
export class CustomerFormComponent {
  private readonly fb  = inject(NonNullableFormBuilder);     // reset() goes back to initial values, not null
  private readonly svc = inject(CustomerService);
  saving = signal(false);

  form = this.fb.group({
    name:  ['', [Validators.required, Validators.maxLength(80)]],
    email: ['', { validators: [Validators.required, Validators.email], asyncValidators: [uniqueEmail()], updateOn: 'blur' }],
    gstin: ['', Validators.pattern(/^[0-9]{2}[A-Z0-9]{13}$/)],
    address: this.fb.group({ line1: ['', Validators.required], pin: ['', Validators.pattern(/^\d{6}$/)] }),
    phones: this.fb.array([this.fb.control('')]),            // dynamic list of controls
  }, { validators: [atLeastOneContact] });                      // cross-field validator on the group

  get phones() { return this.form.controls.phones; }
  addPhone()  { this.phones.push(this.fb.control('')); }

  submit() {
    if (this.form.invalid) { this.form.markAllAsTouched(); return; }   // show all errors
    this.saving.set(true);
    this.svc.create(this.form.getRawValue())                   // getRawValue(): includes disabled controls, fully typed
      .pipe(finalize(() => this.saving.set(false)))
      .subscribe({
        next: () => this.form.reset(),
        error: (e: HttpErrorResponse) => this.applyServerErrors(e),
      });
  }

  // Map Spring's MethodArgumentNotValidException → { errors: [{ field: "email", message: "must be unique" }] }
  private applyServerErrors(e: HttpErrorResponse) {
    if (e.status !== 400) return;
    for (const err of e.error?.errors ?? []) {
      this.form.get(err.field)?.setErrors({ server: err.message });  // field path like "address.pin" works with get()
    }
  }
}

// Custom validators: sync (pure function) and async (returns Observable)
export const atLeastOneContact: ValidatorFn = (g) =>
  g.get('email')?.value || g.get('phones')?.value?.some((p: string) => p) ? null : { contactRequired: true };

export function uniqueEmail(): AsyncValidatorFn {
  const svc = inject(CustomerService);                        // factory called in injection context (field init)
  return (c) => svc.emailExists(c.value).pipe(map(exists => exists ? { taken: true } : null), catchError(() => of(null)));
}

8. State management and performance (signal stores, NgRx SignalStore, @defer, bundles)

Most apps do not need a global state library. Server data belongs to the server; the client keeps a small cache plus UI state. Start with a signal-based service per feature. Reach for NgRx SignalStore when many features share state and you want a fixed shape (state / computed / methods) with devtools. Classic NgRx Store (actions/reducers/effects) is for very large teams that want Redux discipline.

// orders/orders.store.ts — a plain signal store (no library)
@Injectable({ providedIn: 'root' })
export class OrdersStore {
  private readonly api = inject(OrderService);
  // private writable state
  private readonly state = signal<{ items: Order[]; status: 'idle'|'loading'|'error'; filter: string }>({ items: [], status: 'idle', filter: '' });
  // public read-only selectors
  readonly items   = computed(() => this.state().items);
  readonly loading = computed(() => this.state().status === 'loading');
  readonly visible = computed(() => { const f = this.state().filter.toLowerCase(); return this.items().filter(o => o.customer.toLowerCase().includes(f)); });
  // commands
  setFilter(filter: string) { this.state.update(s => ({ ...s, filter })); }
  load() {
    this.state.update(s => ({ ...s, status: 'loading' }));
    this.api.list().subscribe({
      next:  items => this.state.update(s => ({ ...s, items, status: 'idle' })),
      error: ()    => this.state.update(s => ({ ...s, status: 'error' })),
    });
  }
  ship(id: number) {   // optimistic update + rollback
    const before = this.state();
    this.state.update(s => ({ ...s, items: s.items.map(o => o.id === id ? { ...o, status: 'SHIPPED' } : o) }));
    this.api.ship(id).subscribe({ error: () => this.state.set(before) });
  }
}

    )),
  })),

    proxy_set_header X-Forwarded-Proto $scheme;
  }
  location ~* \.(js|css|woff2|png|svg)$ {
    add_header Cache-Control "public, max-age=31536000, immutable";   # hashed names → cache forever
    try_files $uri =404;
  }
  location / {
    add_header Cache-Control "no-store";           # index.html must always be fresh
    try_files $uri $uri/ /index.html;              # deep links /orders/42 → index.html → Angular router
  }
  gzip on; gzip_types text/css application/javascript application/json image/svg+xml;
}

Q. The app works at / but every deep link such as /orders/42 gives a blank page in production and the console shows main-XYZ.js loaded as text/html. What is wrong?
Reveal hint
Two linked mistakes. (1) The server falls back to index.html for every path, including missing JS files, so a wrong asset path returns HTML with status 200 → "Unexpected token <". (2) The assets are requested relative to /orders/ because <base href> is wrong or missing. Fix: keep <base href="/"> in index.html (or --base-href /app/ when deployed under a sub-path), and make the fallback apply only to non-file paths (try_files $uri $uri/ /index.html with a separate =404 rule for static extensions).

Migration path (1.x → modern)Notes
1. Refactor 1.x to .component() + one-way bindings + ES modules + TypeScriptRemoves $scope soup first; already a big quality win on the old stack.
2. Hybrid with @angular/upgrade (UpgradeModule, downgradeComponent)Both frameworks run on one page; migrate component by component. Costs two bundles and two change-detection systems meanwhile — keep the window short.
3. Or strangler pattern by routeNew routes in a new Angular app behind the same NGINX; old 1.x app shrinks until deleted. Simpler than hybrid when features are route-separable.
4. Never "big-bang rewrite in secret"Six months with no release is the classic failure. Ship each migrated route.

Seven rules that cover 90% of Angular code review. (1) Standalone components, OnPush, no NgModules. (2) State in signals; derive with computed; never mutate in place. (3) inject() fields, services for shared state, components for views. (4) Lazy routes per feature; route params as inputs. (5) No manual subscribe without takeUntilDestroyed; prefer toSignal/httpResource/async. (6) Typed reactive forms; validate on the server too. (7) Build once, configure at runtime, serve index.html fallback, cache hashed assets forever.
Q. Interviewer: "Explain change detection in Angular — then and now — in two minutes."
Reveal hint
Then (AngularJS): dirty checking — after any event the digest loop re-evaluates every $watch until nothing changes; slow with thousands of bindings. Angular with zone.js: zone.js monkey-patches browser async APIs so Angular knows "something happened", then walks the component tree top-down comparing bound values; OnPush skips subtrees whose inputs (by reference) and events have not changed. Now (signals, zoneless): templates read signals, so Angular knows exactly which components depend on which state; a set() marks only those for re-render and the scheduler batches the work — no zone.js, no tree walk, no guessing. Mention the migration path: adopt OnPush + signals today, then flip provideZonelessChangeDetection().
