0. How Linux is put together (the picture behind every command)

LayerWhat it isYou touch it via
KernelOwns CPU, memory, disks, network. Everything else asks it through system calls (open, read, fork, execve, socket…)./proc, /sys, sysctl, dmesg, strace
ProcessesRunning programs. Each has a PID, a parent, a user, open file descriptors, environment, and limits. PID 1 is systemd (or your app, in a container).ps, top, kill, /proc/<pid>
Files"Everything is a file": disks, devices (/dev), sockets, pipes, kernel state (/proc, /sys). A file is an inode (metadata + data blocks); names are just links to inodes.ls -li, stat, lsof
Users & permissionsEvery process runs as a UID/GID; every file has owner, group, mode bits. root (UID 0) bypasses checks. Capabilities split root's powers.id, chmod, chown, sudo
ShellA program (bash, sh, zsh) that reads your commands, expands them, and asks the kernel to run programs. Scripts are just saved commands.Your terminal
Init / servicessystemd starts and supervises services, mounts, timers; journald collects their logs.systemctl, journalctl
ContainersNormal processes isolated with namespaces (what they see) and limited with cgroups (what they may use). Same kernel as the host.docker, crictl, nsenter

Mental model: the kernel is the landlord; processes are tenants who must ask for everything (memory, files, network) through a fixed set of doors (system calls). The shell is your phone to the landlord. /proc is the landlord's live ledger — you can read a tenant's limits, open files, and environment there without disturbing them.
Q. A container shows 64 GB RAM in free -h but was started with --memory 512m. Which is right?
Reveal hint
Both, in a way. free reads /proc/meminfo, which shows the host. The container's real limit is in its cgroup: cat /sys/fs/cgroup/memory.max. Modern JVMs (and docker stats) read the cgroup; old tools and old Java 8 builds did not — and got OOM-killed.

Q. df -h says /var is 100% full, but du -sh /var says 20 GB of 100 GB. Where is the space?
Reveal hint
Deleted-but-open files. A process still holds a file descriptor to a log that was rm'd; the blocks stay allocated until it closes. lsof +L1 (or lsof | grep deleted) shows them; truncate via /proc/<pid>/fd/<n> or restart the process.

TopicWrongRight

Q. The service exited with code 137 but dmesg shows no OOM message. What else sends it?
Reveal hint
Something sent SIGKILL: systemd after TimeoutStopSec expired, Docker/Kubernetes after the termination grace period, or a human kill -9. In Kubernetes, check kubectl describe pod → Reason: OOMKilled vs Error. If the app ignores SIGTERM or takes too long to stop, you get 137 without OOM.

3. systemd and journald — running a Java service properly

# /etc/systemd/system/shop-api.service
[Unit]
Description=Shop API
After=network-online.target postgresql.service
Wants=network-online.target

[Service]
Type=simple                                   # exec = start when the binary is exec'd; notify = app tells systemd it is ready
User=shop
Group=shop
WorkingDirectory=/opt/shop/current
EnvironmentFile=/etc/shop/api.env             # KEY=value lines; chmod 640 root:shop
Environment=JAVA_TOOL_OPTIONS="-XX:MaxRAMPercentage=75 -XX:+ExitOnOutOfMemoryError"
ExecStart=/usr/bin/java -jar /opt/shop/current/shop-api.jar
ExecReload=/bin/kill -HUP $MAINPID
Restart=on-failure                            # or always
RestartSec=5
StartLimitIntervalSec=300
StartLimitBurst=5                             # give up after 5 crashes in 5 min (so you notice)
TimeoutStopSec=30                            # SIGTERM, wait 30 s, then SIGKILL — match Spring's graceful timeout
KillSignal=SIGTERM
SuccessExitStatus=143                         # JVM exits 143 on SIGTERM; treat as clean
LimitNOFILE=65536
TasksMax=4096
MemoryMax=2G                                  # cgroup limit — the JVM sees it via MaxRAMPercentage
CPUQuota=200%
# hardening
NoNewPrivileges=yes
ProtectSystem=strict
ReadWritePaths=/opt/shop/current/logs /tmp
PrivateTmp=yes
ProtectHome=yes

[Install]
WantedBy=multi-user.target

Q. systemctl status shows Main PID exited, code=exited, status=143 in red. Is that a failure?
Reveal hint
143 = 128 + 15: the JVM exited because it received SIGTERM — a normal stop. Add SuccessExitStatus=143 so systemd (and your Restart=on-failure) treat it as success instead of restarting a service you just stopped.

Q. curl localhost:8080/health on the host works; from another host curl host:8080 times out. ss -tulpn shows 0.0.0.0:8080. What is it?
Reveal hint
The app is fine and listening on all interfaces, so it is a network-level block: host firewall (nft/ufw), cloud security group, or a NACL/route. Prove it with tcpdump port 8080 on the server while curling: no SYN arriving = blocked before the box.

5. Disk, memory, CPU — reading the numbers

Disk

df -h                                   # space per filesystem (watch Use% and the mount point)
df -i                                   # inodes — "No space left" with free GB = out of inodes (millions of tiny files)
du -xh --max-depth=1 /var | sort -h | tail   # drill down one level at a time; -x stays on this filesystem
ncdu /var                               # interactive, if installed
iostat -xz 1                            # per-device: %util near 100 and high await = disk is the bottleneck
iotop -o                                # which process is doing the IO
lsof +L1                                # deleted but open files holding space

Memory

free -h
               total   used   free   shared  buff/cache  available
Mem:            15Gi  6.2Gi  1.1Gi    120Mi       8.1Gi      8.9Gi
# "free" being small is NORMAL — Linux uses spare RAM as file cache (buff/cache) and gives it back.
# Look at "available". Swap in use + rising "si/so" in vmstat = real pressure.
vmstat 1 5                               # r (runnable), b (blocked), si/so (swap in/out), wa (IO wait %), st (steal)
cat /proc/meminfo | egrep "MemAvailable|Swap|Dirty"
ps -o pid,rss,vsz,cmd -p <pid>             # RSS = real resident memory (what the OOM killer counts); VSZ = reserved address space (ignore for Java)
smem -r | head                           # proportional set size when many processes share libs
cat /sys/fs/cgroup/memory.max /sys/fs/cgroup/memory.current   # container limit vs usage (cgroup v2)
sysctl vm.swappiness vm.overcommit_memory

CPU and load

uptime
 10:31:07 up 42 days,  load average: 6.10, 4.20, 2.05

Q. A 4-core container has cpu.max = 200000 100000 (2 CPUs). The JVM reports availableProcessors() = 2, yet top inside shows 400% possible. Which does the app get?
Reveal hint
It may run on all 4 cores briefly, but the cgroup throttles it to 2 CPU-seconds per second; cpu.stat shows nr_throttled climbing. Threads pause mid-request — p99 latency spikes with "idle" CPU. Set requests, consider no CPU limit in Kubernetes, and size thread pools from availableProcessors().

Q. jcmd says "Unable to open socket file: target process not responding or HotSpot VM not loaded" — but the JVM is running. Why?
Reveal hint

8. Bash scripting that does not break production

#!/usr/bin/env bash
# deploy.sh — deploy a release of shop-api. Usage: deploy.sh <version> [--dry-run]
set -Eeuo pipefail                                 # -e exit on error, -u unset var = error, -o pipefail, -E traps in functions
IFS=$'\n\t'                                        # word-split only on newlines/tabs, not spaces

readonly SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
readonly APP_DIR="${APP_DIR:-/opt/shop}"              # default if unset
readonly LOG="/var/log/shop/deploy.log"

log()  { printf '%s [%s] %s\n' "$(date -u +%FT%TZ)" "$1" "${*:2}" | tee -a "$LOG" >&2; }
die()  { log ERROR "$@"; exit 1; }
need() { command -v "$1" >/dev/null 2>&1 || die "missing command: $1"; }

cleanup() { local rc=$?; rm -rf "${TMP:-}"; [[ $rc -ne 0 ]] && log ERROR "failed with exit $rc at line ${BASH_LINENO[0]}"; exit $rc; }
trap cleanup EXIT                                  # always runs: success, error, Ctrl-C

usage() { sed -n '2,3p' "$0"; exit 2; }

# ---- args ----
[[ $# -ge 1 ]] || usage
VERSION="$1"; shift
DRY_RUN=false
while [[ $# -gt 0 ]]; do
  case "$1" in
    --dry-run) DRY_RUN=true ;;
    -h|--help) usage ;;
    *) die "unknown option: $1" ;;
  esac; shift
done
[[ "$VERSION" =~ ^[0-9]+\.[0-9]+\.[0-9]+$ ]] || die "bad version: $VERSION"

need curl; need systemctl; need sha256sum
if [[ $EUID -ne 0 ]]; then die "run as root (sudo)"; fi

# ---- do the work ----
TMP="$(mktemp -d)"
readonly JAR_URL="https://artifacts.shop.example/shop-api/${VERSION}/shop-api.jar"
log INFO "downloading $JAR_URL"
curl -fsSL --retry 3 -o "$TMP/shop-api.jar" "$JAR_URL"
curl -fsSL -o "$TMP/shop-api.jar.sha256" "$JAR_URL.sha256"
(cd "$TMP" && sha256sum -c --quiet shop-api.jar.sha256) || die "checksum mismatch"

readonly RELEASE="$APP_DIR/releases/$VERSION"
if "$DRY_RUN"; then log INFO "dry run: would install to $RELEASE and restart"; exit 0; fi

install -d -o shop -g shop "$RELEASE"
install -o shop -g shop -m 0644 "$TMP/shop-api.jar" "$RELEASE/shop-api.jar"
ln -sfn "$RELEASE" "$APP_DIR/current"                   # atomic switch
systemctl restart shop-api

for i in {1..30}; do                                  # wait for health, max 30 s
  if curl -fsS localhost:8080/actuator/health | grep -q '"UP"'; then log INFO "deployed $VERSION"; exit 0; fi
  sleep 1
done
log ERROR "health check failed, rolling back"
PREV="$(ls -1dt "$APP_DIR"/releases/* | sed -n 2p)"
ln -sfn "$PREV" "$APP_DIR/current" && systemctl restart shop-api
die "rolled back to $(basename "$PREV")"
RuleWhy
set -Eeuo pipefail at the topWithout it, a failed cd or curl is ignored and the script happily deletes the wrong directory. pipefail makes cmd | tee fail when cmd fails.
Quote every variable: "$var", "$@"Spaces and globs in values otherwise split or expand. rm -rf "$DIR/"* vs rm -rf $DIR/* with empty DIR = rm -rf /*.
[[ ]] not [ ]; $(…) not backticks; local in functionsSafer parsing, nesting, no global leaks.
trap cleanup EXITTemp files removed and errors logged even on Ctrl-C or set -e exit.
Idempotent stepsinstall -d, ln -sfn, mkdir -p: running twice is safe.
--dry-run and --helpOperators can see what will happen before it happens.
Check tools and privileges firstFail in the first second, not after half the work.
Log to stderr with timestamps; data to stdoutScripts compose: ./list.sh | jq still works.
Verify downloads (checksum/signature)A proxy or mirror can hand you anything.
shellcheck deploy.sh in CICatches 90% of quoting and logic bugs. shfmt for formatting.

Q. ssh -L 5432:db.internal:5432 bastion then psql -h localhost. Where does the TCP connection to the DB actually originate?
Reveal hint

StepCommandsLooking for
1. Is the box alive and sane?uptime; df -h; free -h; systemctl --failed; dmesg -T | tail -30Reboot? Disk full? OOM killer? Failed units?
2. Is the service running?systemctl status shop-api; journalctl -u shop-api -n 200 --no-pager (K8s: kubectl get pods; describe; logs --previous)Exit codes (137/143), stack traces at the end of the log, restart loop.

5. Is it resources?top -H -p $(pidof java); vmstat 1 5; iostat -xz 1 3; cat /sys/fs/cgroup/cpu.statCPU-bound thread, IO wait, swap, throttling.

The 7 rules to remember: 1) read available not free, load per core, %wa and %st; 2) ss, curl -v, dig, tcpdump tell you DNS vs refused vs blocked; 3) services run as their own user under systemd with limits, graceful stop, and journald; 4) SIGTERM first, SIGKILL later; 137 = killed, 143 = clean stop; 5) three thread dumps, a heap dump, and a JFR before any restart; 6) set -Eeuo pipefail, quote everything, trap cleanup, shellcheck; 7) in containers, limits live in /sys/fs/cgroup and the JVM must respect them.
Q. Interviewer: "Production API is slow. You have SSH. First three commands?"
Reveal hint
Something like: uptime && free -h && df -h (is the box itself in trouble), top -H -p $(pidof java) or vmstat 1 (CPU vs IO vs memory), then jcmd $(pidof java) Thread.print (what the app is stuck on). The point is the order: machine → process → application, each step narrowing the cause before you touch anything.
