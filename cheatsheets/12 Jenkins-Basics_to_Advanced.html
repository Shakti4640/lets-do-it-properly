0. What is Jenkins? (the big idea)

Jenkins is an automation server. It watches your code, and when something changes it runs a set of steps for you: build, test, package, deploy. This is CI/CD: Continuous Integration (merge and test often) and Continuous Delivery (always ready to ship). Jenkins is open source, runs on Java, and gets most of its power from plugins.

WordPlain meaning
Controller (was "master")The main Jenkins server: web UI, job config, scheduling. Should not run heavy builds itself.
Agent (was "slave")A machine or container that does the actual work. The controller sends it jobs.
NodeAny machine Jenkins can run work on (controller or agent).
ExecutorOne "slot" on a node. A node with 4 executors can run 4 builds at once.
Job / ProjectA thing Jenkins can run. The modern kind is a Pipeline.
Build / RunOne execution of a job. Numbered: #1, #2…
PipelineA job defined as code, in a file called Jenkinsfile, kept in your repo.
StageA named block of the pipeline (Build, Test, Deploy). Shows as a column in the UI.
StepOne action inside a stage: sh, git, junit…
WorkspaceThe folder on the agent where the job checks out code and works.
ArtifactA file a build produces and keeps: a jar, a Docker image tag, a report.
PluginAn add-on. Git, Docker, Kubernetes, Slack, credentials — almost everything is a plugin.

A typical flow

#What happens
1You push to GitHub / GitLab / Bitbucket. A webhook tells Jenkins.
2Jenkins reads the Jenkinsfile from the repo and starts a build on a free agent.
3The agent checks out the code, runs Build → Test → Package stages.
4Test reports and artifacts are saved; a Docker image is pushed.
5On the main branch (or after a manual OK) the Deploy stage runs.
6Slack / email gets a green or red message. The run is kept in history.
Mental model: Jenkins is a very patient robot assistant. You write a checklist (the Jenkinsfile). Every time code changes, it runs the whole checklist the same way, and shouts if any item fails.
Jenkins vs GitHub Actions / GitLab CI: those are hosted and YAML-based, easy to start. Jenkins is self-hosted, uses Groovy, has thousands of plugins, and you control everything (and maintain everything). Big companies with special needs often keep Jenkins.
Q. Where should the Jenkinsfile live — in Jenkins, or in the code repo?
Reveal hint
In the repo, next to the code. Then it is versioned, reviewed in pull requests, and each branch can have its own pipeline. Pasting scripts into the Jenkins UI is the old way and gets lost or drifts.

Q. Jenkins restarted and all your jobs are gone. Most likely cause?
Reveal hint
The container ran without a volume on /var/jenkins_home, so the data lived in the container's own layer and vanished when it was re-created. Always mount a named volume (or a PVC on Kubernetes).

Q. A Multibranch Pipeline shows no jobs after a scan. Why?
Reveal hint
Branches only appear if they contain a Jenkinsfile at the configured path (default: repo root). Also check the branch discovery filters and that the credential can read the repo.

3. Declarative Pipeline — the full skeleton

There are two Jenkinsfile styles. Declarative has a fixed, easy structure and is what you should use. Scripted is free-form Groovy for odd cases. Below is a complete Declarative file; each block is explained after it.

pipeline {
    agent { label 'linux' }                      // where the whole pipeline runs (can be per stage)

    options {
        timeout(time: 30, unit: 'MINUTES')
        buildDiscarder(logRotator(numToKeepStr: '20'))
        disableConcurrentBuilds()
        timestamps()
    }

    environment {                                 // env vars for every stage
        REGISTRY = 'ghcr.io/shop'
        IMAGE    = "${REGISTRY}/api:${env.BUILD_NUMBER}"
    }

    parameters {                                  // "Build with Parameters"
        choice(name: 'ENV', choices: ['dev', 'staging', 'prod'], description: 'Target')
        booleanParam(name: 'RUN_E2E', defaultValue: false)
    }

    triggers { cron('H 2 * * 1-5') }

    stages {
        stage('Checkout') {
            steps { checkout scm }                   // the repo + branch that holds this Jenkinsfile
        }
        stage('Build') {
            steps { sh './mvnw -B -q package -DskipTests' }
        }
        stage('Test') {
            steps { sh './mvnw -B test' }
            post {
                always { junit 'target/surefire-reports/*.xml' }   // test report, even on failure
            }
        }
        stage('Image') {
            when { branch 'main' }                    // only on main
            steps {
                withCredentials([usernamePassword(credentialsId: 'ghcr', usernameVariable: 'U', passwordVariable: 'P')]) {
                    sh '''
                        echo "$P" | docker login ghcr.io -u "$U" --password-stdin
                        docker build -t "$IMAGE" .
                        docker push "$IMAGE"
                    '''
                }
            }
        }
        stage('Deploy') {
            when { allOf { branch 'main'; expression { params.ENV == 'prod' } } }
            input { message 'Deploy to prod?'; ok 'Ship it'; submitter 'release-managers' }
            steps { sh "kubectl set image deploy/api api=$IMAGE -n shop" }
        }
    }

    post {                                        // runs after all stages
        success { slackSend color: 'good',   message: "OK ${env.JOB_NAME} #${env.BUILD_NUMBER}" }
        failure { slackSend color: 'danger', message: "FAILED ${env.JOB_NAME} #${env.BUILD_NUMBER} ${env.BUILD_URL}" }
        always  { cleanWs() }
    }
}
BlockRequired?Does
pipeline { }YesThe outer wrapper. Only one.
agentYes (top or per stage)Where to run: any, none, { label 'x' }, { docker { image 'node:20' } }, { kubernetes { … } }.
stages → stage → stepsYesThe work. At least one stage with steps.
optionsNoTimeouts, retries, log keeping, concurrency, timestamps, skipDefaultCheckout().
environmentNoEnv vars. Can pull secrets: TOKEN = credentials('my-token').
parametersNoInputs: string, choice, booleanParam, password, text. Read as params.NAME.
triggersNocron, pollSCM, upstream.
toolsNoAuto-install and add to PATH: maven 'M3', jdk 'jdk21', nodejs 'node20' (names set in Global Tool Configuration).
whenNo (per stage)Skip a stage unless a condition holds.
inputNo (per stage)Pause for a human click.
postNo (pipeline or stage)always, success, failure, unstable, changed, aborted, cleanup.
TopicWrongRight
Groovy code in stepsLoops, if, variable assignment directly inside steps { } → "Expected a step" error.Wrap it: script { if (x) { … } }. Or move logic into a shared library.
Quotessh 'echo $BUILD_NUMBER' works (shell expands), but sh 'echo ${params.ENV}' prints nothing — single quotes do not interpolate Groovy.Use double quotes for Groovy values: sh "echo ${params.ENV}". Use single quotes + $VAR for env vars and secrets.
No timeoutA hung test holds an executor forever.options { timeout(…) } on the pipeline or stage.
No log rotationDisk fills with 5,000 old builds.buildDiscarder(logRotator(numToKeepStr: '30', artifactNumToKeepStr: '5')).
Report only on successjunit at the end of steps; a failing test aborts before it runs, so no report.post { always { junit … } }.
Validate before you push: Manage Jenkins → Pipeline Syntax has a "Declarative Directive Generator" and a "Snippet Generator" that write step code for you. The Jenkins CLI also has declarative-linter, and VS Code has a Jenkinsfile linter extension.
Q. environment { TOKEN = credentials('api-token') } then sh "curl -H 'Auth: $TOKEN' …". Is the token safe in the log?
Reveal hint
Mostly — Jenkins masks the value in the console as ****. But because you used double quotes, Groovy pasted the secret into the shell command string, which can leak via set -x or process lists. Use single quotes so the shell reads $TOKEN from the environment.

Q. Stage "Build" runs sh 'export VERSION=1.2'. Stage "Deploy" runs sh 'echo $VERSION'. What prints?
Reveal hint
Nothing. Every sh step is a fresh shell process. Set it in Groovy instead: env.VERSION = '1.2' (visible to later steps) or capture with returnStdout.

5. Flow control — when, parallel, matrix, script

when — run a stage only if…

ConditionExample
Branch name (glob)when { branch 'release/*' }
Pull request buildwhen { changeRequest() } · changeRequest target: 'main'
Tagwhen { tag 'v*' }
Env varwhen { environment name: 'DEPLOY', value: 'true' }
Any Groovy testwhen { expression { return params.ENV != 'dev' } }
Combinewhen { allOf { branch 'main'; not { changeRequest() } } } · anyOf { … }
Files changedwhen { changeset '**/*.sql' }
Evaluate before agentwhen { beforeAgent true; branch 'main' } — do not grab a node just to skip.

parallel — stages at the same time

stage('Tests') {
    failFast true                                 // stop the others when one fails
    parallel {
        stage('Unit') {
            agent { label 'linux' }
            steps { sh './mvnw test' }
        }
        stage('Lint') {
            agent { docker { image 'node:20-alpine' } }
            steps { sh 'npm ci && npm run lint' }
        }
        stage('Security scan') {
            steps { sh 'trivy fs .' }
        }
    }
}

matrix — the same stage across combinations

stage('Test matrix') {
    matrix {
        axes {
            axis { name 'JDK'; values '17', '21' }
            axis { name 'OS';  values 'linux', 'windows' }
        }
        excludes { exclude { axis { name 'OS'; values 'windows' } axis { name 'JDK'; values '17' } } }
        agent { label "${OS}" }
        stages {
            stage('Test') { steps { sh "./mvnw -Djava.version=${JDK} test" } }
        }
    }
}

script — escape hatch to Groovy

steps {
    script {
        def services = ['api', 'web', 'worker']
        def jobs = [:]
        services.each { svc ->
            jobs[svc] = { sh "docker build -t ${svc} ./${svc}" }   // closures for dynamic parallel
        }
        parallel jobs
        if (currentBuild.result == 'UNSTABLE') { echo 'Tests had failures' }
    }
}
TopicWrongRight
Big script blocksA 300-line script { }. You lost every benefit of Declarative.Move logic into a shared library (Section 7) and call one step.
Parallel on one agentThree parallel stages all needing the same single-executor node → they run one by one.Give each branch its own agent, or raise executors.
Skipped vs failedUsing when to skip the Deploy stage, then reading "SUCCESS" as "deployed".Skipped stages show grey. Add an echo or set currentBuild.description so the result is clear.
Try/catch in Declarative: you cannot write try directly in steps. Use script { try { … } catch (e) { … } }, or better, catchError / warnError steps, or stage-level post { failure { … } }.
Q. failFast true is set and one parallel branch fails. Do the others stop at once?
Reveal hint
They are asked to abort. A running sh gets a kill signal; Groovy code stops at the next step. Branches that already finished are untouched. The stage result is FAILURE.

6. Credentials — secrets done right

Jenkins stores secrets encrypted under Manage Jenkins → Credentials. Each has an ID you refer to from the Jenkinsfile. The console log masks their values as ****.

KindHoldsBinding in withCredentials
Secret textOne token / API key.string(credentialsId: 'tok', variable: 'TOKEN')
Username with passwordLogin pair.usernamePassword(credentialsId: 'reg', usernameVariable: 'U', passwordVariable: 'P')
SSH username with private keyGit over SSH, servers.sshUserPrivateKey(credentialsId: 'deploy', keyFileVariable: 'KEY', usernameVariable: 'U')
Secret filekubeconfig, service-account JSON, keystore.file(credentialsId: 'kubeconf', variable: 'KUBECONFIG')
CertificatePKCS#12 bundle.certificate(credentialsId: 'c', keystoreVariable: 'KS', passwordVariable: 'KP')
Plugin kindsAWS keys, Vault, Azure SP, GitHub App…Each plugin adds its own binding or withAWS-style wrapper.
 
// 1) Scoped to a block — best
withCredentials([usernamePassword(credentialsId: 'ghcr', usernameVariable: 'U', passwordVariable: 'P')]) {
    sh 'echo "$P" | docker login ghcr.io -u "$U" --password-stdin'   // single quotes!
}

// 2) In the environment block — whole pipeline or stage
environment {
    AWS = credentials('aws-ci')      // username/password kind → AWS_USR and AWS_PSW are created too
    NPM_TOKEN = credentials('npm')   // secret text
}

// 3) SSH key for git or scp
sshagent(['deploy-key']) {
    sh 'scp target/app.jar deploy@host:/opt/app/'
}
ScopeWho can use it
SystemOnly Jenkins itself (agent connections, plugins). Jobs cannot see it.
GlobalEvery job.
FolderOnly jobs inside that folder. Use this to separate teams.
UserPersonal; only in builds that user starts.
TopicWrongRight
Secrets in Jenkinsfilesh 'docker login -p hunter2' committed to git.Credentials store + withCredentials.
Groovy interpolationsh "curl -u $U:$P …" (double quotes) — the secret becomes part of the command text; Jenkins even warns about it.sh 'curl -u "$U:$P" …' (single quotes) — the shell reads env vars at run time.
Printing secretsecho "token is ${TOKEN}". Masking only catches exact matches; base64 or splitting leaks it.Never echo. Never write to a file you archive.
Global everythingAll credentials Global; any job can use the prod deploy key.Folder-scoped credentials + folder permissions.

Who can read secrets anyway? Anyone with "Configure" rights on a job can write a pipeline that prints a credential (encoded). Treat job-config rights as secret-read rights, and lock down with folders and RBAC.
Q. environment { DB = credentials('db-login') } for a username/password credential. What variables exist?
Reveal hint
Three: DB = user:password, DB_USR = user, DB_PSW = password. For secret text, just DB. For a secret file, DB is a temp file path.

7. Shared Libraries — reuse pipeline code

A shared library is a git repo of Groovy code that every Jenkinsfile can call. It turns a 200-line pipeline into 10 lines, and fixes a bug once for all teams.

// repo layout
(root)
├── vars/                          // global steps — one file = one step, named after the file
│   ├── buildDockerImage.groovy    // call as:  buildDockerImage(name: 'api')
│   ├── buildDockerImage.txt       // optional help text shown in the UI
│   └── standardPipeline.groovy    // a whole reusable pipeline
├── src/                           // normal Groovy classes, e.g. org/shop/Semver.groovy
│   └── org/shop/Semver.groovy
└── resources/                     // non-Groovy files, read with libraryResource
    └── org/shop/sonar.properties
// vars/buildDockerImage.groovy
def call(Map cfg) {
    def tag = "${cfg.registry ?: 'ghcr.io/shop'}/${cfg.name}:${env.BUILD_NUMBER}"
    sh "docker build -t ${tag} ${cfg.context ?: '.'}"
    sh "docker push ${tag}"
    return tag
}

// vars/standardPipeline.groovy — a full pipeline as a step
def call(Map cfg) {
    pipeline {
        agent { label 'linux' }
        stages {
            stage('Build') { steps { sh cfg.buildCmd } }
            stage('Image') { steps { script { buildDockerImage(name: cfg.name) } } }
        }
    }
}

// Jenkinsfile in an app repo — now tiny
@Library('shop-pipeline@v2') _
standardPipeline(name: 'api', buildCmd: './mvnw -B package')
Setup / useHow
RegisterManage Jenkins → System → Global Trusted Pipeline Libraries: name, default version (branch/tag), git URL, credentials.
Load@Library('name') _ (default version) · @Library('name@v2') _ (pin) · library 'name' (dynamic, inside script).
Implicit loadTick "Load implicitly" so every Jenkinsfile gets it without the annotation.
Resourcesdef txt = libraryResource 'org/shop/sonar.properties'
Classesimport org.shop.Semver then new Semver(v).bump(). Classes must be Serializable if used across steps.
TestJenkinsPipelineUnit (unit tests for library code) + a "library-test" job that runs on each PR to the library repo.
TopicWrongRight
VersionEvery app on @Library('lib') = main. One bad push breaks 80 pipelines at once.Tag releases; pin @Library('lib@v2'); roll forward team by team.
Untrusted librariesFolder-level libraries from a repo anyone can push to, marked trusted.Global libraries run without the sandbox — only from a protected repo with code review. Folder libraries run sandboxed.
Steps inside classesCalling sh from a class in src/ → "No such property: sh".Pass the steps (or this) object into the class, or keep step calls in vars/.
Q. What is the lonely underscore in @Library('lib') _?
Reveal hint
An annotation must sit on something. _ is a throw-away import statement for the annotation to attach to, when you have nothing else to import. Without it you would need @Library('lib') import org.shop.Foo.

Q. agent any at the top, plus agent { docker {…} } on one stage. How many executors does that build hold?
Reveal hint
Two during that stage: the top-level node stays allocated for the whole run, and the Docker stage grabs another (unless reuseNode true). Use agent none at the top when every stage picks its own agent.

Q. sh 'mvn test' fails on a red test. Does junit in the same steps block still run?
Reveal hint
No — the failing sh stops the steps block. Either run Maven with -Dmaven.test.failure.ignore=true and let junit set UNSTABLE, or put junit in post { always { } }.

Q. Is Jenkins's own password store a good place for all company secrets?
Reveal hint
No. It is fine for CI credentials, but the master key sits on the same disk and anyone with job-config rights can extract values. For important secrets, use HashiCorp Vault / cloud secret managers via their plugins and short-lived tokens.

12. Troubleshooting and quick reference

SymptomLook atLikely cause
Build stuck "Waiting for next available executor"Manage Jenkins → Nodes; the label in agentNo online node has that label, or all executors busy. Typo in label is common.
"Expected a step" / "Unknown stage section"Line number in the errorGroovy code outside script { }, or a block in the wrong place (e.g. when inside steps).
"Scripts not permitted to use method …"In-process Script ApprovalSandbox blocked a Groovy call. Approve it, or move the code to a trusted library.

Webhook does nothingGitHub → Settings → Webhooks → Recent Deliveries; Jenkins system logWrong URL (/github-webhook/), Jenkins not reachable, or branch filtered out.

Minimal Jenkinsfile to copy

pipeline {
    agent { docker { image 'node:20-alpine' } }
    options { timeout(time: 15, unit: 'MINUTES'); buildDiscarder(logRotator(numToKeepStr: '20')) }
    stages {
        stage('Install') { steps { sh 'npm ci' } }
        stage('Test')    { steps { sh 'npm test -- --reporter=junit --outputFile=junit.xml' }
                           post { always { junit 'junit.xml' } } }
        stage('Build')   { steps { sh 'npm run build'; archiveArtifacts 'dist/**' } }
    }
    post { failure { echo "Failed: ${env.BUILD_URL}" } }
}
The 6 rules to remember: 1) Jenkinsfile in the repo, Declarative style; 2) controller runs zero builds — agents do the work; 3) secrets only through the credentials store, with single-quoted sh; 4) always timeout and buildDiscarder; 5) reports in post { always }; 6) shared library + JCasC so nothing lives only in the UI.
Q. You need to test a Jenkinsfile change fast without ten commits. What is the quickest loop?
Reveal hint
Replay. Open the last build → Replay → edit the Groovy in the browser → Run. When it works, commit that version. Also handy: the Snippet Generator for exact step syntax, and the validate endpoint for syntax errors.
