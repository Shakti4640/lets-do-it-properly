0. How AWS is organised (accounts, regions, the shared-responsibility line)

TermPlain meaningWhy you care
AccountThe billing and security boundary. Everything lives in one.One account per environment (dev / staging / prod) is the strongest isolation you can buy for free.
OrganizationA tree of accounts with shared billing and guardrails (SCPs).Platform team owns it; you get an account and an SSO login.
RegionA geographic cluster (ap-south-1 Mumbai, eu-west-1 Ireland…). Most resources are regional.Data stays where you put it; latency; some services only in some regions.
Availability Zone (AZ)One or more data centres inside a region, isolated power/network. ap-south-1a/b/c.Run in ≥ 2 AZs or one data-centre failure is your outage.
Global servicesIAM, Route 53, CloudFront, Organizations.IAM changes apply everywhere.
ARNAmazon Resource Name: arn:aws:s3:::shop-uploads, arn:aws:sqs:ap-south-1:123456789012:orders.How IAM policies name things.
Managed vs self-runRDS runs Postgres for you; EC2 gives you a VM to run it yourself.Default to managed; your team's time is the expensive part.
Shared responsibilityAWS secures the cloud (hardware, hypervisor, managed service internals); you secure what you put in it (IAM, security groups, data, patches on EC2).An open S3 bucket is your fault, not AWS's.

Mental model: an AWS account is an empty building you rent. IAM is the badge system, the VPC is the floor plan and the walls, security groups are the door locks, and every service is a department you can hire by the hour. The bill is the only thing that is truly unlimited.
Q. Your staging and prod run in one account, separated by naming. Someone's staging script runs aws s3 rm --recursive on the wrong bucket. What stopped it?
Reveal hint
Nothing — the credentials were valid for both. Separate accounts turn "please be careful" into "not possible": the staging role cannot even see prod buckets. That is why the account is the primary isolation unit.

Q. Your policy allows s3:GetObject on the bucket, but the app still gets AccessDenied reading an object encrypted with a KMS key. Why?
Reveal hint
Reading an SSE-KMS object also needs kms:Decrypt on that key — both in your identity policy and allowed by the key's own policy. Two policies, two places; CloudTrail shows the Decrypt denial.

2. VPC — the network your services live in

PieceMeaningTypical setup
VPCYour private network, a CIDR like 10.0.0.0/16.One per environment/account.
SubnetA slice of the VPC in one AZ. Public if its route table sends 0.0.0.0/0 to an Internet Gateway; otherwise private.Per AZ: one public (ALB, NAT), one private-app (ECS tasks), one private-data (RDS, Redis). 3 AZs × 3 = 9 subnets.
Internet Gateway (IGW)Lets public subnets talk to the internet both ways.One per VPC.
NAT GatewayLets private subnets reach out (pull images, call Stripe) without being reachable from outside.One per AZ for HA; costs ~$32/month each + per-GB — a classic surprise bill.
Route tableWhere traffic for each destination goes.Public: 0.0.0.0/0 → igw. Private: 0.0.0.0/0 → nat.
Security Group (SG)Stateful firewall on a resource (ENI). Allow rules only; return traffic auto-allowed. Can reference other SGs.ALB SG: 443 from 0.0.0.0/0. App SG: 8080 from ALB SG. DB SG: 5432 from App SG. That chain is the whole security model.
Network ACLStateless allow/deny per subnet. Default allows all.Leave default unless you need subnet-level deny.
VPC EndpointPrivate path to AWS services (S3, ECR, SSM, Secrets Manager, SQS…) without NAT/internet.Gateway endpoints (S3, DynamoDB) are free; interface endpoints cost per hour but cut NAT data charges and improve security.
ENIA virtual network card. Every Fargate task, RDS instance, Lambda-in-VPC gets one.Subnet IP exhaustion (/24 = 251 usable) bites with many tasks.

Q. Security groups are "stateful". What does that save you from writing?
Reveal hint
Return traffic. If you allow inbound 8080 from the ALB, the responses go back out without any outbound rule. NACLs are stateless — there you would have to allow the ephemeral port range (1024–65535) both ways, which is why people leave NACLs at default.

Q. ECS keeps restarting your task every ~2 minutes with "Task failed ELB health checks", but curl localhost:8080/actuator/health works inside the container. What is wrong?
Reveal hint
Either the ALB cannot reach the task (task SG must allow 8080 from the ALB's SG), the target-group health path/port differs from what the app serves, or the JVM takes longer than healthCheckGracePeriodSeconds to come up. Check the target group's "unhealthy reason" first — it names the cause.

Q. After an RDS Multi-AZ failover your Spring app logs errors for 3 more minutes although RDS says failover finished in 60 s. Why?
Reveal hint
The endpoint's DNS now points at the new primary, but your existing pooled connections still point at the dead host and only die when TCP gives up (or Hikari recycles them). Fix: the AWS JDBC wrapper's failover plugin (detects and reconnects in seconds), short socketTimeout, and Hikari maxLifetime around 5–10 min; the JVM must not cache DNS forever.

5. S3 — objects, presigned URLs, lifecycle, security

ConceptMeaning
Bucket / keyGlobally unique bucket name; keys are strings like uploads/2026/10/25/9001.pdf — "folders" are just prefixes.
ConsistencyStrong read-after-write for all operations since 2020. No eventual-consistency dance any more.
Storage classesSTANDARD → STANDARD_IA (infrequent) → GLACIER_IR / GLACIER / DEEP_ARCHIVE (cheap, slow). INTELLIGENT_TIERING moves objects for you.
Lifecycle rules"After 30 days move to IA, after 365 to Glacier, after 7 years delete"; also "abort incomplete multipart uploads after 7 days" (saves money).
VersioningKeeps old versions; protects from overwrite/delete. Pair with lifecycle to expire old versions.
EncryptionSSE-S3 (default, free) or SSE-KMS (your key, audit, cross-account control). Enforce with a bucket policy.
Block Public AccessAccount- and bucket-level switch. On, everywhere, unless you knowingly host a public website (then CloudFront + OAC instead).
Presigned URLA time-limited URL that carries your permission: clients upload/download directly to S3 without going through your JVM.
Multipart uploadRequired > 5 GB, recommended > 100 MB; the SDK's Transfer Manager does it.
Event notificationsObject created → SQS / SNS / Lambda / EventBridge. Thumbnailing, virus scan, ingestion.
Access points, Object Lock, ReplicationPer-app access policies; WORM compliance; cross-region copies.
 
// SDK v2: upload, download, presign (dependencies: software.amazon.awssdk:s3, :url-connection-client or :apache-client)
@Configuration
class AwsConfig {
    @Bean S3Client s3() { return S3Client.builder().region(Region.AP_SOUTH_1).build(); }           // one client per app; thread-safe; credentials from the chain
    @Bean S3Presigner presigner() { return S3Presigner.builder().region(Region.AP_SOUTH_1).build(); }
}

@Service
class UploadService {
    private final S3Client s3; private final S3Presigner presigner;
    private static final String BUCKET = "shop-prod-uploads";

    void put(String key, Path file) {
        s3.putObject(PutObjectRequest.builder().bucket(BUCKET).key(key)
                .contentType("application/pdf").serverSideEncryption(ServerSideEncryption.AWS_KMS).build(), file);
    }
    byte[] get(String key) {
        return s3.getObjectAsBytes(b -> b.bucket(BUCKET).key(key)).asByteArray();   // small files; stream large ones with getObject(...) → ResponseInputStream
    }
    // browser uploads straight to S3: the JVM only mints the URL
    URL presignUpload(String key, String contentType) {
        var put = PutObjectRequest.builder().bucket(BUCKET).key(key).contentType(contentType).build();
        return presigner.presignPutObject(p -> p.signatureDuration(Duration.ofMinutes(10)).putObjectRequest(put)).url();
    }
    URL presignDownload(String key) {
        return presigner.presignGetObject(p -> p.signatureDuration(Duration.ofMinutes(5))
                .getObjectRequest(g -> g.bucket(BUCKET).key(key)
                    .responseContentDisposition("attachment; filename=\"invoice-9001.pdf\""))).url();
    }
    List<String> listPrefix(String prefix) {
        return s3.listObjectsV2Paginator(b -> b.bucket(BUCKET).prefix(prefix)).contents().stream().map(S3Object::key).toList();   // paginator handles 1000-key pages
    }
}
// big files: S3TransferManager (software.amazon.awssdk:s3-transfer-manager + aws-crt) does multipart + parallel automatically

Q. A presigned PUT URL works from curl but the browser gets a CORS error. What is missing?
Reveal hint
A CORS configuration on the bucket allowing your origin, the PUT method, and the headers you sign (Content-Type, x-amz-server-side-encryption). Also the browser must send exactly the headers that were signed — a different Content-Type gives SignatureDoesNotMatch.

Q. CloudWatch shows HTTPCode_ELB_5XX 502s but zero HTTPCode_Target_5XX and the app logs nothing. Where is the problem?
Reveal hint
Between the ALB and the target, not in the app code: the target closed the connection (keep-alive timeout shorter than the ALB's), the task was being killed mid-request (deregistration/graceful shutdown), or a response header exceeded limits. @Component
class OrderEventsListener {
    @SqsListener(value = "shop-prod-orders", acknowledgementMode = AcknowledgementMode.ON_SUCCESS)   // delete only if the method returns normally
    void on(OrderPlaced event, @Header("ApproximateReceiveCount") int attempt) {
        billing.handle(event);                 // throw → message becomes visible again after the visibility timeout → retried → DLQ after maxReceiveCount
    }
}

@Service
class OrderPublisher {
    private final SqsTemplate sqs;
    void placed(Order o) {
        sqs.send(to -> to.queue("shop-prod-orders").payload(OrderPlaced.from(o))
                       .header("eventId", o.eventId().toString()));              // consumers dedupe on this
        // FIFO: .messageGroupId(o.customerId()).messageDeduplicationId(o.eventId().toString())
    }
}

SQS settingGuidance
Visibility timeout≥ 6× your max processing time (AWS's rule of thumb); extend with ChangeMessageVisibility for long jobs. Too short = duplicate processing.
Redrive policy → DLQmaxReceiveCount 3–5; alarm on DLQ depth; a redrive button exists to move messages back.
Long pollingReceiveMessageWaitTimeSeconds=20 — fewer empty receives, lower cost.
RetentionDefault 4 days, max 14. DLQ: 14 days.
Message size256 KB max; bigger → S3 + pointer (extended client library).
BatchingSend/receive/delete in batches of 10 — cost and throughput.
EncryptionSSE-SQS (free) or SSE-KMS.
Scaling consumersECS service autoscaling on ApproximateNumberOfMessagesVisible (target tracking on backlog per task).
TopicWrongRight
Non-idempotent consumersStandard queue delivers twice → two invoices.Dedupe on an event id (DB unique constraint) — at-least-once is the contract.
No DLQA poison message retried forever, blocking FIFO groups.Redrive policy + DLQ alarm + a replay runbook.
Short polling in a loopEmpty receives every 100 ms: cost and throttling.Long polling (20 s).
Deleting before processingReceive → delete → process → crash = lost message.Process, then delete (ON_SUCCESS).
Direct SNS → HTTPS to your APISpiky retries, your API must be up to receive.SNS → SQS → your consumer; the queue absorbs bursts and outages.
SQS as KafkaReplaying last week's events from SQS.SQS is a work queue; for retention/replay use EventBridge archive, Kinesis, or MSK.
Q. With a FIFO queue, one message for group cust-42 keeps failing. What happens to the other messages for cust-42 and for other customers?
Reveal hint
Other groups flow normally. cust-42's later messages are blocked behind the failing one until it succeeds or moves to the DLQ after maxReceiveCount — so a DLQ is not optional for FIFO. Head-of-line blocking per group is the price of ordering.

Q. Your task has secretsmanager:GetSecretValue on the secret but fails at start with "AccessDeniedException … kms:Decrypt". The secret uses the default aws/secretsmanager key. Why?
Reveal hint
The default key works within the same account without extra KMS grants, so this means the secret is in another account or uses a customer-managed key. Cross-account secrets require a CMK whose key policy grants your role kms:Decrypt, plus a resource policy on the secret. Check which key the secret actually uses.

// one client per service, built once, thread-safe, closed on shutdown
@Bean(destroyMethod = "close")
SqsClient sqs() {
    return SqsClient.builder()
        .region(Region.AP_SOUTH_1)                                   // or let it come from AWS_REGION / the task metadata
        .credentialsProvider(DefaultCredentialsProvider.create())   // the default anyway — shown for clarity
        .overrideConfiguration(c -> c

            .apiCallAttemptTimeout(Duration.ofSeconds(3))             // per attempt

        .httpClientBuilder(ApacheHttpClient.builder().maxConnections(100).connectionTimeout(Duration.ofSeconds(2)))
        .build();
}
